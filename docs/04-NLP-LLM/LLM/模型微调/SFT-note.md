# SFT 监督微调（Supervised Fine-Tuning）

## 定义
监督微调（Supervised Fine-Tuning，SFT）是指在已经预训练好的大语言模型基础上，使用**人工标注的高质量"输入—输出"数据**对模型进行进一步训练，使其学会遵循指令、回答问题、完成特定任务。

- **它是什么**：SFT 是介于预训练与人类偏好对齐之间的有监督训练阶段——把「指令/输入」作为条件、「期望回答」作为监督目标，对模型做下一步 token 预测式的微调。
- **解决什么问题**：预训练模型已掌握大量语言知识和世界知识，但它的主要能力是"续写文本"，不一定能直接理解人类指令或给出有用回答；SFT 让模型从"会说话"变成"会按要求办事"，即学会理解用户意图、遵循指令格式、生成有用且符合预期的回答。
- **核心特征**：训练数据量远小于预训练；训练成本相对较低；效果提升显著，是把通用模型变成"助手型模型"的关键步骤。
- **适用范畴**：指令遵循、单轮问答、多轮对话、代码生成、摘要、翻译等下游任务的监督式适配；也常用于开源基座模型在部署前的必要对齐步骤。

## 原理
- **为什么这样设计**：预训练的目标是海量无标注文本上的 next-token 续写，学到的条件分布偏向"任意自然的续写"，而非"对用户有用的回答"。SFT 用任务分布的高质量标注数据，把生成分布校准到"指令 → 期望回答"上，本质是把模型行为从语言建模迁移到任务求解。
- **核心机制（损失函数）**：以指令（含可选输入）为条件 x、期望输出为 y，只对输出 token 计算交叉熵损失：

```
L = -1/N * Σ_i log P(y_i | x, y_<i)
```

其中 y_<i 为输出序列中第 i 个 token 之前的 token。训练时通常将 instruction 部分在 loss 中 mask 掉，只监督 output，避免模型"背输入"而非"学应答"。
- **训练数据格式**：SFT 通常使用"指令—回答"对（instruction/input/output），也可以包含多轮对话、代码生成、摘要、翻译等任务数据；数据质量直接决定效果上限。
- **在训练流程中的位置**：典型大语言模型训练流程为「预训练 → SFT → 奖励建模 / 人类反馈强化学习（RLHF / DPO 等）→ 最终对齐模型」：
  - **预训练**：海量无标注文本，学习语言规律与世界知识；
  - **SFT**：高质量标注数据，学习任务格式和人类偏好；
  - **RLHF / DPO**：进一步对齐人类价值观，减少有害输出。
- **参数高效原理**：由于大模型参数量巨大、全参数 SFT 成本较高，实践中常用只更新少量参数的低秩/适配方案（LoRA、QLoRA、Adapter、Prefix Tuning 等），即可达到接近全参数微调的效果。

## 应用
- **典型使用场景**：①把开源基座模型微调成可对话的助手模型；②让模型学会特定任务格式（代码、摘要、翻译、工具调用等）；③领域化适配——配合领域数据提升特定任务表现。
- **优点**：训练成本相对较低（数据量远小于预训练）；能显著提升指令遵循能力与实用性；是通用模型走向"助手型模型"的关键步骤。
- **快速上手步骤**：①准备数据：整理成 instruction/input/output 或对话格式的 JSON 数据集，并保证格式与质量一致；②选微调方式：资源充足可选全参数 SFT，资源受限用 LoRA/QLoRA 等参数高效方法；③组装 prompt 模板并对齐训练格式（分隔符、角色标记需与推理时一致）；④训练时 mask instruction 部分的 loss；⑤在验证集上评估指令遵循质量，而非只看 loss。
- **注意事项 / 常见坑**：
  - 数据质量是决定因素——脏数据、错误标注会被模型直接模仿放大；
  - 模型主要模仿标注数据中的行为，泛化能力受限于数据分布（数据覆盖面窄则任务外泛化差）；
  - SFT 不能完全解决幻觉、偏见、安全性等问题，通常仍需后续 RLHF / DPO 对齐阶段；
  - prompt 模板不一致（训练 vs 推理）是效果崩坏的常见原因；
  - 小数据集上重复训练易过拟合，注意早停与正则。

```python
# SFT 训练数据样例 + 最小训练要点（含注释）
import json

# 1) 数据格式：指令—回答对（instruction/input/output），可含多轮对话
sample = {
    "instruction": "请用一句话解释什么是光合作用",
    "input": "",
    "output": "光合作用是植物利用光能把二氧化碳和水转化为有机物并释放氧气的过程。"
}

# 2) 组装 prompt：把 instruction(及可选 input) 作为条件 x，output 作为监督目标 y
def format_prompt(example):
    if example.get("input"):
        return f"### 指令\n{example['instruction']}\n### 输入\n{example['input']}\n### 回答\n"
    return f"### 指令\n{example['instruction']}\n### 回答\n"

# 3) 训练要点：只对 output 部分计算交叉熵损失
#    L = -1/N * Σ_i log P(y_i | x, y_<i)
#    训练时把 instruction 对应位置的 loss mask 掉，避免模型"背输入"而非"学应答"。
#    推理时用与训练一致的 prompt 模板，否则效果会明显退化。

# 4) 工程实现（等价流程，通常直接用现成框架，无需手写循环）：
#    from trl import SFTTrainer            # Hugging Face TRL
#    trainer = SFTTrainer(
#        model=model,                      # 基座模型（或 AutoModelForCausalLM）
#        train_dataset=dataset,            # instruction/input/output 格式数据集
#        peft_config=lora_config,          # 用 LoRA 时传入，冻结原参数只训低秩增量
#        formatting_func=format_prompt,    # prompt 组装函数
#    )
#    trainer.train()
```

**案例详解**：以「解释光合作用」样本为例——x = 指令文本，y = 期望回答；loss 只统计 y 上每个 token 的预测概率的负对数均值。全参数 SFT 会更新模型全部权重，而 LoRA/QLoRA 冻结原参数、只训练注入的低秩增量矩阵，可大幅降低显存与算力开销，效果接近全参数微调。QLoRA 进一步对基座权重做 4-bit 量化，可在单张消费级显卡上微调数十亿参数模型。

## 关联
- 前置：[[大语言模型预训练]]
- 类似：[[RLHF]]（区别是：SFT 用人工标注的输入—输出对做有监督学习，目标是指令遵循与任务格式；RLHF 用人类偏好排序数据配合强化学习，目标是价值观对齐与减少有害输出）
- 类似：[[无监督微调 / 继续预训练]]（区别是：无监督微调用无标注文本继续做 next-token 训练以注入领域知识或语言风格，SFT 用输入—输出标注对以学会遵循指令、完成任务）
- 进阶：[[LoRA]]、[[QLoRA]]（参数高效微调，降低 SFT 的显存与算力成本）；[[DPO]]（直接偏好优化，SFT 之后更轻量的对齐替代方案）

## 对比选型
| 方案 | 核心思想 | 最佳场景 |
|------|----------|----------|
| 本文方案：SFT 监督微调 | 用人工标注的"输入—输出"对做有监督训练，把生成分布校准到指令应答 | 让基座模型学会遵循指令、任务格式与人类偏好，是助手化的关键一步 |
| 无监督微调（继续预训练） | 在无标注领域文本上继续 next-token 训练 | 大规模注入领域知识/语言风格，不改变任务交互方式 |
| RLHF / DPO | 用人类偏好排序或对比数据做强化学习/直接偏好优化 | SFT 之后进一步对齐人类价值观，提升安全性与有用性 |
| LoRA / QLoRA 等参数高效微调 | 冻结原参数，只训练低秩增量或少量适配参数 | 资源受限时以低成本完成 SFT 流程 |
