# 提示学习与上下文学习（In-Context Learning, ICL）

## 定义

上下文学习（In-Context Learning, ICL）指把若干**输入-输出示例**与待解问题拼进同一段提示（prompt）文本喂给 LLM，**不更新任何参数**，让模型靠续写（条件生成）就把任务做对的范式。提示学习（Prompt Learning）是其广义工程侧：通过设计指令、示例与格式来调动模型既有能力。

- 解决的问题：任务需要快速上线或形态频繁变化时，不必为每个新任务训练模型——把"教"从训练期挪到推理期的上下文里，零训练成本、可即时切换。
- 核心特征：① 零参数更新，知识"瞬时注入"——关掉上下文就消失，区别于微调的权重内化；② 能力来源是预训练已把"示例模式 → 照葫芦画瓢"压进权重，提示只是把这个能力**唤起**出来。
- 适用范畴：Zero-shot（只给指令/问题、不给示例）、One/few-shot（给 1~k 个标注示例，是 ICL 的典型形态）；整体依赖模型已有能力与指令遵循水平——RLHF/SFT 之后的模型越会"按示例的格式走"，ICL 越灵。
- 与相邻概念的关系：指令微调（Instruction tuning）用"指令-回答"对做 SFT，把"听指令"本身练进权重；提示工程（Prompt engineering）是设计指令/格式/示例的工程实践，ICL 是其"上下文侧"。

术语速查表：

| 概念 | 含义 | 与微调的关系 |
|------|------|--------------|
| Zero-shot | 只给指令/问题，不给示例 | 依赖模型已有能力 |
| One/few-shot | 给 1~k 个标注示例（ICL 的典型形态） | **不改权重**，只改上下文 |
| Instruction tuning | 用"指令-回答"对做 SFT | 把"听指令"本身练进权重 |
| Prompt engineering | 设计指令/格式/示例的工程实践 | ICL 是其"上下文侧" |

关键区别：**ICL 的知识是"瞬时注入"的**——关掉上下文就消失；微调是**权重内化**。

## 原理

ICL 全程不做梯度更新：对固定权重 θ，模型实际在"示例约束下最大化后验续写概率"，即隐式推断 y\* = argmax_y P(y | x, {(x_i, y_i)}_{i=1..k}; θ)。示例只改变条件上下文而不改变分布本身，因此效果上限由预训练压进权重的能力决定。主流解释有三类：

- **任务识别（task recognition）**：模型把示例当作"这个输入分布长什么样、输出格式长什么样"的证据，内部其实在做隐式的任务推断与条件生成——这是 GPT-3 论文（Language Models are Few-Shot Learners）的核心观察。
- **机械记忆/归纳头（induction head）**：小模型上可观测到 induction head 机制：看到 `A B ... A` 后倾向预测 `B`；ICL 可视为这类内部机制在大尺度上的涌现（学习示例 = 建立输入到输出的映射）。
- **贝叶斯视角**：示例 = 从任务分布里采出的条件，模型在其约束下最大化后验续写概率。由此推出**示例质量/代表性 > 数量**，且示例顺序与标签分布都会影响后验——这解释了"标签顺序在 k 小时敏感、先展示的示例权重更高"等可复现现象。

从工程链路看，示例必须先经过 prefill 进入 KV-Cache 才能参与注意力，所以 ICL 的效果与可用上下文长度、注意力稀释直接相关（成本模型见关联笔记）；本质上它是"瞬时知识"，无法替代参数内化，也不能凭空注入训练中从未见过的复杂规则。

## 应用

典型使用场景：快速上线、任务形态常变、零训练成本的任务（分类、抽取、格式转换、Demo/PoC、评估基线）；需要把领域知识/私有库带进推理时改用 RAG（检索→塞进上下文）；需要稳定格式、领域风格、行为持续一致时用 SFT/LoRA；需对齐偏好、提升推理稳定性时再做偏好优化/RL。选型见下方"对比选型"表。

快速上手步骤——构造一份典型 few-shot 提示：

```text
<系统指令>: 你是情感分析助手，只输出 POSITIVE 或 NEGATIVE。
<示例 1>    Review: 电影太棒了。→ POSITIVE
<示例 2>    Review: 剧情无聊透顶。→ NEGATIVE
<待预测>    Review: 演员演技炸裂。→
```

要素与讲究：角色/任务描述、示例（输入→输出）、**稳定的分隔符与输出格式**（可被程序解析）、终止约束（"只输出…"）。实践要点：分隔符统一且罕见（`###`、XML 标签、JSON 结构），避免与正文混淆；示例覆盖正反两类与边界情况，标签顺序在 k 小时敏感（先展示的示例权重更高）；让模型先"抄格式"再回答，复杂任务给"思路"示例（思维链 CoT 是 ICL 的进阶形态）；输出约束（JSON schema/枚举）放指令里，解析端做容错。

注意事项/常见坑：

- ❌ 把 ICL 当"学新知识"：复杂新规则需要几十上百示例，演示太少时模型会背示例而非泛化；学不会 ≠ 没给够，可能要微调或 RAG。
- ❌ 假设"示例越多越好"：上下文窗口有限，长示例挤占空间还稀释注意力；4~8 个精选示例常优于 20 个平庸示例。
- ❌ 忽略敏感度：**示例顺序颠倒、标签改写、格式微调都可能让准确率大幅抖动**（著名的 label/order/format 敏感实验）——评估时要跑多次并换顺序。
- ❌ 直接把不可信文本拼进提示 → prompt injection（提示注入）；对用户输入与指令要做边界隔离。
- ❌ 中文模板 + 英文示例混用、示例域与测试域不一致 → 输出风格漂移。
- ❌ 训练集泄漏进示例（示例本身含答案泄漏给无关查询）——评测时要与测试集隔离。
- 成本视角：示例即 token，长上下文 = 更多 prefill 计算与 KV-Cache 显存（见 `LLM推理与KV-Cache.md`）；量大时用 RAG/缓存/Prompt 压缩。

```python
# 代码示例（含注释）+ 案例详解
# 案例：构建 0-shot / 4-shot 情感分类模板，演示"示例选择/顺序/格式"敏感度。
# ICL 不训练任何参数——只把系统指令与示例拼进同一段 prompt，靠条件续写出答案
# （与配套示例 提示学习与上下文学习_sample.py 思路一致，默认零依赖可运行）。

SYSTEM = "你是情感分析助手，只输出 POSITIVE 或 NEGATIVE。\n"

# 示例池：注意 3 条 POSITIVE 在前、1 条 NEGATIVE 在后——
# k 较小时"先展示的示例权重更高"，标签分布会倾斜模型的输出。
DEMOS = [
    ("电影太棒了。", "POSITIVE"),
    ("剧情无聊透顶。", "NEGATIVE"),
    ("演员演技炸裂。", "POSITIVE"),
    ("看得我热泪盈眶。", "POSITIVE"),
]

def build_prompt(query: str, demos=None):
    """拼提示：0-shot 传 demos=None；few-shot 传 [(review, label), ...]。
    统一分隔符(<示例 i> / <待预测>)且正文中罕见，保证输出可被程序稳定解析。"""
    parts = [SYSTEM]
    if demos:
        for i, (review, label) in enumerate(demos, 1):
            parts.append(f"<示例 {i}>\nReview: {review}\n-> {label}\n")
    parts.append(f"<待预测>\nReview: {query}\n->")
    return "\n".join(parts)

query = "这电影节奏太拖了。"

print("=== 0-shot（无示例）===")
print(build_prompt(query))                # 只靠系统指令，考验模型既有能力
print("\n=== 4-shot（带示例）===")
print(build_prompt(query, demos=DEMOS))   # 示例教会模型"输出格式 + 正反判断"

# 实操提示：
# 1) 换顺序/换标签再跑几遍，观察准确率抖动（评估应多次运行并打乱示例顺序）；
# 2) 示例覆盖正反两类与边界情况，4~8 个精选示例优于 20 个平庸示例；
# 3) 解析端做容错（枚举/正则匹配），不要假设模型严格只输出两个词；
# 4) 不可信文本不要直接拼进提示——防止 prompt injection。
```

## 对比选型
| 方案 | 核心思想 | 最佳场景 |
|------|----------|----------|
| 本文方案：ICL + 提示工程 | 不改权重，把"指令 + 输入输出示例"拼进上下文，靠条件续写唤起预训练能力 | 快速上线、任务形态常变、零训练成本、标注数据少 |
| RAG（检索增强） | 检索相关文档塞进上下文，把外部知识带进推理 | 领域知识/私有库需进推理、知识频繁更新 |
| SFT/LoRA（微调） | 用标注数据（低秩近似）更新权重，内化领域知识/格式 | 稳定格式、领域风格、行为持续一致、复杂规则示例难覆盖 |
| 偏好优化/RL（如 GRPO） | 用偏好信号/奖励对齐模型行为 | 对齐偏好、提升推理稳定性 |
