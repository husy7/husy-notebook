# 0-1 背包问题（动态规划，从递归到滚动数组）

## 定义

0-1 背包（0/1 Knapsack）是动态规划的入门经典问题：有 $n$ 件物品，第 $i$ 件物品有重量 $w_i$ 与价值 $v_i$（通常约定 $w_i, v_i \ge 0$），现有一个容量为 $C$ 的背包，要求从这 $n$ 件物品中选出一个子集，使得「所选物品的总重量不超过 $C$」且「总价值最大」。

- 名称由来：每件物品只有两种状态——不选（记 0）或整件选走（记 1），不允许装一部分，也不允许同一件重复装。这正是它与「分数背包（物品可分，贪心可得到最优）」和「完全背包（同一件可无限重复取）」的本质区别。
- 解决什么问题：资源总量受限下的最优子集选取，属组合优化问题；它的判定版本（子集和问题 Subset-Sum）是 NP 完全的，故不存在多项式时间算法（除非 P=NP），但整数容量版本的 DP 解法复杂度为 $O(n \cdot C)$，属于「伪多项式」时间。
- 适用范畴：一切可抽象为「$n$ 个二元决策 + 总资源上限 + 目标最大化 / 可行性 / 计数」的问题，例如预算内选项目组合、容器与内存分配、小规模精确调度，以及大量 LeetCode 变式题（416 分割等和子集、474 一和零、494 目标和等）。
- 核心特征：同时具备最优子结构（去掉最后一件后，前 $n-1$ 件仍是同构子问题）与重叠子问题（朴素递归树中同一状态 $(i, c)$ 被不同分支反复求解）——二者正是动态规划能够奏效的两大要素。
- 与搜索的区别：DFS/BFS 是「遍历状态空间寻找可行解」，靠访问顺序与剪枝去重；背包 DP 是「按阶段合并等价状态直接递推最优值」，把指数级枚举折叠成一张 $(n+1)\times(C+1)$ 的状态表。

## 原理

思路：先写出最朴素的递归枚举（每件「取/不取」两个分支），从递归函数签名中提炼出状态与转移方程；接着观察到大量 $(i, c)$ 子问题被不同分支重复计算（重叠子问题），于是用「缓存 / 查表」消除重复；再把自顶向下的递归改写成自底向上的填表；最后发现第 $i$ 行只依赖第 $i-1$ 行，从而把二维表压缩成一维滚动数组。整体脉络正是本笔记标题：递归 → 记忆化 → 二维 DP → 滚动数组。

状态定义（关键推导起点）：记 $dp[i][j]$ = 只考虑前 $i$ 件物品、背包容积为 $j$ 时可获得的最大价值。对第 $i$ 件物品只有两个决策，据此写出转移方程：

$$dp[i][j] = \max\big(dp[i-1][j],\ dp[i-1][j - w_i] + v_i\big), \quad j \ge w_i$$

$$dp[i][j] = dp[i-1][j], \quad j < w_i$$

- 分支一「不取第 $i$ 件」：结果等于前 $i-1$ 件在容量 $j$ 下的最优值 $dp[i-1][j]$；
- 分支二「取第 $i$ 件」：需先为它腾出 $w_i$ 空间，前 $i-1$ 件只能在容量 $j - w_i$ 下发挥，即 $dp[i-1][j-w_i] + v_i$；两者取大即为最优。
- 边界：$dp[0][j] = 0$（没有物品可选，价值恒 0），$dp[i][0] = 0$（无容量）。正确性由数学归纳法保证：两个分支覆盖了「含第 $i$ 件 / 不含第 $i$ 件」的全部可行子集，故处理完前 $i$ 件后表中每个格子都等于对应子问题的最优值。

空间优化（滚动数组）的原理：转移式显示第 $i$ 行只依赖第 $i-1$ 行，因此无需保留整张表，仅用一维数组 $dp[j]$，每处理一件物品就在原数组上就地更新。关键在于容量 $j$ 必须从 $C$ **逆序**递减到 $w_i$：由于 $j - w_i < j$，逆序时 $dp[j-w_i]$ 仍是上一件物品处理完的旧值（本轮尚未覆盖），从而保证每件物品至多取一次；若正序遍历，$dp[j-w_i]$ 已被本轮更新过，同一件物品可被重复取，方程就悄悄退化成了完全背包。

复杂度推导：
- 暴力递归：$T(n) = 2T(n-1) + O(1)$，解得时间 $O(2^n)$、递归栈空间 $O(n)$；
- 记忆化搜索 / 二维自底向上：状态总数 $(n+1)(C+1)$，每状态 $O(1)$ 转移 → 时间 $O(n \cdot C)$、空间 $O(n \cdot C)$；
- 滚动数组：时间不变 $O(n \cdot C)$，空间降为 $O(C)$。DP 填表逐格进行、结果与数据排列无关，故最好 / 最坏 / 平均时间复杂度相同（均为 $O(n \cdot C)$），差异只在空间占用与是否保留可回溯的整张表。

## 应用

典型使用场景：
- 「资源总量受限 + 每项只用一次 + 求最大收益 / 可行性 / 方案数」类题目。LeetCode 变式：416（分割等和子集，把 $C = sum/2$ 的可行性问题建模成 0-1）、494（目标和，转 0-1 计数）、474（一和零，双容量 0-1）、1049（转化为最接近 $sum/2$ 的 0-1 背包）。
- 工程场景：预算 / 带宽 / 内存受限下的最优组合选择，NP 困难问题在小规模精确求解时的通用子程序，以及树形背包、多维背包、依赖背包等进阶模型的基础。
- 教学价值：第一个完整展示「消除重叠子问题把 $2^n$ 压成多项式」的案例，也是理解空间优化（滚动数组）的标准素材。

快速上手 5 步：
1. 判定题型：每项可选可不选、至多一次、总量受限 → 0-1 背包；
2. 设状态：$dp[j]$ = 容量 $j$ 时的最优值（容量 $j$ 作为内层维度）；
3. 定初始化：求「不超过容量」的最大值用全 0；求「恰好装满」用 $dp[0]=0$、其余 $-\infty$；求方案数用 $dp[0]=1$、其余 0；
4. 双重循环：物品循环在外层，容量 $j$ 从 $C$ 逆序到 $w_i$；
5. 需要输出「具体选了哪些物品」时，保留二维表并自后往前回溯，或用额外数组记录每步选择。

边界条件与常见坑（❌ / ✅）：
- ❌ 容量循环写成正序 `for j in range(w, C+1)`：同一件物品被反复取，退化为完全背包（见案例：物品 (2,3) 正序会把 dp[4] 误算成 6）。✅ 一律写 `for j in range(C, w-1, -1)` 逆序。
- ❌ 把容量放外层、物品放内层：一旦先固定容量，「每件至多用一次」的约束就被破坏。✅ 物品在外、容量在内。
- ❌ 求「恰好装满」却把 dp 初始化为全 0：混入容量未用满的非法状态，答案偏大。✅ 令 $dp[0]=0$、其余 $dp[j]=-\infty$，转移时若左项为 $-\infty$ 说明该状态不可达。
- ❌ 不处理 $w_i > C$ 的超重物品：$j - w_i < 0$ 会导致越界或读到错误值。✅ 转移前保证 $j \ge w_i$（内层循环起点直接设为 $w_i$），或预处理时跳过超重物品。
- ❌ 把 $O(n \cdot C)$ 当成多项式复杂度：当 $C$ 达 $10^9$ 量级时会超时或爆内存。✅ 认清其伪多项式本质；$C$ 巨大而总价值 $V$ 很小（或 $n$ 很小）时，改用「以价值为状态求最小重量」或 meet-in-the-middle。
- ❌ 价值 / 重量出现负数还直接套方程：价值为负的物品永远不该取。✅ 标准 0-1 前提是 $w_i, v_i \ge 0$，有负值需先剔除或单独处理。
- ❌ 朴素递归处理 $n = 50$：$2^{50}$ 次调用必卡死，并触发 Python 递归深度限制。✅ 大数据用迭代 DP；递归只用于教学演示或配合 `lru_cache`。

代码（可直接运行，按标题路线给出四种写法）：

```python
from functools import lru_cache


def brute_solve(w, v, C):
    """① 暴力递归：每件物品取/不取两个分支，指数级，仅限教学演示。"""
    def rec(i, c):                       # 前 i 件（下标 0..i）、剩余容量 c
        if i < 0 or c <= 0:              # 没有物品或没有容量 → 价值 0
            return 0
        if w[i] > c:                     # 第 i 件太重装不下，只能跳过
            return rec(i - 1, c)
        return max(rec(i - 1, c),                    # 不取第 i 件
                   rec(i - 1, c - w[i]) + v[i])      # 取第 i 件
    return rec(len(w) - 1, C)


def memo_solve(w, v, C):
    """② 记忆化搜索：递归 + 缓存，重叠子问题只算一次。"""
    n = len(w)

    @lru_cache(maxsize=None)
    def dfs(i, c):
        if i < 0 or c <= 0:
            return 0
        if w[i] > c:
            return dfs(i - 1, c)
        return max(dfs(i - 1, c), dfs(i - 1, c - w[i]) + v[i])

    return dfs(n - 1, C)


def solve_2d(w, v, C):
    """③ 自底向上二维 DP：返回整张表，供回溯输出具体方案。"""
    n = len(w)
    dp = [[0] * (C + 1) for _ in range(n + 1)]   # dp[i][j]: 前 i 件、容量 j
    for i in range(1, n + 1):                    # 外层：逐件加入决策
        wi, vi = w[i - 1], v[i - 1]
        for j in range(1, C + 1):                # 内层：枚举所有容量
            if wi <= j:                          # 装得下：取与不取取较大
                dp[i][j] = max(dp[i - 1][j], dp[i - 1][j - wi] + vi)
            else:                                # 装不下：继承上一行结果
                dp[i][j] = dp[i - 1][j]
    return dp


def solve_1d(w, v, C):
    """④ 滚动数组：只保留容量维，空间 O(C)。★容量必须逆序遍历。"""
    dp = [0] * (C + 1)
    for i in range(len(w)):                      # 每件物品就地更新一遍 dp
        for j in range(C, w[i] - 1, -1):         # 逆序！保证每件只用一次
            # 此刻 dp[j - w[i]] 仍是上一件处理完的旧值
            dp[j] = max(dp[j], dp[j - w[i]] + v[i])
    return dp


def traceback(dp, w, C):
    """根据二维表自后往前回溯，返回被选中物品的下标（0 基）。"""
    picked, j = [], C
    for i in range(len(w), 0, -1):
        if dp[i][j] != dp[i - 1][j]:             # 本行比上一行更优 ⇒ 第 i 件被取
            picked.append(i - 1)
            j -= w[i - 1]                        # 腾出它的重量继续往前查
    return picked[::-1]


if __name__ == "__main__":
    # 样例：4 件物品 (重量, 价值) = (2,3) (3,4) (4,5) (5,6)，背包容量 8
    weights = [2, 3, 4, 5]
    values = [3, 4, 5, 6]
    C = 8

    print("① 暴力递归:", brute_solve(weights, values, C))
    print("② 记忆化  :", memo_solve(weights, values, C))
    dp2 = solve_2d(weights, values, C)
    print("③ 二维 DP :", dp2[len(weights)][C])
    print("④ 滚动数组:", solve_1d(weights, values, C)[C])
    print("⑤ 具体方案:", traceback(dp2, weights, C))
```

**案例详解**

运行后①②③④ 四行输出均为 `10`，即容量 8 时的最大总价值；`⑤ 具体方案: [1, 3]` 表示最优解为第 1 件（w=3, v=4）与第 3 件（w=5, v=6），总重量 3+5=8 ≤ C，总价值 4+6=10，恰好用满容量。

一维滚动数组每处理完一件物品后的中间状态如下，可与二维表的每一行对照理解：

- 处理完物品 0（w=2, v=3）：`dp = [0,0,3,3,3,3,3,3,3]`（容量 ≥ 2 都可只装它）；
- 处理完物品 1（w=3, v=4）：`dp = [0,0,3,4,4,7,7,7,7]`（容量 5 时 2+3 ≤ 5，价值 3+4=7）；
- 处理完物品 2（w=4, v=5）：`dp = [0,0,3,4,5,7,8,9,9]`；
- 处理完物品 3（w=5, v=6）：`dp = [0,0,3,4,5,7,8,9,10]`，答案取 `dp[8] = 10`。

回溯为何得到 [1, 3]：从 (i=4, j=8) 出发，`dp[4][8]=10 ≠ dp[3][8]=9` ⇒ 第 3 件被取，j 减 5 变 3；`dp[3][3]=4 == dp[2][3]=4` ⇒ 第 2 件未取；`dp[2][3]=4 ≠ dp[1][3]=3` ⇒ 第 1 件被取，j 减 3 变 0，结束。

复杂度：① 暴力递归最坏 $O(2^n)$，仅适合 $n \le 20$；②③④ 时间均为 $O(n \cdot C)$（② 只访问递归到达的状态，总量仍 ≤ $O(n \cdot C)$）；空间上 ②③ 为 $O(n \cdot C)$（缓存 / 整表），④ 仅为 $O(C)$，因此滚动数组写法是面试与竞赛中的最终推荐。

## 对比选型
| 方案 | 核心思想 | 最佳场景 |
|------|---------|----------|
| 本文方案（一维滚动数组 DP） | 自底向上填表，容量逆序就地更新，保证每件物品只用一次 | 求精确最优解且不要求输出方案；时间 $O(n \cdot C)$、空间 $O(C)$，面试与竞赛首选 |
| 替代方案：二维自底向上 DP | 保留完整 $(n+1)\times(C+1)$ 状态表，每格只依赖上一行 | 需要回溯输出「具体选了哪些物品」，或作为教学演示 |
| 替代方案：记忆化搜索（自顶向下） | 递归 + 缓存，只计算递归真正到达的状态 | 状态稀疏（大量 $(i, c)$ 不可达，如容量大而组合受限）；由已有暴力递归改造成本最低 |
| 替代方案：贪心（单位价值降序） | 每步局部最优，优先装入性价比最高的物品 | 分数背包（物品可分）可证明最优；0-1 背包只能得到近似解，如 C=50 时 (10,60)(20,100)(30,120)，贪心得 160 < 最优 220 |
