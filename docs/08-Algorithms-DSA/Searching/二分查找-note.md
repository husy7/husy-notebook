# 二分查找（含边界处理与变体）

## 定义

二分查找（Binary Search），又称折半查找，是一种在**有序数组**上通过不断把搜索区间对半划分来定位目标值的查找算法。它解决的核心问题是：给定一个已排序的序列与一个目标值，在 $O(\log n)$ 时间内判断目标是否存在并返回其下标（或第一个满足某条件的下标），远快于顺序扫描的 $O(n)$。

核心特征：
1. **输入前提是有序**：数组必须按升序（或降序）排列，否则"丢弃一半区间"的推理不成立，结果不可信；
2. **依赖随机访问**：需在 $O(1)$ 时间取到任意下标元素（如 Python list、C 数组），链表上无法 $O(1)$ 取中值，二分退化为低效扫描；
3. **迭代不变量（Loop Invariant）**：每轮都维护一个"可能包含目标值"的区间 $[low, high]$，通过比较中值与目标，丢弃确定不含目标的那一半；
4. **单路径分治**：每轮只处理一个子区间、只沿一条路径下钻，不回溯、不合并，逻辑比归并排序等"双路分治"简单；
5. **只定位不搬运**：它只做"查找/定位"，不改动数据，返回下标、插入点或边界位置。

适用范畴：一切"搜索空间随下标或参数单调"的定位问题——精确值查找、上下界查找（lower_bound / upper_bound）、重复元素区间统计、以及"最大值最小化 / 最小值最大化"类的**二分答案**问题和单调连续函数求根（浮点二分）。

## 原理

**思路**：为什么能每次砍掉一半？关键在**有序性**。设数组升序，比较中值 $A[mid]$ 与 $target$ 后只有三种情况：相等即命中；$A[mid] < target$，则由单调性，$mid$ 及其左侧全部元素都小于 $target$，整个左半边（含 $mid$）不可能含答案，直接丢弃，答案只可能在 $[mid+1, high]$；$A[mid] > target$ 时对称地丢弃右半边，答案在 $[low, mid-1]$。每一轮区间长度近似减半：$n \to n/2 \to n/4 \to \cdots \to 1$，因此至多 $\lceil \log_2(n+1)\rceil$ 轮后要么命中，要么区间耗尽证明目标不存在。

核心流程（以闭区间 $[low, high]$ 版本为例）：
1. 初始化 $low=0,\ high=n-1$，不变量：若 $target$ 存在，则必在闭区间 $[low, high]$ 内；
2. 循环条件 $low \le high$（区间非空），取中点 $mid = low + \lfloor (high - low)/2 \rfloor$；
3. 三分支移动边界：命中返回；偏小则 $low = mid + 1$；偏大则 $high = mid - 1$；
4. 循环结束仍未返回，说明 $target$ 不存在，返回 $-1$ 或插入点。

关键细节与推导：
- **防溢出写法** $mid = low + (high - low) // 2$：在 C/Java 等 32 位定长整数语言里 $(low+high)$ 可能超过上限而溢出成负数（经典 bug），减法形式把差值控制在区间长度内，安全；Python 整数不限长，此写法主要为了习惯一致与可移植。
- **区间表示必须自洽**：闭区间 $[low, high]$ 配 `while low <= high`、两端分别 $\pm 1$；左闭右开 $[low, high)$ 配 `while low < high`、中值偏左、左移 $+1$ 右移不动的写法。混用必然造成漏元素或死循环。
- **复杂度推导**：设第 $k$ 轮后区间长度为 $n / 2^k$，区间耗尽需要 $n / 2^k \le 1$，即 $k \ge \log_2 n$。故**最好** $O(1)$（首轮 $mid$ 恰为目标），**最坏与平均** $O(\log n)$；每轮仅常数次比较与赋值，**空间**迭代版 $O(1)$，递归版因调用栈深度为 $O(\log n)$。

## 应用

典型使用场景：
- **精确查找**：判断元素是否存在于有序列表并返回下标（LeetCode 704 即模板题）；
- **上下界与区间统计**：`lower_bound(x)` / `upper_bound(x)` 求"第一个 $\ge x$"与"第一个 $> x$"的下标，两者之差即等于 $x$ 的元素个数，也用于求有序数组的插入点以保持有序——Python 标准库 `bisect` 直接封装了这两个变体；
- **二分答案**：当"可行性"关于解值单调时（如给定体力最多能种多少树、分割数组使各段和最大值最小），对答案的值域二分，每次用 $O(n)$ 校验，总复杂度 $O(n \log V)$；
- **浮点求根**：对单调连续函数（如 $f(x)=x^2-2$）在实数区间上按精度二分，逼近 $\sqrt{2}$ 或函数零点。

快速上手步骤：
1. **确认单调性**：搜索空间（下标域或答案值域）必须有序/单调，无序则先排序，但注意排序会丢失原始下标，需要时先用元组记录；
2. **固定一种写法**：新手建议统一用闭区间 `[l, r]` + `while l <= r` + `l = mid+1 / r = mid-1`，想清楚"找到/未找到分别返回什么"；
3. **处理重复元素**：需要第一个/最后一个目标时改用 `bisect_left`/`bisect_right` 风格的变体；
4. **手推小用例**：拿空数组、单元素、目标在首尾、目标不存在、含重复元素 5 类用例各跑一遍，验证不变量与终止；
5. **警惕死循环与 off-by-one**：任何一版写完后，检查每轮 $low$、$high$ 是否必然向中间收缩。

常见坑 ❌/✅：
- ❌ 区间与循环条件不匹配：`while low < high` 却用闭区间逻辑，漏掉最后一个候选元素。✅ 闭区间用 `<=`，左闭右开用 `<`，两种风格选定后全程自洽。
- ❌ 死循环：`while l < r` 且中值偏左（`(l+r)//2`）时写 `l = mid`，当区间剩两个元素（如 $[3,4]$）时 `mid` 恒为 3、`l` 永不前进。✅ 要么写 `l = mid + 1`，要么在中值取偏左时配合 `r = mid`（参考变体 B 的写法）。
- ❌ 整型溢出：`(l + r) // 2`。✅ 写 `l + (r - l) // 2`。
- ❌ 对无序数组直接二分得出"看似合理"的错误结果。✅ 先保证单调，或在排序前的副本上操作。
- ❌ 重复元素时用"返回任意一个"的版本，得到的位置不确定。✅ 需要边界时用 lower/upper 变体，`[left, right)` 才是全部等于 $x$ 的下标区间。
- ❌ 递归/循环结束后忘记处理 $high$ 为 $-1$ 或越界为 $n$ 的返回语义。✅ 循环外统一返回哨兵（-1 或插入点 $low$），并用边界用例单测。

```python
def binary_search(nums, target):
    """变体 A：闭区间精确查找——找到返回下标，找不到返回 -1。"""
    low, high = 0, len(nums) - 1        # 闭区间 [low, high]；不变量：target 若存在必在此区间内
    while low <= high:                  # 区间非空才继续（low == high 时仍要检查最后那个元素）
        mid = low + (high - low) // 2   # 防溢出写法，等价于 (low + high) // 2
        if nums[mid] == target:
            return mid                  # 命中：直接返回下标
        elif nums[mid] < target:
            low = mid + 1               # 左半边全部 < target，整体丢弃，去右半边找
        else:
            high = mid - 1              # 右半边全部 > target，整体丢弃，去左半边找
    return -1                           # 区间耗尽仍未命中：target 不存在


def lower_bound(nums, target):
    """变体 B：左闭右开 [0, n)，返回第一个 >= target 的下标（等价 bisect_left）。
    用于在含重复元素的有序数组中定位左边界 / 求插入点。"""
    low, high = 0, len(nums)            # high 指向哨兵 n，保持 [low, high) 语义一致
    while low < high:                   # 区间为空（low == high）时即收敛出答案
        mid = low + (high - low) // 2   # 中点偏左：只剩两个元素时 mid 取左边那个
        if nums[mid] < target:
            low = mid + 1               # nums[mid] < target：mid 不可能是答案，排除
        else:
            high = mid                  # nums[mid] >= target：mid 可能是答案，保留进区间
    return low                          # 此刻 low == high，即第一个 >= target 的下标


def upper_bound(nums, target):
    """变体 C：左闭右开，返回第一个 > target 的下标（等价 bisect_right）。
    与 lower_bound 配合：[lower_bound(x), upper_bound(x)) 恰好覆盖所有等于 x 的元素。"""
    low, high = 0, len(nums)
    while low < high:
        mid = low + (high - low) // 2
        if nums[mid] <= target:
            low = mid + 1               # 等于 target 也不保留，继续向右找严格大于的位置
        else:
            high = mid
    return low


def sqrt_float(x, eps=1e-9):
    """变体 D：二分答案——在单调连续函数上按精度二分，逼近 sqrt(x)。"""
    low, high = 0.0, float(x)           # x >= 1 时 sqrt(x) 必落在 [0, x]
    while high - low > eps:             # 浮点区间用"宽度"判停，不能套用 low <= high
        mid = (low + high) / 2.0
        if mid * mid < x:
            low = mid                   # mid 平方偏小，答案在右侧
        else:
            high = mid                  # mid 平方偏大，答案在左侧
    return (low + high) / 2.0


if __name__ == "__main__":
    a = [1, 3, 3, 5, 7, 9]              # 有序数组（含重复元素 3）
    print(binary_search(a, 3))          # 2   首轮 mid=2 即命中（重复时只保证"某个"位置）
    print(binary_search(a, 6))          # -1  不存在，3 轮后区间耗尽
    print(lower_bound(a, 3))            # 1   第一个 >= 3 的下标
    print(upper_bound(a, 3))            # 3   第一个 > 3 的下标，故 3 的区间是 [1, 3)
    print(upper_bound(a, 9))            # 6   超过末尾时返回 len(a) 这个哨兵位
    print(sqrt_float(2.0))              # 1.41421356237（约等于根号 2）
```

**案例详解**：主函数先在有序数组 `a = [1, 3, 3, 5, 7, 9]` 上验证四个变体。`binary_search(a, 3)` 首轮 `mid = 0 + (5-0)//2 = 2`，恰好 `a[2] == 3`，一次命中返回 `2`——注意重复元素下它返回的是"某一个"3，不能用于求边界，这正是变体 B/C 存在的意义。`binary_search(a, 6)` 依次比较 $a[2]=3<6$ 把下界推到 3、$a[4]=7>6$ 把上界压到 3、$a[3]=5<6$ 再推到 4，最终 `low=4 > high=3` 循环结束返回 `-1`，共 3 轮比较，与 $\lceil \log_2 6\rceil = 3$ 吻合。`lower_bound(a, 3)` 用左闭右开写法：中值偏左、`nums[mid] >= target` 时右边界收到 `mid`（候选保留）、`< target` 时左边界收到 `mid+1`（候选排除），最终收敛于 `1`；`upper_bound(a, 3)` 把判断改为 `nums[mid] <= target` 才右移，得到 `3`，于是"所有等于 3 的元素"恰好是下标区间 $[1,3)$。`upper_bound(a, 9)` 返回 `len(a)=6`，说明上界变体天然用哨兵位表达"目标大于所有元素"。最后的浮点二分每轮让区间宽度减半，从宽度 2 缩到 $10^{-9}$ 约需 $\log_2(2\times 10^9)\approx 31$ 次迭代，与数组长度无关，这是浮点二分与整数二分在终止条件上的关键区别。

## 关联
- 前置：[[快速排序-note]]（二分查找要求输入有序，快速排序是把无序输入变有序的典型手段；二者共享"切分区间、缩小问题规模"的分治直觉，先掌握快排的分区与递归再学二分更顺）。
- 类似：[[归并排序-note]]（同属每轮把区间对半划分的分治算法；区别是归并排序把两个子区间**都**递归处理后再合并，而二分查找每轮只保留**可能含目标的那一半**继续下钻，是单路径分治，无需合并与回溯）。
- 进阶：[[哈希表-note]]（把"查找"从有序下标推广到任意可哈希键的检索结构，平均 $O(1)$；区别与取舍是哈希表不支持顺序/范围查询与上下界操作，因此在有序数据上的定位与二分答案场景中，二分查找不可替代）。

## 对比选型
| 方案 | 核心思想 | 最佳场景 |
|------|---------|----------|
| 本文方案：有序数组二分查找 | 每轮比较中值，丢弃不含目标的一半区间，$O(\log n)$ 定位 | 静态有序数据上的精确查找、lower/upper 边界、二分答案，Python 中直接交给 `bisect` |
| 线性查找（顺序扫描） | 从头到尾逐一比较 | 数据无序、规模很小、或只能顺序访问的结构（链表） |
| 哈希表 | 键经散列函数映射到桶，平均 $O(1)$ 存取 | 无序等值键的检索、去重与计数；不支持范围查询与有序遍历 |
| 平衡二叉搜索树（BST/跳表） | 用树高 $O(\log n)$ 的动态结构维持有序 | 需要频繁插入删除、同时要求保持有序可查询的动态数据（静态数组场景二分更省） |
