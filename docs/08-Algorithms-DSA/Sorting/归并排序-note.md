# 归并排序（Merge Sort）

## 定义

归并排序（Merge Sort）是一种基于"分治（Divide and Conquer）"策略的稳定比较排序算法，由 John von Neumann 于 1945 年提出。它要解决的问题是：给定一个由可比较元素构成的序列，将其按升序（或降序）重排，同时要求算法在最坏情况下依然高效，且能保持相同关键字元素的原始相对次序（稳定性）。

核心思想是把"排序整个数组"这个复杂任务递归地拆成"排序两个更小的半段"这一简单子任务：每次把待排序区间对半切开，分别把两半排好，再通过一趟线性扫描把两个有序子序列合并为一个整体有序的序列。

核心特征：时间复杂度在任何输入分布下（最好/最坏/平均）都是 $$O(n\log n)$$，稳定性好，但需要 $$O(n)$$ 的辅助空间（不像堆排序那样可以原地完成）；对顺序存储的数组它不依赖基准（pivot）的选取，因此不存在快速排序那样"最坏退化到 $$O(n^2)$$"的问题。

适用范畴：需要稳定排序、无法回避最坏情况性能、数据规模较大且内存可容纳（或借助磁盘分阶段处理的外部排序）、以及对链表这类不支持随机访问的线性结构排序——归并排序只需顺序访问，天然适合链表。它也是 TimSort、多路归并（K-way merge）、逆序对统计等众多实用算法的基础组件。

## 原理

思路：归并排序建立在一个显然的事实之上——**两个各自有序的序列可以在 $$O(n)$$ 时间内合并成一个有序序列**（只需不断比较两段的头部、取走较小者）。那么只要保证"每一半已经有序"，合并的结果就一定整体有序。于是问题从"排整个数组"递归缩小为"排更短的子数组"，直到子数组长度 ≤ 1——长度为 0 或 1 的序列天然有序、无需再排，这就是递归基。

完整流程分三步（自顶向下版本）：
1. **分解（Divide）**：取中点 $$mid=\lfloor(lo+hi)/2\rfloor$$，把区间 $$[lo,hi]$$ 切成 $$[lo,mid]$$ 与 $$[mid+1,hi]$$；
2. **解决（Conquer）**：递归地对两个子区间各自执行归并排序，使它们分别有序；
3. **合并（Combine）**：用双指针从左、右两段头部同时向后扫描，每次把较小者写入辅助数组；某一段耗尽后，把另一段剩余元素顺序拷入，最后整体写回原区间。

与快速排序"先划分（把大部分比较放在向下递归前）、后递归"相反，归并排序是**先递归到底、再在回溯过程中合并**——几乎全部比较工作集中在合并阶段。其运行时间的递推关系为：
$$T(n)=2T(n/2)+O(n)$$
其中 $$2T(n/2)$$ 是两个规模减半子问题的求解代价，$$O(n)$$ 是一次合并的线性代价。用递归树观察：每一层总共要处理恰好 n 个元素，递归树共 $$\log_2 n$$ 层，于是
$$T(n)=O(n\log n)$$
（按主定理：$$a=2,b=2,f(n)=O(n)=\Theta(n^{\log_2 2})$$，属于临界情形，同样得出 $$O(n\log n)$$。）由于切分总是严格对半、与输入顺序无关，最好、最坏、平均时间复杂度**同为** $$O(n\log n)$$——这是它相对快速排序最突出的理论优势。

空间方面：每层合并需要一个与区间等长的临时数组；递归回溯时子层数组即可释放，任一时刻只保留当前递归路径上的辅助空间，峰值 $$O(n)$$；递归调用栈深度为 $$O(\log n)$$。稳定性来自合并规则——相等关键字时优先取左半元素（比较写为 `<=`），使相等记录的相对次序不被破坏。

## 应用

典型使用场景：
- **稳定排序需求**：如按关键字排序后仍要求保持记录的原始录入顺序（多关键字排序的次关键字稳定归并）。
- **外部排序（External Sort）**：数据量大于内存时，先分块排序生成有序"归并段"，再用多路归并（K-way merge，常配合堆/败者树选出各段最小者）逐轮合并——这是数据库与大数据引擎排序的底层思想。
- **链表排序**：链表不支持随机访问，快排/堆排在其上性能退化；归并排序只依赖顺序访问，且在链表上能做到 $$O(1)$$ 额外空间，因而成为链表排序的标准做法。
- **统计逆序对**：合并阶段当右半元素先于左半被取走时，它恰好与左半剩余的全部元素构成逆序对，可顺手计数，总复杂度仍为 $$O(n\log n)$$。
- **生产环境基石**：Python 的 `sorted()` / `list.sort()`、Java 对象数组排序等使用的 TimSort 正是"插入排序 + 归并排序"的混合体，归并负责其中大规模数据的核心阶段。

快速上手步骤：① 写递归函数，参数为数组与区间边界，先写递归基（区间空或只剩一个元素直接返回）；② 计算中点并递归排序左右两半；③ 实现 merge：申请临时数组、双指针比较、处理某段耗尽后的剩余拷贝；④ 分别用偶数个、奇数个元素和含重复元素的数组测试，再与 `sorted()` 在大随机数组上对拍验证正确性与稳定性。

边界条件与易错点（❌/✅）：
- ❌ 递归基写错或区间边界计算失误导致无限递归、栈溢出；✅ 习惯写成 `if lo >= hi: return`，中点用 `mid = (lo + hi) // 2`。
- ❌ merge 循环结束后忘记拷贝"剩余元素"；✅ 双指针任一越界后，必须把另一段从当前指针到末尾的元素整体接入结果。
- ❌ 相等时取右半元素（比较写成 `<`），破坏稳定性；✅ 必须写 `<=`，相等时优先取左半。
- ❌ 用 `float('inf')` 作哨兵防越界，但数据本身含无穷大或浮点元素时出错；✅ 用索引边界判断替代哨兵更稳妥。
- ❌ 小数组也递归到长度 1，函数调用开销大；✅ 工程实现中当区间长度小于阈值（如 16~32）时改用插入排序，这正是 TimSort 的做法。
- ❌ 误以为归并排序"在近乎有序时更快"；✅ 它完全不感知输入有序性，任何输入都是 O(n log n)——想利用有序性应选插入排序或 TimSort。

```python
# -*- coding: utf-8 -*-
"""归并排序：自顶向下递归实现（返回新列表的版本，便于教学演示）"""

def merge(left, right):
    """合并两个已有序的列表，返回合并后仍有序的新列表"""
    result = []
    i = j = 0
    # 双指针：谁小取谁；相等（<=）时优先取左半，保证稳定性
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1
    # 某一半耗尽后，另一半的剩余部分本就整体有序，直接拼接
    result.extend(left[i:])
    result.extend(right[j:])
    return result

def merge_sort(arr):
    """对列表 arr 执行归并排序，返回排好序的新列表"""
    # 递归基：长度为 0 或 1 的序列天然有序
    if len(arr) <= 1:
        return arr
    mid = len(arr) // 2                    # 1. 分解：对半切分
    left = merge_sort(arr[:mid])           # 2. 递归排序左半
    right = merge_sort(arr[mid:])          #    递归排序右半
    return merge(left, right)              # 3. 合并：回溯时线性合并

if __name__ == "__main__":
    data = [38, 27, 43, 3, 9, 82, 10]
    print("排序前:", data)
    print("排序后:", merge_sort(data))

    # 稳定性自测：元素为 (成绩, 学号)，按成绩升序排序
    students = [(88, "A01"), (75, "B02"), (88, "C03"), (75, "D04")]
    sorted_students = merge_sort(students)
    print("稳定排序:", sorted_students)  # 成绩相同者仍保持原学号先后顺序
```

案例详解：以 `data = [38, 27, 43, 3, 9, 82, 10]` 为例。分解阶段：`mid = 3` 切成 `[38, 27, 43, 3]` 与 `[9, 82, 10]`；左半再切为 `[38, 27]`、`[43, 3]`，直到每个区间只剩单元素。回溯合并时：`[38,27]` 合并为 `[27,38]`，`[43,3]` 合并为 `[3,43]`，二者再合并为 `[3,27,38,43]`；右半先得 `[9,82]`，与 `[10]` 合并成 `[9,10,82]`。最后一趟双指针逐对比较（3<9 取 3，9<27 取 9，10<27 取 10，27<82 取 27……），得到 `[3,9,10,27,38,43,82]`。每一趟合并恰好扫描区间全部元素一次：7 个元素约有 $$\lceil\log_2 7\rceil = 3$$ 层，每层代价 O(n)，总计 $$O(n\log n)$$。程序输出为：

```
排序前: [38, 27, 43, 3, 9, 82, 10]
排序后: [3, 9, 10, 27, 38, 43, 82]
稳定排序: [(75, 'B02'), (75, 'D04'), (88, 'A01'), (88, 'C03')]
```

最后一行输出验证了稳定性：同为 88 分的 A01、C03 在排序后仍保持原有先后次序，说明合并比较正确使用了 `<=`。

## 对比选型
| 方案 | 核心思想 | 最佳场景 |
|------|----------|----------|
| 本文方案：归并排序 | 分治：对半切分→递归排好两半→O(n) 线性合并；稳定且复杂度恒为 O(n log n)，代价是 O(n) 辅助空间 | 需要稳定排序、最坏情况要有保证、外部/链表排序、大数据量 |
| 快速排序 | 选基准 pivot→一趟划分使左小右大→递归两侧；平均 O(n log n)、原地、缓存友好，但最坏 O(n²)、不稳定 | 数组驻留内存、无稳定性要求、追求小常数因子的通用排序 |
| 堆排序 | 建最大堆→反复将堆顶与末尾交换并下沉；原地 O(n log n)，但跳跃式访问缓存不友好且不稳定 | 内存受限必须原地、且要求最坏 O(n log n) 保证、不在乎稳定性 |
| 插入排序 | 将新元素依次插入左侧已有序区；小规模/近似有序时接近 O(n)，最坏 O(n²) | 数据量很小或近乎有序时的收尾排序，如 TimSort 对小段的处理 |
