# 快速排序（QuickSort）

## 定义

快速排序（QuickSort）是由 C. A. R. Hoare 于 1960 年提出、1961 年正式发表的一种**基于比较的排序算法**（Comparison Sort），它利用**分治（Divide and Conquer）**策略把大问题不断切成小问题后递归求解。它解决的问题与所有排序算法相同——给定 $n$ 个可比较的元素，按全序关系（如数值从小到大）重新排列；区别在于它追求**就地（in-place）**完成，且平均性能的常数因子很小。

核心特征有三：其一，一趟**划分（Partition）**选定一个枢轴（pivot），把数组整理成「左半全部 $\le$ pivot、pivot 归位、右半全部 $>$ pivot」的形态；其二，划分完成后 pivot 已位于**最终正确位置**，只需递归排序左右两段，**不需要合并**——这与归并排序"先拆到单元素、再合并"形成关键区别；其三，整个过程在原数组上通过交换完成，额外空间只来自递归调用栈。

适用范围非常广：只要数据支持比较（数值、字符串、自定义对象均可），快排几乎都是通用排序的首选；语言标准库与数据库引擎普遍采用它或其变体。它**不稳定**（相等元素的相对顺序可能被打乱）、**最坏情况**可退化为 $O(n^2)$，因此工程实现通常配合随机化 pivot、三数取中（median-of-three）或三路划分（3-way partitioning）来规避退化。

典型地位：快排是实践中平均最快的通用比较排序之一，是《算法导论》等教材讲授分治与随机化算法的标准案例；其划分思想还衍生出快速选择（QuickSelect）、Top-K、求中位数等经典算法。

## 原理

**思路**：先选一个 pivot，通过一趟扫描把所有比它小的元素换到左边、比它大的换到右边，pivot 落位后数组被切分成两个相互独立的子问题；再对两个子区间递归执行同样的操作——"先分治、后无事可做"。每次递归至少确定一个元素（pivot）的最终位置，这是快排收敛的根基。

**核心机制（Lomuto 划分）**：取区间右端为 pivot；维护指针 $i$ 作为"小于区"的右边界（开区间），指针 $j$ 从头扫描，凡遇到 $< pivot$ 的元素就与 $nums[i]$ 交换并把 $i$ 右移一格；扫描结束后把 pivot 换到 $nums[i]$ 并返回 $i$，一趟划分即满足 $nums[lo..i-1] < nums[i] = pivot \le nums[i+1..hi]$。Hoare 划分则从两端相向扫描、交换两侧"错位"的元素，交换次数约为 Lomuto 的 1/3，是工程实现的主流。

**复杂度推导**：设排序长度为 $n$ 的区间耗时 $T(n)$，一趟划分代价为 $\Theta(n)$，随后递归处理长度分别为 $k$ 与 $n-1-k$ 的两段，递推关系为

$$T(n)=T(k)+T(n-1-k)+\Theta(n),\quad T(0)=T(1)=\Theta(1)$$

- **最好/平均**：划分最平衡（每趟近似对半分），$T(n)=2T(n/2)+\Theta(n)$，由主定理得 $T(n)=\Theta(n\log n)$；若随机选 pivot，任意输入下每趟划分"期望平衡"，故期望时间复杂度恒为 $O(n\log n)$。
- **最坏**：数组已有序且固定选端点做 pivot 时 $k=0$，递推化为 $T(n)=T(n-1)+\Theta(n)$，累加得 $T(n)=\Theta(n^2)$。

**空间复杂度**：划分仅靠交换完成、不新建数组；额外开销只是递归调用栈深度——平均（随机划分）$O(\log n)$，最坏（完全失衡退化为 $n$ 层）$O(n)$。实现上可"先递归较短一侧、长侧改尾递归/迭代"把最坏栈深压回 $O(\log n)$。

**稳定性说明**：单向扫描交换会把与 pivot 相等的元素移动到 pivot 另一侧，从而打乱相等元素的原始相对顺序，故快排**不稳定**。

## 应用

**典型使用场景**：对海量数值/字符串做通用排序；作为语言与数据库的通用排序引擎（C 标准库 `qsort`、Java 基本类型数组的 Dual-Pivot QuickSort）；借助划分思想求解第 K 大、Top-K、中位数（快速选择）；以及对内存敏感的原地排序需求。Python 内置 `sorted`/`list.sort` 用的是针对"部分有序"数据优化的 Timsort，但算法面试与自研排序引擎仍以手写快排为主。

**快速上手步骤**：① 递归出口写成 `lo >= hi`；② 实现 `partition`：选 pivot → 单趟扫描交换 → pivot 归位并返回下标；③ 递归调用左右两段；④ 用随机 pivot 或三数取中做退化防护；⑤ 区间小于约 16 个元素时可切换插入排序（cutoff 优化）减少递归开销。

**易错点/坑列表**：
- ❌ 递归出口只写 `lo == hi`，漏掉 `lo > hi` 的空区间，导致无限递归直至 `RecursionError`；✅ 一律写 `lo >= hi`。
- ❌ pivot 固定取最左/最右元素，输入恰好有序或逆序时退化为 $O(n^2)$；✅ 用 `random.randint` 随机选，或"首、中、尾三数取中"。
- ❌ 对**大量重复元素**仍用普通二路划分：每趟只确定一个元素位置，如全等数组退化为 $O(n^2)$；✅ 改用三路划分（$<pivot$ / $=pivot$ / $>pivot$）或双向 Hoare 划分。
- ❌ 把"原地"写成"每层切片新建列表"，产生 $O(n\log n)$ 的复制开销且并非原地；✅ 全程用下标区间与交换操作，不要在递归里传 `arr[:mid]`。
- ❌ 用朴素递归排 $10^6$ 级数据：Python 默认递归深度约 1000，直接抛 `RecursionError`；✅ 先 `sys.setrecursionlimit(...)`，或改写成显式栈的迭代版。
- ❌ 在需要**稳定**排序的场合（多关键字、需保持先序次序）用快排；✅ 稳定性要求请选归并排序（见对比选型）。
- ✅ 正确性自检第一关：空数组与单元素数组必须原样返回，不越界、不递归。

**代码示例（可运行）**：

```python
# -*- coding: utf-8 -*-
"""快速排序（QuickSort）：原地分治排序，期望时间 O(n log n)"""
import random

def partition(nums, lo, hi):
    """Lomuto 划分：把区间整理成 [小于区 | pivot | 大于区]，返回 pivot 下标"""
    pivot_idx = random.randint(lo, hi)                          # ① 随机选 pivot，规避最坏 O(n^2)
    nums[pivot_idx], nums[hi] = nums[hi], nums[pivot_idx]       # 把 pivot 换到右端，便于统一处理
    pivot = nums[hi]
    i = lo                                                      # i 是"小于区"右边界（开区间）
    for j in range(lo, hi):                                     # ② 线性扫描其余元素
        if nums[j] < pivot:                                     # ③ 小于 pivot 的丢进"小于区"
            nums[i], nums[j] = nums[j], nums[i]
            i += 1
    nums[i], nums[hi] = nums[hi], nums[i]                       # ④ pivot 归位：左小右大
    return i

def quicksort(nums, lo, hi):
    """对 nums[lo..hi]（含端点）原地排序"""
    if lo >= hi:                                                # ⑤ 递归出口：空区间或单元素
        return
    p = partition(nums, lo, hi)                                 # 一趟划分，pivot 位置已定
    quicksort(nums, lo, p - 1)                                  # ⑥ 递归排序左半段（全部 < pivot）
    quicksort(nums, p + 1, hi)                                  #    递归排序右半段（全部 > pivot）

if __name__ == "__main__":
    arr = [4, 7, 2, 1, 3]
    quicksort(arr, 0, len(arr) - 1)
    print(arr)                                                  # 输出：[1, 2, 3, 4, 7]
```

**案例详解**：以 `[4, 7, 2, 1, 3]` 为例，首趟随机选中 pivot=3（已换至右端）。指针 j 扫描 0..3：`4<3`否、`7<3`否；`2<3`是 → 交换 `nums[0]` 与 `nums[2]` 得 `[2,7,4,1,3]`，i→1；`1<3`是 → 交换 `nums[1]` 与 `nums[3]` 得 `[2,1,4,7,3]`，i→2。扫描结束把 pivot 与 `nums[2]` 交换得 `[2,1,3,7,4]`，返回 2——元素 3 一步到达最终位置。随后递归排序左段 `[2,1]`（再划分一次变 `[1,2]`）与右段 `[7,4]`（变 `[4,7]`），最终输出 `[1, 2, 3, 4, 7]`。可见每趟至少确定一个元素的位置、两侧互不干扰，这正是"分治后无需合并"的来源；整体约 $\log_2 n$ 层递归、每层总扫描代价 $O(n)$，期望时间 $O(n\log n)$。

## 对比选型
| 方案 | 核心思想 | 最佳场景 |
|------|---------|----------|
| 本文方案（随机化快速排序） | 随机选 pivot 做原地划分并递归；期望 $O(n\log n)$、常数因子小 | 通用随机数据排序、追求平均最快的原地排序；Top-K / 快速选择 |
| 归并排序 | 拆到单元素再逐层合并两个有序段；稳定、需 $O(n)$ 额外空间 | 链表排序、外部排序、要求稳定或最坏 $O(n\log n)$ 保证的场景 |
| 堆排序 | 建堆后反复弹出堆顶重建堆；原地、最坏 $O(n\log n)$ | 内存极紧且要求最坏时间有界，能容忍常数大与不稳定 |
| Python 内置 `sorted`（Timsort） | 归并 + 插入排序混合，自动识别数据中的有序片段 | 业务代码日常排序；近乎有序数据上可接近 $O(n)$ |
