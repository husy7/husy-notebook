## 1. 基本信息
- **题目编号/标题**：274. H 指数（H-Index）
- **难度**：中等
- **标签**：数组、排序、计数、贪心
- **题目链接**：[LeetCode 274. H-Index](https://leetcode.com/problems/h-index/)
## 2. 题目理解
- **输入**：
  - 一个整数数组 citations，其中 citations[i] 表示研究者的第 i 篇论文被引用的次数；长度 n ≥ 1。
- **输出**：
  - 一个整数，表示该研究者的 h 指数。
- **核心规则**：
  - h 指数是满足“至少有 h 篇论文，且每篇论文的引用次数 ≥ h”的最大 h。
  - 如果多个 h 都满足，取最大的那个。
- **示例分析**：
  - `[3,0,6,1,5]` -> `3`
    - 降序排序为 [6,5,3,1,0]：
      - 第 1 篇引用 6 ≥ 1；
      - 第 2 篇引用 5 ≥ 2；
      - 第 3 篇引用 3 ≥ 3；
      - 第 4 篇引用 1 < 4。
    - 最大的满足条件的 h 为 3。
  - `[1,3,1]` -> `1`
    - 降序排序为 [3,1,1]：
      - 第 1 篇引用 3 ≥ 1；
      - 第 2 篇引用 1 < 2。
    - 最大的满足条件的 h 为 1。
## 3. 解题思路与策略
- **思路方向**：
  - 方向 A（排序+遍历）：将 citations 降序排序，然后从大到小寻找最大的 i（或 i+1）使得 citations[i] ≥ i+1。优点是思路直观；缺点是需要 O(n log n) 的时间。适合本题 n 较小的情形。题目官方与多种解法普遍采用该思路。
  - 方向 B（计数/桶排序）：根据题目约束 citations[i] ∈ [0, 1000] 且 n ≤ 5000，用长度为 n+1 的数组统计“引用次数 ≥ k”的论文数量，从大到小找最大的 h 使得 count[h] + count[h+1] + ... ≥ h。优点是 O(n) 时间、O(n) 空间；缺点是需要额外空间。官方题解也给出了这种线性解法。
  - 方向 C（二分）：先将 citations 排序，然后在 [0, n] 区间二分 h，用“至少 h 篇论文引用 ≥ h”的条件判断可行位置。时间 O(n log n)，空间 O(1) 或 O(n) 取决于排序实现；适合作为面试扩展思路。
- **最终选择的方法**：**方向 A（排序+遍历）**。理由：代码简洁、易于理解和实现，在 n ≤ 5000 的约束下完全够用；且便于在面试中快速写出正确解。
- **排序+遍历直觉**：
  - 把引用次数从大到小排列后，“前 i 篇引用是否都 ≥ i”的条件等价于“第 i 篇引用 ≥ i”。
  - 从左到右遍历，找到第一个不满足“ citations[i] ≥ i+1 ”的位置 i，则 i 就是最大的 h；若都满足，则 h=n。
  - 关键变量：排序后的数组 citations（降序）、循环下标 i、返回的 h=i（在第一次失效时）或 n（全部满足）。
  - 关键判断：if citations[i] < i+1: return i。
  - 提前返回：一旦出现引用次数不足以支撑当前 i+1，就返回 i，因为之后只会更难满足。
## 4. 算法步骤
1. 将 citations 按降序排序。
2. 从 i = 0 开始遍历：
   - 子步骤 2.1：如果 citations[i] < i+1，说明前 i+1 篇无法都至少被引用 i+1 次，返回 i。
   - 子步骤 2.2：否则继续下一轮循环。
3. 若循环正常结束，说明对所有 0 ≤ i < n 都有 citations[i] ≥ i+1，则返回 n。
## 5. 复杂度分析
- **时间复杂度**：`O(n log n)`。排序的代价是 O(n log n)，遍历是 O(n)，主项为 O(n log n)。
- **空间复杂度**：`O(1)` 或 `O(n)`。取决于语言排序是否原地；Python 的 sort 是原地排序，算法层面额外空间为常数级。
## 6. 代码实现
```python
        
class Solution:
    def hIndex(self, citations: list[int]) -> int:
        '''
        可以这样理解。
        h = 1的时候，论文中必须有1篇被引用次数>=1
        h = 2的时候，论文中必须有2篇被引用次数>=2
        h = 3的时候，论文中必须有3篇被引用次数>=3
        以此类推......
        '''
        # 步骤1：降序排序
        citations.sort(reverse=True)
        n = len(citations)
        h = 0
        # 步骤2：遍历寻找最大的 h 满足 citations[h] >= h+1
        for i in range(n):
            if citations[i] >= i + 1:
                h += 1
        
        return h

```
## 7. 边界情况与易错点
- **边界 1**：所有论文引用次数为 0 → 0。例如 `[0,0,0]`：
  - 降序后仍为 [0,0,0]；
  - i=0 时 citations[0]=0 < 1，返回 0，符合预期。
- **边界 2**：所有论文引用次数 ≥ n → n。例如 `[4,4,4]`（n=3）：
  - 降序后 [4,4,4]；
  - i=0: 4 ≥ 1；i=1: 4 ≥ 2；i=2: 4 ≥ 3；循环结束返回 3，符合预期。
- **易错点**：
  - 判断时下标从 0 开始，条件应为 citations[i] ≥ i+1，而非 citations[i] ≥ i。
  - 如果用升序排序再从右往左遍历，要注意索引不越界，最安全的写法是 citations[-i-1] ≥ i+1。
  - 题目要求“最大”的 h，因此一旦失效点出现就可以直接返回，不能继续尝试更小的值。
- **反例思考**：
  - 错误做法：只统计“引用次数 ≥ 中位数”的论文数量。例如 `[0,1]`：
    - 中位数为 0 或 1 附近；直接统计可能得到错误 h；
    - 正确应为 1（有 1 篇论文引用 ≥ 1）。
  - 另一错误做法：先计算平均值再向下取整。例如 `[100,0,0]`：
    - 平均约 33；正确 h 应为 1，因为只有 1 篇引用 ≥ 1，而不是 33。
