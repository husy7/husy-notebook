## 1. 基本信息
*   **题目编号/标题**：[134. 加油站]
*   **难度**：[中等]
*   **标签**：[贪心、数组]
*   **题目链接**：[LeetCode 134](https://leetcode.com/problems/gas-station/)

## 2. 题目理解
*   **输入**：两个整数数组 `gas` 和 `cost`，长度均为 `n`。
    - `gas[i]` 表示第 `i` 个加油站可加的油量。
    - `cost[i]` 表示从第 `i` 个加油站到第 `i+1` 个加油站需要消耗的油量。
*   **输出**：若存在一个起始加油站编号，使得汽车能按顺序绕环路行驶一周，则返回该编号；否则返回 `-1`。题目保证若存在解，则解唯一。
*   **核心规则**：
    *   汽车油箱容量无限，初始油箱为空。
    *   从某个加油站出发，依次经过每个加油站，到下一个加油站前必须保证油箱油量足够消耗。
    *   环路：最后一个加油站的下一个是第一个加油站。
*   **示例分析**：
    *   `gas = [1,2,3,4,5]`, `cost = [3,4,5,1,2]` -> `3`
        - 从索引 3 出发，按顺序累计油量始终非负，最终回到 3。
    *   `gas = [2,3,4]`, `cost = [3,4,3]` -> `-1`
        - 总油量 `2+3+4=9`，总消耗 `3+4+3=10`，总油量不足，无法绕行一周。

## 3. 解题思路与策略
*   **思路方向**：
    *   *方向 A (暴力模拟)*：对每个起点，模拟绕行一圈，检查油箱是否始终非负。时间复杂度 `O(n²)`，不可接受。
    *   *方向 B (贪心一次遍历)*：**<-- 选择此方向**。利用“总油量 >= 总消耗”是有解的必要充分条件，并且通过一次遍历找到唯一可能的起点。时间复杂度 `O(n)`，空间复杂度 `O(1)`。
*   **贪心直觉**：
    *   核心思想：如果从某个起点出发，在到达某个加油站时油箱变成负数，那么从该起点到当前加油站之间的任意加油站都不可能是有效起点，因此可以直接跳过这一段，从下一个加油站重新开始检查。
    *   关键变量：`total_tank` 记录全程油量净变化（总油量 - 总消耗），用于判断整体是否有解；`curr_tank` 记录从当前候选起点出发到当前位置的油箱剩余油量；`start` 记录当前候选起点。
    *   遍历过程中，若 `curr_tank < 0`，说明当前候选起点不可行，且该起点到当前位置之间的所有站都不可能作为起点（因为它们在到达当前位置前就已经失败），于是将 `start` 更新为 `i+1`，并将 `curr_tank` 重置为 0。
    *   最终，若 `total_tank >= 0`，则 `start` 即为唯一可行起点；否则返回 `-1`。

## 4. 算法步骤
1.  初始化 `total_tank = 0`，`curr_tank = 0`，`start = 0`。
2.  遍历 `i` 从 `0` 到 `n-1`：
    *   计算 `diff = gas[i] - cost[i]`。
    *   `total_tank += diff`，`curr_tank += diff`。
    *   若 `curr_tank < 0`：
        *   说明从当前 `start` 无法到达 `i+1`，将 `start` 更新为 `i+1`。
        *   重置 `curr_tank = 0`（因为新的起点开始时油箱为空）。
3.  遍历结束后，检查 `total_tank`：
    *   若 `total_tank >= 0`，返回 `start`。
    *   否则返回 `-1`。

## 5. 复杂度分析
*   **时间复杂度**：`O(n)`。只需一次遍历数组。
*   **空间复杂度**：`O(1)`。仅使用常数个变量。

## 6. 代码实现
```python

class Solution:
    def canCompleteCircuit(self, gas: List[int], cost: List[int]) -> int:
        # total_tank 记录从起点 0 到当前位置的累计净油量（总加油 - 总消耗），用于判断全局是否有解
        total_tank = 0
        
        # curr_tank 记录从当前候选起点 start 出发到当前位置的油箱剩余油量
        curr_tank = 0
        
        # start 记录当前候选的起始加油站索引
        start = 0
        
        # 遍历每个加油站
        for i in range(len(gas)):
            # 当前加油站的净收益 = 可加油量 - 到下一站需要消耗的油量
            diff = gas[i] - cost[i]
            
            # 更新全局净油量
            total_tank += diff
            
            # 更新当前段的油箱剩余
            curr_tank += diff
            
            # 如果当前段油箱变为负数，说明从 start 出发无法到达 i+1 站
            # 同时也说明从 start 到 i 之间的任意加油站出发都不可能成功（因为少了一段非负前缀，情况只会更差）
            # 因此将起点更新为 i+1，并重置当前段油箱（新车从新起点出发，油箱为空）
            if curr_tank < 0:
                start = i + 1
                curr_tank = 0
        
        # 遍历结束后，若全局净油量 >= 0，则总油量足够绕一圈，返回找到的起点
        # 否则返回 -1 表示无解
        return start if total_tank >= 0 else -1
```

## 7. 边界情况与易错点
*   **边界 1**：单个加油站（`n = 1`）。
    - 若 `gas[0] >= cost[0]`，返回 `0`；否则返回 `-1`。
    - 代码处理：遍历一次，若 `curr_tank < 0` 则 `start = 1`，但最终 `total_tank >= 0` 时返回 `start`（可能为 1，但此时无意义，因为只有 0 是合法起点）。需注意当 `n=1` 且 `gas[0] < cost[0]` 时，`total_tank < 0`，返回 `-1`；若 `gas[0] >= cost[0]`，`curr_tank >= 0`，`start` 保持 0，返回 0。正确。
*   **边界 2**：总油量恰好等于总消耗。
    - 此时 `total_tank = 0`，存在解，且解唯一。代码会返回 `start`。
*   **易错点**：
    - 忘记重置 `curr_tank` 为 0 当更换起点时，导致后面计算受前面负值影响。
    - 误解“唯一解”的含义：题目保证若有解则唯一，但我们的算法返回的 `start` 可能不是唯一解（如果存在多个可行起点，题目不会出现），因此可以直接返回。
    - 在 `curr_tank < 0` 时，错误地只将 `start` 加一而不是 `i+1`，因为中间所有站都不可能是起点。
*   **反例思考**：
    - `gas = [1,2,3,4,5]`, `cost = [3,4,5,1,2]`，算法模拟：i=0 diff=-2，curr=-2<0 → start=1,curr=0；i=1 diff=-2，curr=-2<0 → start=2,curr=0；i=2 diff=-2，curr=-2<0 → start=3,curr=0；i=3 diff=3，curr=3；i=4 diff=3，curr=6，total=0。最后返回 start=3，正确。

## 8. 做题思路总结
*   **加油站问题的贪心本质**：将每个加油站的净收益 `gas[i] - cost[i]` 视为数组元素，问题转化为寻找一个起始位置，使得从该位置开始的累加和始终非负，且总和非负。
*   **核心技巧**：
    - 用 `total_tank` 判断全局可行性（总油量是否足够）。
    - 用 `curr_tank` 维护从当前候选起点开始的累加和，一旦为负则抛弃当前段，从下一个位置重新开始。
*   **为什么有效**：若从 A 到 B 的累加和变为负，则 A 到 B 之间任意一点作为起点，其在到达 B 前累加和更小（因为少了一段非负的前缀），因此都不可能完成全程，可以直接跳过。
*   **类似题目**：最大子数组和（Kadane 算法）也使用“一旦当前和为负就重置”的思想。
