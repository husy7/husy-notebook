# 模型评估：指标、交叉验证与过拟合

## 定义

模型评估是机器学习流程中**度量模型真实表现、并验证该度量是否可信**的环节，它回答两个核心问题：**"模型表现如何？"**（用指标量化）与 **"结果是否可信？"**（用验证方法保证）。

- **解决什么问题**：度量的是模型的**泛化能力**——即模型在"从未见过"的数据上的表现，而不是对训练集的死记硬背；同时为模型选型、调参、阈值决策和能否上线提供量化依据。
- **核心矛盾——过拟合**：模型把训练集中的噪声当成规律记下来，导致训练集指标漂亮、新数据上表现崩塌。因此评估有一条根本原则：**必须使用模型从未见过的数据（测试集 / 验证集）**，否则一切指标都会严重虚高、评估失去意义。
- **核心特征**：按任务分层度量——分类问题建立在混淆矩阵四元素之上（Accuracy / Precision / Recall / F1 / AUC-ROC），回归问题看误差与拟合优度（MSE / RMSE / MAE / R²）；指标只回答"表现如何"，可信度还要靠验证方法保证。
- **适用范畴**：所有监督学习任务（二分类、多分类、回归），从线性模型、树模型到深度学习都适用；通常配合**交叉验证**（K 折、LOOCV）对指标做多次平均以消除单次随机划分的运气成分，并用**偏差-方差**框架诊断欠拟合 / 过拟合。

## 原理

**① 混淆矩阵：一切分类指标的计数基础**

先定义四个格子——TP（实际正、预测正）、FN（实际正、预测负，漏报）、FP（实际负、预测正，误报）、TN（实际负、预测负）：

| | 预测为正 | 预测为负 |
|----|---------|---------|
| **实际为正** | TP | FN |
| **实际为负** | FP | TN |

这四格把一次预测的结果完整切分，下面所有分类指标都由它们组合而来。

**② 分类指标：公式、机理与适用**

| 指标 | 公式/含义 | 适用 |
|------|-----------|------|
| **准确率 Accuracy** | $(TP+TN)/(总)$ | 类别均衡时 |
| **精确率 Precision** | $TP/(TP+FP)$，预测为正的里面有多少是对的 | 误报代价高（如垃圾邮件） |
| **召回率 Recall** | $TP/(TP+FN)$，真正的正样本找回了多少 | 漏报代价高（如癌症筛查） |
| **F1** | $2 \cdot \frac{P \cdot R}{P + R}$，P 与 R 的调和平均 | 类别不平衡、P/R 都要兼顾 |
| **AUC-ROC** | ROC 曲线下面积，衡量排序/区分能力 | 类别不平衡、阈值无关 |

> 💡 **精确率与召回率是一对矛盾**：把判别阈值调高 → 预测为正的样本变少但更"精"，Precision 上升、Recall 下降；调低阈值则反向。F1 用**调和平均**折中——调和平均对较小值惩罚更重，所以只有当 P 与 R 同时较高时 F1 才高。

**③ 回归指标**

| 指标 | 含义 |
|------|------|
| **MSE / RMSE** | 均方误差及其开方；误差先平方再平均，惩罚大误差；RMSE 量纲与原值一致、更直观 |
| **MAE** | 平均绝对误差，对异常值更鲁棒 |
| **R²（决定系数）** | 模型比"直接取平均"的基线改善了百分之多少，≤1，越大越好 |

**④ 交叉验证：为什么比单次划分更可信**

单次随机划分（`train_test_split`）的结果受"这一刀切在哪"影响很大，换一次随机种子分数就会变。**K 折交叉验证**把数据分成 K 份，轮流以其中 K-1 份训练、剩余 1 份验证，共训练 K 次，再对 K 个验证分数取平均（常用 K=5 或 10）：**平均分**给出泛化能力的点估计，**标准差**给出波动幅度。相比单次划分，它更稳定，且每个样本都当过验证样本、数据利用更充分。

**⑤ 偏差-方差：过拟合 / 欠拟合的解释框架**

**偏差（bias）**是模型过度简化造成的误差，表现为欠拟合；**方差（variance）**是模型对训练集波动过度敏感造成的误差，表现为过拟合。两者构成泛化误差的主要来源，也是"评估结果为什么异常"的诊断依据：

| 状态 | 表现 | 对策 |
|------|------|------|
| **欠拟合** | 训练集与测试集都差 | 增加模型复杂度、加特征 |
| **过拟合** | 训练集好、测试集差 | 正则化、减少特征、更多数据、早停 |

**判断口诀**：训练误差 ≪ 测试误差 → 过拟合；训练误差本身就高 → 欠拟合。

**⑥ 测试集治理：防数据泄漏的原理**

任何需要从数据中"学"参数的步骤——标准化器的均值/方差、特征选择器的系数——都必须**只用训练部分拟合**、再应用到验证部分。若先在全量数据上 fit 再做交叉验证，验证集信息会"泄漏"进训练过程，指标系统性虚高。sklearn 的 `Pipeline` 会把 fit 限定在每一折的训练子集内，自动保证不泄漏。

## 应用

**典型使用场景**
- 模型选型与上线评估：用交叉验证比较多个候选模型，挑出平均分高且波动小的那个。
- 业务代价权衡：垃圾邮件（误报代价高 → 盯 Precision）、癌症筛查（漏报代价高 → 盯 Recall）、类别不平衡（弃 Accuracy，用 Precision/Recall/F1/AUC）。
- 回归预测质检：房价、销量等连续值预测，用 RMSE 把握绝对误差量级、MAE 抗异常值、R² 看相对基线改善。

**快速上手步骤**
1. **先划分**：拆出最终测试集（全流程只允许用它评估一次）；调参期间从训练集再拆**验证集**，或直接对训练集做 K 折。
2. **选指标**：分类按"误报/漏报代价 + 类别是否平衡"在 P/R/F1/AUC 中选；回归按"是否容忍异常值"在 RMSE 与 MAE 间取舍，辅以 R²。
3. **交叉验证**：对训练集跑 `cross_val_score(..., cv=5)`，取 `scores.mean()` 作为泛化估计、`scores.std()` 看稳定性。
4. **诊断过拟合**：对比训练误差与验证误差，按口诀判断状态，再对症下药（正则化 / 加数据 / 早停 / 减特征）。
5. **收尾评估**：全部调参选型结束后，**测试集只评估一次**，得到最终可信指标。

**注意事项 / 常见坑**
- ❌ **类别极度不平衡**时用 Accuracy → "全猜多数类"也看似很高 → ✅ 用 Precision/Recall/F1/AUC。
- ❌ 用**测试集反复调参选模型** → 测试集被"用脏"、指标虚高 → ✅ 拆独立验证集调参，测试集只评一次。
- ❌ 先在全量数据上**拟合标准化器/特征选择器**再做交叉验证 → 数据泄漏、指标虚高 → ✅ 先划分再 fit，或直接套 `Pipeline`。
- ❌ **回归数据有噪声/异常值**时只看 RMSE → 平方误差被异常值带偏 → ✅ 补充 MAE 对比。
- ❌ **小数据集**跑 K 折 → 每折训练集过小、结果高方差、不可靠 → ✅ 增大 K，或使用留一法（LOOCV，K=N）。
- 边界：AUC 反映的是**排序/区分能力**而非绝对准确度，商业落地还需结合具体阈值与误报/漏报的业务代价做最终决策。

```python
# ================= 1) 分类指标：Accuracy / Precision / Recall / F1 =================
from sklearn.metrics import accuracy_score, precision_recall_fscore_support
from sklearn.metrics import roc_auc_score

y_true = [1, 0, 1, 1, 0, 1]   # 真实标签：6 个样本，其中 4 个正类(1)、2 个负类(0)
y_pred = [1, 0, 0, 1, 0, 1]   # 预测标签：第 3 个样本(索引 2)把正类判成负类 → 产生 1 个 FN

# 混淆矩阵统计：TP=3（索引 0/3/5 猜对）、FP=0、FN=1（索引 2 漏报）、TN=2（索引 1/4）
print(accuracy_score(y_true, y_pred))        # 0.8333 = 5/6（6 个里猜对 5 个）
p, r, f1, _ = precision_recall_fscore_support(y_true, y_pred, average="binary")
print(p, r, f1)                              # P=1.0（没有 FP）、R=0.75（漏了 1 个正样本）、F1≈0.857
# ★ 案例要点：Accuracy(0.833) 看不出"漏掉正样本"这件事；若换成类别极不平衡的数据
#   （如 99 个负类 + 1 个正类），全猜负类时 Accuracy=0.99 却毫无召回能力——
#   这正是"类别不平衡时必须弃用 Accuracy、改看 Precision/Recall/F1/AUC"的原因。
#   AUC 需要正类概率而非硬标签：roc_auc_score(y_true, y_prob)（y_prob 是预测为正类的概率）

# ================= 2) K 折交叉验证：把可信度量化出来 =================
from sklearn.model_selection import cross_val_score
from sklearn.linear_model import LogisticRegression

# 假设 X（特征矩阵）、y（标签数组）已就绪；cv=5 → 数据分 5 份，轮流 4 份训练、1 份验证
scores = cross_val_score(LogisticRegression(max_iter=1000), X, y, cv=5)
print(scores.mean(), scores.std())   # 平均分 = 泛化水平点估计；标准差小 = 结果稳定可信
# ★ 案例要点：不要拿单次 train_test_split 的分数下结论——换一次随机种子分数就变；
#   K 折把多次划分的分数取平均并给出波动，模型选型与调参都应以此为基准。
```

## 对比选型

| 方案 | 核心思想 | 最佳场景 |
|------|---------|----------|
| **本文方案：指标评估 + K 折交叉验证（K=5/10）** | 按任务选指标量化表现，把数据分 K 份轮流训练/验证取"平均分±波动"做可信估计，再用训练/验证误差差诊断过拟合 | 中小数据集上的模型选型、调参与上线前评估，追求稳定可信的泛化估计 |
| 替代方案：单次 hold-out（train_test_split） | 一次随机划分为训练/测试，各跑一遍即出结果，成本最低 | 数据量很大（单次划分已足够稳定）或算力受限时的快速粗评 |
| 替代方案：留一法 LOOCV（K=N） | 每轮只留 1 个样本做验证、训练 N 次，最大化利用训练数据 | 样本极珍贵的小数据集；计算成本高且结果方差大，需结合业务判断使用 |
