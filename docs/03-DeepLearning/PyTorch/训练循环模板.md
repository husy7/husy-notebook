# PyTorch 训练循环模板

## 定义

PyTorch 训练循环模板，是把"训练一个模型"的标准流程固定成四步、可循环复用的骨架代码：

> 定义**数据（Dataset/Dataloader）** → 定义**模型** → 定义**损失与优化器** → 跑 **train loop + eval loop**。

它解决的核心问题是：每次写训练脚本都从零组织代码，容易漏掉关键步骤——忘记切换 `model.train()/eval()`、忘记 `opt.zero_grad()`、验证时还建立计算图——导致评估指标错乱或显存浪费。把流程固化成模板后，任何模型都能"填空式"接入训练，只需把注意力放在每个组件的职责上，而不必重复踩框架级的基础坑。

核心特征：① 组件职责单一——Dataset 只回答"一份样本长什么样"，DataLoader 负责批量拼装、shuffle 打乱与并行取数，模型、损失函数、优化器各自独立、可自由替换；② 训练与验证两条循环显式分开，分别用 `model.train()` 与 `model.eval()` 声明所处模式；③ 单步参数更新的顺序固定为五步：`zero_grad → 前向 → loss → backward → step`；④ 按 epoch 汇总并打印 `train_loss / train_acc / val_acc`，便于观察收敛与是否过拟合。

适用范畴：单机单卡、中小规模的监督学习（分类/回归）训练脚本起步，是真实项目脚手架的地基——多卡（`DataParallel`/`DistributedDataParallel`）、混合精度（AMP）、断点续训等都在这个骨架之上再叠加扩展。本质上它是"mini-batch 梯度下降 + autograd 自动微分"的具体落地：外层循环的每一轮迭代，就是一次用一批数据估计梯度并更新模型参数的过程。

## 原理

**为什么是这四步**：训练的本质是反复"用一批数据算出损失 → 求梯度 → 沿负梯度更新参数"。Dataset/DataLoader 负责把原始数据切成 mini-batch；模型前向给出预测（logits）；损失函数量化预测与标签的差距；优化器按 autograd 算出的梯度更新 `model.parameters()`。四步正好构成一次参数更新的最小闭环，所以被固定成模板循环复用。

**Dataset/Dataloader 的工作机制**：继承 `torch.utils.data.Dataset` 只需实现两个方法——`__len__`（返回样本总数）与 `__getitem__(idx)`（返回第 idx 个 `(输入, 标签)`），PyTorch 借此可用统一下标方式对任意数据源取样本；`DataLoader` 在其上完成 batch 拼装、`shuffle` 打乱与 `num_workers` 多进程预取，因此 `for batch in loader` 每次取出的 `(inputs, labels)` 都已经是"批量 + 打乱 + 并行"处理后的结果，训练脚本本身不用关心这批数据怎么凑出来的。

**梯度为什么默认累加**：`.backward()` 把梯度累加到张量的 `.grad` 上而不是覆盖，这是为了支持"把大 batch 拆成小 batch 多次反向、等效一次大 batch 更新"这类用法；代价是普通训练中必须每步先调用 `opt.zero_grad()` 清空上次梯度，否则梯度跨 batch 叠加，参数更新方向错误、loss 震荡。

**模式切换的语义**：BatchNorm 在 train 模式用当前 batch 的统计量、在 eval 模式用训练期累计的 running 统计量；Dropout 在 train 随机失活、在 eval 全量通过。`model.train()` / `model.eval()` 就是切换这些层行为的总开关，评估时忘记切换会得到错乱的 Loss/精度。

**验证为什么不建图**：验证/推理只取前向数值、不参与优化，`with torch.no_grad()` 让前向不建立计算图、不保存中间梯度，既省显存又提速。

**损失与标签约定**：分类任务用 `nn.CrossEntropyLoss`，其内部完成 softmax + 负对数似然，因此模型输出应为 logits（不要再手动 softmax），标签必须是 `long` 类型（`y.long()`）；该损失默认 `reduction='mean'`，把损失按 batch 平均归一化。自定义损失时同样应归一化——用 mean 而非 sum，否则损失大小随 batch 增大而膨胀，学习率语义漂移，这正是"大批次 + 大学习率不收敛"的根源之一（另见 linear scaling rule）。

关键约定速查表（为什么这样做）：

| 步骤 | 原因 |
|------|------|
| `model.train()` / `model.eval()` | 切换 BatchNorm/Dropout 行为，避免评估错误 |
| `opt.zero_grad()` | Ops 默认梯度累加，不清会叠加错梯度 |
| `loss.mean()` 而非 `.sum()` | 归一化损失，不受 batch 大小影响 |
| `with torch.no_grad()` | 验证不建立计算图，省显存 |

## 应用

**典型使用场景**：学习 PyTorch 时写的第一份训练脚本；把论文/他人的模型代码跑通并对比基线；作为自研项目的脚手架，在其上挂 `device` 迁移、AMP、DDP、断点续训等扩展。

**快速上手步骤**：
1. 把数据组织成 Dataset 子类：实现 `__len__` 与 `__getitem__`，决定"一份样本长什么样"；
2. 构造 DataLoader：训练集 `shuffle=True` 打乱，验证集保序（`shuffle=False`），需要时可设 `num_workers` 并行取数；
3. 定义模型、损失函数、优化器（如 `optim.Adam(model.parameters(), lr=1e-3)`）；
4. 写 `train_one_epoch(loader)`：`model.train()` + 五步更新 + 统计 accuracy；写 `evaluate(loader)`：`model.eval()` + `torch.no_grad()` + `argmax(1)` 比对；
5. 外层 `for epoch in range(N)` 依次调两者，打印 `train_loss / train_acc / val_acc`；
6. 观察 val_acc 平台期后，再引入学习率调度、早停、AMP、断点续训等进阶手段。

**常见坑**：
- ❌ 训练时忘记 `model.train()` → 用了验证模式统计，Loss/精度错乱。✅ 严格区分两模式。
- ❌ 分类标签是 `long()`，模型输出是 logits，却直接和 float 比较。✅ logits 用 `argmax`，标签转 long。
- ❌ 每 epoch `val_loader.dataset[:]` 可直接切，但真实项目建议建独立 val_loader 保持与训练一致的 `transform`。
- ❌ 大批次 + 大学习率直接上不收敛。✅ 学习率大致随 batch 增大而调大（linear scaling rule）。
- 边界：多卡（`DataParallel`/`DistributedDataParallel`）、混合精度（AMP）、断点续训超出本节骨架范围，需在骨架之上叠加对应封装。

```python
# ============================================================
# PyTorch 训练循环模板 —— 完整可运行示例（模拟二分类，CPU 可直接跑）
# 覆盖四步：Dataset → DataLoader → 模型/损失/优化器 → train+eval loop
# ============================================================
import torch
import torch.nn as nn
import torch.optim as optim
from torch.utils.data import Dataset, DataLoader

torch.manual_seed(0)                                # 固定随机种子，保证结果可复现
X = torch.randn(1000, 8)                            # 1000 个样本，每个 8 个特征
y = (X[:, 0] + X[:, 1] > 0).long()                  # 构造二分类标签（注意 .long()）

# ---- ① 数据：Dataset 只回答"一份样本长什么样" ----
class DS(Dataset):
    def __init__(self, X, y):
        self.X, self.y = X, y
    def __len__(self):                              # 必须实现：返回样本总数
        return len(self.y)
    def __getitem__(self, i):                       # 必须实现：返回第 i 个 (输入, 标签)
        return self.X[i], self.y[i]

# ---- ② DataLoader：批量 + shuffle（训练打乱，验证保序）+ 可设 num_workers 并行取数 ----
train_loader = DataLoader(DS(X[:800], y[:800]), batch_size=64, shuffle=True)
val_loader   = DataLoader(DS(X[800:], y[800:]), batch_size=64)   # 验证集 shuffle=False

# ---- ③ 模型 / 损失 / 优化器 ----
model   = nn.Sequential(nn.Linear(8, 16), nn.ReLU(), nn.Linear(16, 2))  # 输入8 → 隐层16 → 2类 logits
loss_fn = nn.CrossEntropyLoss()     # 期望 logits 输入 + long 标签；内部 softmax；默认 mean 归一化
opt     = optim.Adam(model.parameters(), lr=1e-2)

# ---- ④ train + eval 循环 ----
for epoch in range(20):
    # -------- 训练循环 --------
    model.train()                   # 训练模式：BN 用 batch 统计、Dropout 随机失活
    run_acc, n = 0.0, 0
    for xb, yb in train_loader:
        opt.zero_grad()             # ① 清空上次梯度（PyTorch 梯度默认累加，不清必错）
        out = model(xb)             # ② 前向，得到 logits
        loss = loss_fn(out, yb)     # ③ 算损失
        loss.backward()             # ④ 反向传播：autograd 建计算图求梯度
        opt.step()                  # ⑤ 更新参数
        # 统计准确率：logits 用 argmax(1) 取类别，与 long 标签比较（不可与 float 直接比）
        run_acc += (out.argmax(1) == yb).sum().item(); n += len(yb)

    # -------- 验证循环 --------
    model.eval()                    # 验证模式：切换 BN/Dropout 行为，避免评估错乱
    with torch.no_grad():           # 推理不建计算图，省显存
        val_out = model(val_loader.dataset[:][0]).argmax(1)      # dataset[:] 直接切片
        va = (val_out == val_loader.dataset[:][1]).float().mean()  # 简单示例可用；真实项目建议独立 val_loader 保持一致 transform
    print(f"epoch {epoch}: train_acc={run_acc/n:.3f} val_acc={va:.3f}")
```

> **案例详解**：`X` 是 1000×8 的高斯随机输入，标签取"前两维之和是否大于 0"，数据线性可分、任务足够简单；800/200 划分训练/验证集，batch_size=64，MLP（8→16→2）+ Adam(lr=1e-2) 训练 20 个 epoch。由于任务简单，train_acc 与 val_acc 会快速逼近 1.0，且两者同步上升说明没有过拟合迹象。这段代码把模板的每个环节都走了一遍：Dataset 两个必须方法、DataLoader 的 train/val 差异、五步更新顺序、模式切换与 no_grad——其中标签在构造时已 `.long()`、比较时 logits 用 `argmax(1)`、每步先 `zero_grad`，正好演示"常见坑"里三条约定。

## 对比选型
| 方案 | 核心思想 | 最佳场景 |
|------|---------|----------|
| 本文方案（手写四步循环） | Dataset→DataLoader→模型/损失/优化器→train/eval loop 全部显式控制，五步更新顺序固定、组件可自由替换 | 学习原理、需要自定义 loss/梯度逻辑的科研与教学、小规模实验起步 |
| PyTorch Lightning Trainer | 用 LightningModule/LightningDataModule 把样板代码（模式切换、device、AMP、checkpoint、logger）收编为框架约定，自动跑 train/val loop | 工程化复现、多卡/TPU 扩展、需要实验记录与自动断点保存 |
| Keras `model.fit`（高层 API） | 编译模型后一行 `fit` 自动完成训练与验证，无需手写任何循环细节 | 快速原型、标准监督学习、不想接触底层循环细节 |
