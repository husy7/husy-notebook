# 课程笔记：人在回路（Human-in-the-loop）与状态管理

## 1. 为什么需要人在回路？
- 代理执行长任务时，可能需要在**调用工具前**进行人工审核（例如确认敏感操作、修正查询参数）。
- LangGraph 通过 **中断（breakpoints）** 和 **状态修改** 提供灵活的人机协作能力。

## 2. 设置中断（Breakpoints）

### 2.1 在编译图时指定中断点
- 使用 `interrupt_before` 或 `interrupt_after` 参数。
- 示例：在调用 `"action"` 节点（即工具执行节点）**之前**中断：
```python
graph = builder.compile(
    checkpointer=memory,
    interrupt_before=["action"]   # 在进入 action 节点前暂停
)
```
- 这样，代理会在决定调用工具后立即停止，等待人工介入。

### 2.2 中断后的状态快照
- 中断后，图的状态被保存到 Checkpointer 中。
- 可以通过 `graph.get_state(config)` 获取当前状态，查看 `next` 属性得知下一个要执行的节点。

## 3. 恢复执行
- 一旦人工确认或修改完毕，使用相同的 `thread_id` 调用 `graph.stream(config)` 或 `graph.invoke(config)`，**不传入新消息**，即可从断点继续。
```python
# 中断后，继续执行
for event in agent.graph.stream(None, config):  # 无新输入
    # 会从 action 节点继续执行，并输出后续事件
```

## 4. 状态历史与“时间旅行”

### 4.1 查看历史快照
- `graph.get_state_history(config)` 返回所有状态快照的迭代器（按时间逆序）。
- 每个快照包含：
  - `values`：当前状态数据（消息列表等）。
  - `next`：下一个要执行的节点。
  - `config`：包含 `thread_id` 和 `thread_ts`（快照唯一标识）。
```python
states = list(agent.graph.get_state_history(config))
for state in states:
    print(state.values["messages"][-1])   # 查看最后一条消息
```

### 4.2 从历史状态恢复（时间旅行）
- 获取特定快照的 `config`（含 `thread_ts`），然后调用 `graph.stream(None, that_config)` 即可从该点继续执行。
- 相当于**回退到过去**，重新执行后续步骤。

## 5. 修改状态

### 5.1 修改当前状态（针对最新状态）
- 获取当前状态：`state = graph.get_state(config)`
- 修改状态中的消息（例如更正工具调用的参数）：
```python
# 假设要修改最后一条 AI 消息中的工具调用参数
last_msg = state.values["messages"][-1]
last_msg.tool_calls[0]["args"]["query"] = "current weather in Louisiana"  # 修改查询
# 应用更新
graph.update_state(config, {"messages": [last_msg]})
```
- 更新后，该状态成为当前状态，继续执行时使用修改后的内容。

### 5.2 修改历史状态（分支）
- 首先获取历史快照的配置（含 `thread_ts`），然后使用该配置调用 `update_state`。
- 这样会创建一个**分支**，从那个历史点分叉出新的执行路径。

### 5.3 添加新消息（模拟工具响应）
- 有时我们想**人工提供工具结果**，而不是真的去调用工具。
- 可以向状态中追加一条 `ToolMessage`，并指定 `as_node="action"`，表示这条消息是作为 `action` 节点产生的。
- 这样，图就会认为工具已执行完毕，直接进入 LLM 节点生成最终答案。
```python
fake_tool_msg = ToolMessage(
    content="54°C",   # 模拟的天气结果
    tool_call_id=...  # 需要与待响应的 tool_call id 匹配
)
graph.update_state(
    config,
    {"messages": [fake_tool_msg]},
    as_node="action"   # 表示这个消息来自 action 节点
)
```

### 5.4 注意事项：自定义 reducer
- 在 AgentState 中，若使用默认 `operator.add`，更新消息是追加。但若想**替换**特定消息（如人工修正），需要自定义 reducer，按 `id` 查找并替换。
- 课程中提供了 `reduce_messages` 函数，实现“相同 ID 替换，否则追加”。

## 6. 实战演示流程

### 6.1 中断示例
1. 创建代理，编译时设置 `interrupt_before=["action"]`。
2. 用户提问 `"What is the weather in LA?"`，代理返回 AI 消息（包含工具调用）。
3. 图在 `action` 节点前暂停，状态中 `next == ["action"]`。
4. 人工查看工具调用参数，若发现错误（如写成 LA 但实际想要 Louisiana），可修改状态。
5. 恢复执行，工具被调用（按修改后的参数），最终返回正确结果。

### 6.2 时间旅行示例
- 执行中产生了多个状态快照。
- 调用 `get_state_history` 列出所有快照，选择较早的某个快照的配置。
- 使用该配置恢复执行，图将从那个时间点重新运行，等同于“回到过去”。

### 6.3 人工提供工具结果（模拟）
- 在中断点，不调用真实工具，而是人工构造 ToolMessage 追加到状态，并标记为来自 `action` 节点。
- 恢复执行时，图直接跳过工具调用，进入 LLM 节点，使用人工提供的观察结果生成答案。

## 7. 核心价值总结
| 功能 | 说明 |
|------|------|
| **中断（breakpoints）** | 在关键节点前暂停，等待人工审核/干预。 |
| **状态查看** | 随时查看当前或历史状态，透明化执行过程。 |
| **状态修改** | 修正代理的错误决策（如查询参数），无需重新开始。 |
| **时间旅行** | 从任意历史状态恢复执行，支持回溯和分支。 |
| **手动注入结果** | 人工模拟工具响应，无需实际调用工具，增强控制权。 |

> **思考**：LangGraph 的 Checkpointer 不仅是持久化工具，更是实现“人在回路”和“时间旅行”的基础。`update_state` 与 `as_node` 参数的组合，使得状态编辑可以精确模拟节点行为，极大提高了代理的可控性和容错性。这种设计非常适合需要人工监督或合规审核的业务场景。
