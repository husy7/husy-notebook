# 课程笔记：持久化（Persistence）与流式（Streaming）

## 1. 为什么需要持久化和流式？
- 代理通常处理**长时间运行的任务**，状态管理至关重要。
- **持久化（Persistence）**：允许保存代理在特定时刻的状态，以便**未来恢复**，支持多轮对话和断点续传。
- **流式（Streaming）**：实时输出代理当前执行的动作和生成的 token，提高用户体验和调试透明度。

## 2. 持久化（Persistence）实现

### 2.1 Checkpointer 概念
- LangGraph 内置 **Checkpointer**，用于在每个节点**之前和之后**自动保存状态。
- 状态持久化后，可以通过 `thread_id` 区分不同会话，支持并发多用户。

### 2.2 使用 SqliteSaver（同步）
```python
from langgraph.checkpoint.sqlite import SqliteSaver

# 内存模式（重启丢失）
memory = SqliteSaver.from_conn_string(":memory:")

# 或连接外部文件/数据库
# memory = SqliteSaver.from_conn_string("checkpoints.db")
```

- 在编译图时传入 Checkpointer：
```python
graph = builder.compile(checkpointer=memory)
```

### 2.3 代理类修改
```python
class Agent:
    def __init__(self, model, tools, system_prompt, checkpointer=None):
        # ... 构建图 ...
        self.graph = graph.compile(checkpointer=checkpointer)
```

### 2.4 使用 `thread_id` 管理会话
- 调用时传入配置 `config`，包含 `thread_id`：
```python
config = {"configurable": {"thread_id": "1"}}
# 首次调用
result = agent.graph.invoke({"messages": [HumanMessage("What is weather in SF?")]}, config)
# 后续跟随问题，使用同一 thread_id
followup = agent.graph.invoke({"messages": [HumanMessage("What about in LA?")]}, config)
```

- **同一 `thread_id`** → 代理拥有完整历史记忆。
- **不同 `thread_id`** → 会话隔离，互不影响。

### 2.5 生产级 Checkpointer
- LangGraph 还支持 **Redis**、**Postgres** 等持久化 Checkpointer，适合分布式部署。

## 3. 流式（Streaming）

### 3.1 流式事件（消息级）
- 使用 `graph.stream()` 替代 `invoke`，返回**事件流**，每个事件是状态的增量更新。
```python
for event in agent.graph.stream({"messages": [HumanMessage("...")]}, config):
    # event 包含节点执行后的新消息
    for msg in event.get("messages", []):
        print(msg)
```
- 输出顺序示例：
  1. AI 消息（包含工具调用）
  2. 工具消息（观察结果）
  3. AI 消息（最终答案）

- 这提供了**透明的执行过程**，便于调试和前端展示。

### 3.2 流式 Token（字词级）
- 使用 `astream_events`（异步方法），需配合**异步 Checkpointer**（如 `AsyncSqliteSaver`）。
```python
from langgraph.checkpoint.sqlite import AsyncSqliteSaver
async_checkpointer = AsyncSqliteSaver.from_conn_string(":memory:")
agent = Agent(..., checkpointer=async_checkpointer)
```

- 遍历事件，过滤 `on_chat_model_stream` 类型，获取 token：
```python
config = {"configurable": {"thread_id": "2"}}
async for event in agent.graph.astream_events(
    {"messages": [HumanMessage("...")]}, config, version="v1"
):
    if event["event"] == "on_chat_model_stream":
        content = event["data"]["chunk"].content
        if content:
            print(content, end="|")   # 实时打印 token
```
- 可以看到 token 逐个输出，提升交互感（类似 ChatGPT 打字效果）。
- 注意：工具调用阶段没有 token 输出，只有最终回答时才会流式输出。

## 4. 综合演示效果

### 4.1 多轮对话（同一 thread_id）
- 问题1：`"What is the weather in SF?"` → 代理搜索 SF 天气。
- 问题2（跟随）：`"What about in LA?"` → 代理知道上下文，自动搜索 LA 天气。
- 问题3（跟随）：`"Which is warmer?"` → 代理比较两者，给出答案。

### 4.2 不同 thread_id 导致“失忆”
- 用 `thread_id="2"` 直接问 `"Which is warmer?"` → 代理无法理解比较对象，要求澄清。

## 5. 关键优势总结
| 特性 | 作用 |
|------|------|
| **持久化（Checkpointer）** | 支持多用户并发、长对话、断点恢复，实现“记忆”。 |
| **流式事件（消息级）** | 实时显示代理的思考/工具调用/观察，增强透明度。 |
| **流式 Token（字词级）** | 提供打字机效果，改善用户体验。 |
| **线程隔离（thread_id）** | 轻松管理不同会话，互不干扰。 |

> **思考**：LangGraph 的 Checkpointer 设计非常优雅，将状态持久化完全透明化，开发者只需在编译时传入即可。`thread_id` 机制天然支持多会话，非常适合构建聊天机器人或工作流引擎。流式 API 则提供了从“黑盒”到“白盒”的可观测性，对调试和用户体验至关重要。
