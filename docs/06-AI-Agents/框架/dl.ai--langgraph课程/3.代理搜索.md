# 课程笔记：代理搜索（Agentic Search）

## 1. 为什么代理需要专门的搜索工具？
- 标准LLM仅依赖**静态权重**，无法获取**动态数据**（如实时天气、最新比分）。
- 许多应用需要**可溯源的信息**（引用来源）来减少幻觉，增强用户信任。
- 代理必须能够**主动调用外部搜索工具**，获取最新、最相关的信息。

## 2. 传统搜索 vs. 代理搜索

| 对比维度 | 常规搜索（如DuckDuckGo） | 代理搜索（如Tavily） |
|---------|------------------------|---------------------|
| 输出形式 | 返回网页链接列表（URLs） | 返回**结构化JSON**，包含答案、摘要、来源 |
| 后续处理 | 需要手动抓取、解析HTML、清洗文本 | 直接提供**清洗后的关键信息** |
| 信息密度 | 夹杂广告、无关内容，噪音多 | 聚焦问题，直接提取最相关的片段 |
| 适用场景 | 人类浏览 | 代理程序直接消费 |
| 速度/效率 | 需多次请求（搜索→抓取→解析） | 一次调用返回答案+上下文 |

## 3. 代理搜索的内部流程（高级实现）
1. **查询理解与分解**：将复杂问题拆分为子问题（例如：“谁赢了2024超级碗？该州GDP？” → 先查冠军，再查州名，再查GDP）。
2. **多源集成**：根据查询类型选择最佳数据源（天气API、新闻API、通用搜索引擎等）。
3. **内容提取**：从检索到的文档中**分块**，通过**向量搜索**或关键词匹配提取最相关的**K个片段**。
4. **结果评分与过滤**：对片段进行相关性评分，剔除低质量或重复内容，保留高价值信息。
5. **结构化输出**：返回包含**答案、来源URL、摘要**的JSON，便于代理直接使用。

## 4. 实战演示：Tavily 代理搜索工具

### 4.1 初始化
```python
import os
from tavily import TavilyClient

tavily = TavilyClient(api_key=os.getenv("TAVILY_API_KEY"))
```

### 4.2 简单搜索示例
```python
response = tavily.search(query="Nvidia Blackwell GPU")
print(response)   # 返回直接答案 + 来源摘要
```
- 结果无需二次解析，已结构化。

### 4.3 对比：常规搜索的繁琐流程
```python
from duckduckgo_search import DDGS

with DDGS() as ddgs:
    results = list(ddgs.text("current weather in SF", max_results=3))
    # 得到URL列表，需手动抓取和解析
```
- 需要自行选择URL、发送HTTP请求、用BeautifulSoup解析HTML、清洗文本 → 输出仍不干净。

### 4.4 Tavily 返回的结构化数据示例（天气查询）
```json
{
  "query": "current weather in San Francisco",
  "answer": "Partly cloudy, 18°C, humidity 65%, wind 10 mph",
  "sources": [
    {"url": "https://weather.com/...", "content": "..."}
  ]
}
```
- 直接包含**答案**和**来源**，干净且可验证。

## 5. 代理搜索的关键要点
- **面向机器**：返回JSON，而非HTML，便于程序化消费。
- **包含来源**：增加可解释性，降低幻觉风险。
- **自动摘要**：无需额外抽取，减少代理的推理负担。
- **适应性**：可根据问题类型路由到专用API（天气、股票、百科等）。

## 6. 人类需求 vs. 代理需求
- **人类**：希望看到可视化图表、完整网页、丰富排版。
- **代理**：需要**精确、结构化、干净的数据**，以快速进行下一步推理。
- 因此，**代理搜索工具**是专为代理“消化”而设计的，与通用搜索引擎有本质区别。
