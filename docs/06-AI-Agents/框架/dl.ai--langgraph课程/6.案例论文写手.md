# 课程笔记：构建论文写作代理（多步研究 + 修订循环）

## 1. 项目概览
- 构建一个 **AI 论文写手（Essay Writer）**，能自动完成：规划 → 研究 → 撰写 → 反思 → 补充研究 → 重新撰写，直到达到最大修订次数。
- 整体流程为 **循环图**，包含多个专用节点。

## 2. 代理状态（复杂状态）
相比之前只有 `messages` 的状态，本次状态包含多个键：

| 键名 | 类型 | 说明 |
|------|------|------|
| `task` | str | 用户输入的写作任务（主题） |
| `plan` | str | 规划节点生成的写作计划 |
| `draft` | str | 当前论文草稿 |
| `critique` | str | 反思节点生成的批评意见 |
| `content` | List[str] | 从 Tavily 检索到的文档列表（累积） |
| `revision_number` | int | 当前修订次数 |
| `max_revisions` | int | 最大允许修订次数 |

- 所有键**不**使用 `operator.add` 装饰（因为需要覆盖而非追加），除了 `content` 我们希望累积添加，但课程中使用手动合并列表。

## 3. 各节点功能

### 3.1 规划节点（Planning Node）
- 输入：`task`（用户主题）。
- 系统提示：`planning_prompt`（指示 LLM 制定论文大纲/计划）。
- 输出：将 LLM 回复存入 `state["plan"]`。

### 3.2 研究计划节点（Research Plan Node）
- 输入：`task`（用于生成查询）。
- 使用 `model.with_structured_output(Queries)` 强制输出字符串列表（`Queries` 是 Pydantic 类，包含 `queries: List[str]`）。
- 对每个查询调用 Tavily 搜索，结果追加到 `content` 列表。
- 更新 `state["content"]`。

### 3.3 生成节点（Generation Node）
- 输入：`task`, `plan`, `content`（文档列表合并为单个字符串）。
- 系统提示：`writer_prompt`（包含文档内容）。
- 用户消息：包含 `task` 和 `plan`。
- 输出：LLM 生成的论文草稿存入 `state["draft"]`，并将 `revision_number` 加 1。

### 3.4 反思节点（Reflection Node）
- 输入：当前 `draft`。
- 系统提示：`reflection_prompt`（要求对草稿提出批评和改进建议）。
- 输出：批评文本存入 `state["critique"]`。

### 3.5 研究批评节点（Research Critique Node）
- 输入：`critique`（从反思节点获得）。
- 使用 `model.with_structured_output(Queries)` 根据批评生成新的搜索查询。
- 执行 Tavily 搜索，将新文档**追加**到现有 `content` 中。
- 更新 `state["content"]`。

## 4. 条件边（Should Continue）
- 在 `generate` 节点之后执行。
- 逻辑：若 `revision_number >= max_revisions`，则跳转到 **结束（END）**；否则跳转到 `reflect` 节点。
- 这样就形成了 **生成 → 反思 → 研究批评 → 生成** 的循环，直到达到最大修订次数。

## 5. 图结构（Graph）

```
[entry] → planning → research_plan → generate ─┬─ (if done) → END
                                                │
                                                └─ (if more) → reflect → research_critique → (loop back to generate)
```

- **节点**：`planning`, `research_plan`, `generate`, `reflect`, `research_critique`
- **普通边**：`planning → research_plan → generate`；`reflect → research_critique → generate`
- **条件边**：从 `generate` 出发，根据 `should_continue` 选择 `END` 或 `reflect`

## 6. 编译与运行
- 编译时传入 `checkpointer`（SqliteSaver）以支持持久化和中断。
- 调用 `graph.stream()` 以实时观察每个节点的输出。

## 7. 图形界面（GUI）演示
- 课程提供了一个简易前端，用于交互式地生成论文。
- 主要功能：
  - **输入主题**，点击“生成论文”。
  - **中断控制**：可在特定节点后暂停（如 `planning` 后、`research_plan` 后等）。
  - **状态查看**：实时查看当前状态（计划、草稿、批评等）。
  - **状态修改**：在中断点修改 `plan` 或其他字段，然后继续执行（“修改状态”功能）。
  - **时间旅行**：通过“状态快照”列表，选择历史状态并恢复（回到过去）。
  - **多线程**：可同时维护多个不同主题的论文线程（不同 `thread_id`）。

## 8. 实战运行示例
- 任务：`"What is the difference between LangChain and LangSmith?"`
- `max_revisions = 2`
- 执行过程：
  1. `planning` → 生成大纲。
  2. `research_plan` → 搜索相关文档。
  3. `generate` → 生成初稿。
  4. `should_continue` → 未达最大修订，跳转 `reflect`。
  5. `reflect` → 生成批评。
  6. `research_critique` → 根据批评搜索补充信息。
  7. `generate` → 生成第二稿（更完善）。
  8. `should_continue` → 修订次数已达 2，结束。

## 9. 状态修改与回退示例
- 在 `planning` 节点后中断，用户可将 `plan` 修改为完全不同的主题（如从“披萨店”改为“果酱甜甜圈在披萨制作中的重要性”），然后继续。
- 也可以通过状态快照回退到之前的某个状态（如回到最初的“披萨店”计划），重新执行。

## 10. 关键设计要点
- **结构化输出**：使用 `with_structured_output` 强制模型返回查询列表，简化解析。
- **累积内容**：`content` 在每次研究后不断追加，保证草稿能利用所有搜集到的信息。
- **循环控制**：通过 `max_revisions` 防止无限循环。
- **中断点**：可在任意节点后设置 `interrupt_after`，方便人工审核和干预。
- **持久化**：所有状态存储在 Sqlite 中，支持多会话和断点恢复。

## 11. 总结与后续
- 本课构建了一个**多步骤、多工具、有循环、可交互**的复杂代理系统，是前几课知识的综合应用。
- 后续资源：可参考 `helper.py` 中的完整实现，并尝试修改提示词、增加更多工具或调整循环逻辑，以适应自己的写作/研究场景。
