# 课程笔记：LangGraph 实现高级代理

## 1. 回顾上一课（纯Python实现）
- 手动循环：用户消息 → 系统提示 → LLM调用 → 解析输出（Thought/Action） → 执行工具 → 获得观察 → 再次调用LLM，直到最终答案。
- 缺点：依赖正则解析，状态管理简单，难以扩展为多代理或复杂流程。

## 2. LangGraph 是什么？
- **LangGraph** 是 LangChain 的扩展，专为**代理和多代理流程**设计。
- 核心理念：将代理的控制流程表示为**图（Graph）**，包含节点（Nodes）和边（Edges）。
- 优势：
  - **循环图**：天然支持 ReAct 中的循环（LLM → 工具 → LLM → ...）。
  - **内置持久化**：支持多对话、断点续传、状态恢复。
  - **“人在回路”（Human-in-the-loop）**：可在关键节点暂停并等待人工输入。
  - **可控性**：明确的边和条件边，流程清晰、可预测。

## 3. LangGraph 核心概念
| 概念 | 说明 |
|------|------|
| **节点（Node）** | 代表一个函数或代理，例如 LLM 调用、工具执行。 |
| **边（Edge）** | 连接节点，定义执行顺序（普通边）。 |
| **条件边（Conditional Edge）** | 根据当前状态决定下一个要跳转的节点（如判断是否调用工具）。 |
| **状态（State）** | 整个图执行过程中共享的数据结构，可持久化。 |

## 4. 状态（State）设计
- 状态是**图内所有节点和边可访问的全局数据**。
- 使用 Pydantic 或 TypedDict 定义，并可通过 `operator.add` 注解实现**增量更新**（而不是覆盖）。

**简单状态示例**（仅消息列表）：
```python
from typing import Annotated, Sequence
from langchain_core.messages import BaseMessage
import operator

class AgentState(TypedDict):
    messages: Annotated[Sequence[BaseMessage], operator.add]
```
- `operator.add` 表示当有新消息时，追加到列表末尾，而非替换。

**复杂状态示例**：
```python
class AgentState(TypedDict):
    input: str
    chat_history: list
    agent_outcome: Optional[str]
    intermediate_steps: Annotated[list, operator.add]   # 只增量添加
```

## 5. 构建 LangGraph 代理（代码实现）

### 5.1 工具准备（以 Tavily 搜索为例）
```python
from langchain_community.tools.tavily_search import TavilySearchResults
tavily_tool = TavilySearchResults(max_results=2)
```
- 该工具名称默认为 `"tavily_search_results_json"`，LLM 会通过此名称调用。

### 5.2 代理类（参数化）
- 参数：`model`（LLM）、`tools`（工具列表）、`system_prompt`（系统提示）。
- 内部构建图：
  1. 创建 `StateGraph(AgentState)`。
  2. 添加节点：`"llm"` → `call_openai` 方法；`"action"` → `take_action` 方法。
  3. 添加条件边：从 `"llm"` 出发，通过 `exists_action` 判断是否进入 `"action"` 或结束。
  4. 添加普通边：从 `"action"` 回到 `"llm"`（循环）。
  5. 设置入口点（`entry_point`）为 `"llm"`。
  6. 编译图（`.compile()`）为 LangChain Runnable。

### 5.3 核心方法实现

#### a. `call_openai`（LLM 节点）
```python
def call_openai(self, state: AgentState):
    messages = state["messages"]
    # 加入系统消息（不持久化到state，只用于本次调用）
    full_messages = [SystemMessage(content=self.system_prompt)] + messages
    # 调用绑定了工具的模型
    response = self.model.invoke(full_messages)
    # 返回新消息（LangGraph自动追加到state["messages"]）
    return {"messages": [response]}
```
- 注意：模型已通过 `bind_tools(tools)` 绑定工具，输出会包含 `tool_calls`。

#### b. `take_action`（工具执行节点）
```python
def take_action(self, state: AgentState):
    last_message = state["messages"][-1]
    tool_calls = last_message.tool_calls   # 列表，支持并行调用
    results = []
    for tc in tool_calls:
        tool_name = tc["name"]
        tool_args = tc["args"]
        tool = self.tools_dict[tool_name]
        observation = tool.invoke(tool_args)
        results.append(ToolMessage(content=observation, tool_call_id=tc["id"]))
    return {"messages": results}
```
- 支持**并行工具调用**（模型一次性输出多个 `tool_calls`）。
- 返回的 `ToolMessage` 会自动追加到状态中。

#### c. `exists_action`（条件边）
```python
def exists_action(self, state: AgentState):
    last_message = state["messages"][-1]
    return len(last_message.tool_calls) > 0   # True → 跳转到 action 节点；False → 结束
```

### 5.4 图构建代码片段
```python
from langgraph.graph import StateGraph, END

class Agent:
    def __init__(self, model, tools, system_prompt):
        self.model = model.bind_tools(tools)
        self.tools = {t.name: t for t in tools}
        self.system_prompt = system_prompt
        
        graph = StateGraph(AgentState)
        graph.add_node("llm", self.call_openai)
        graph.add_node("action", self.take_action)
        graph.add_conditional_edges("llm", self.exists_action, {True: "action", False: END})
        graph.add_edge("action", "llm")
        graph.set_entry_point("llm")
        self.graph = graph.compile()
```

### 5.5 可视化图
```python
# 生成 PNG 图片（需安装 graphviz）

```

## 6. 使用代理（调用与解析结果）

### 6.1 单问题调用
```python
input_state = {"messages": [HumanMessage(content="What is the weather in SF?")]}
result = agent.graph.invoke(input_state)
final_message = result["messages"][-1]
print(final_message.content)
```

### 6.2 复杂问题示例（顺序工具调用）
- 问题：`"Who won the Super Bowl in 2024? What is the GDP of that state?"`
- 执行过程：
  1. LLM 生成第一个 `tool_call`：搜索 `"2024 Super Bowl winner"` → 获得答案（堪萨斯城酋长队）→ 追加观察。
  2. LLM 第二次生成 `tool_call`：搜索 `"GDP of Missouri"`（因为州名来自上一步）→ 获得 GDP 数据。
  3. LLM 综合信息输出最终答案。
- 这展示了**顺序依赖**的工具调用，LangGraph 的循环机制自动处理。

### 6.3 并行工具调用示例
- 问题：`"What is the weather in SF and LA?"`
- LLM 一次性输出两个 `tool_calls`（分别搜索 SF 和 LA 天气）。
- `take_action` 循环执行两个工具，并一次性返回两个 `ToolMessage`，然后回到 LLM 生成最终回答。
- 节省往返次数，效率更高。

## 7. 关键区别与优势总结

| 对比项 | 纯Python实现 | LangGraph实现 |
|--------|-------------|---------------|
| 状态管理 | 手动维护消息列表 | 自动状态机，支持增量更新 |
| 循环控制 | while循环 + 正则解析 | 图结构，通过边和条件边自然循环 |
| 工具调用 | 仅支持顺序调用 | 支持并行调用（一次返回多个tool_calls） |
| 可扩展性 | 难以增加分支或多人协作 | 易于添加新节点、条件分支，支持多代理 |
| 持久化 | 无 | 内置，可保存和恢复对话状态 |
| 可视化 | 无 | 自动生成图结构图 |
| 模型切换 | 需修改API调用代码 | 通过LangChain统一接口，更换模型不影响其他代码 |
