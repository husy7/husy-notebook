# 多模态嵌入、CLIP 与 bge-visualized-m3 比较

> 依据《第三章 索引构建 第二节 多模态嵌入》整理，重点比较单模态与多模态嵌入、CLIP 范式、bge-visualized-m3 特性、编码能力与相似度示例。

## 一、为什么需要多模态嵌入

| 维度 | 说明 |
|---|---|
| 文本嵌入局限 | 只能处理文本，无法理解“那张有红色汽车的图片”这类跨模态查询 |
| 模态墙 | 文本向量和图像向量处于相互隔离的空间 |
| 多模态嵌入目标 | 将图像、文本等不同类型数据映射到同一个共享向量空间 |
| 理想效果 | 描述“一只奔跑的狗”的文字向量，会接近真实小狗奔跑图片的向量 |
| 核心挑战 | 跨模态对齐 |
| 关键技术 | 对比学习、视觉 Transformer、Transformer、注意力机制 |
| 发展脉络 | Word2Vec → BERT 上下文理解 → CLIP 跨模态能力 |

## 二、单模态嵌入 vs 多模态嵌入

| 比较维度 | 单模态嵌入 | 多模态嵌入 |
|---|---|---|
| 输入类型 | 主要处理文本 | 可处理文本、图像、音频、视频等 |
| 向量空间 | 文本向量独立空间 | 不同模态共享同一向量空间 |
| 跨模态检索 | 不支持或能力弱 | 支持图文检索、组合图像检索等 |
| 典型问题 | 无法理解图像查询 | 可对齐“文字描述”与“图片内容” |
| 代表模型 | Word2Vec、BERT、BGE 等文本嵌入 | CLIP、BLIP、ALIGN、bge-visualized-m3 |
| 核心目标 | 编码文本语义 | 打破模态墙，实现跨模态语义对齐 |

## 三、CLIP 模型要点比较

| 维度 | CLIP |
|---|---|
| 全称 | Contrastive Language-Image Pre-training |
| 架构 | 双编码器架构：图像编码器 + 文本编码器 |
| 输出空间 | 图像和文本映射到同一个共享向量空间 |
| 训练策略 | 对比学习 |
| 训练目标 | 最大化正确图文对的向量相似度，最小化所有错误配对的相似度 |
| 核心机制 | “拉近正例，推远负例” |
| 关键能力 | 零样本识别能力 |
| 零样本实现 | 将传统分类任务转化为“图文检索”问题 |
| 示例 | 判断图片是不是猫，只需计算图片向量与“a photo of a cat”文本向量的相似度 |
| 主要价值 | 无需针对特定任务微调，就能泛化理解视觉概念 |

## 四、常用多模态嵌入模型比较

| 模型/系列 | 侧重点 | 特点 |
|---|---|---|
| CLIP | 图文对比学习与零样本 | 多模态嵌入的重要基础范式，双编码器 + 对比学习 |
| BLIP 系列 | 细粒度图文理解与生成 | 专注于提升细粒度的图文理解与生成能力 |
| ALIGN | 大规模噪声数据训练 | 证明利用海量噪声数据进行大规模训练的有效性 |
| bge-visualized-m3 | 统一、全面的现代多模态嵌入 | 在 BGE-M3 文本嵌入底座上引入图像能力，代表性现代模型 |

## 五、bge-visualized-m3 核心特性：M3

| 特性 | 含义 | 具体说明 |
|---|---|---|
| 多语言性 Multi-Linguality | 支持多语言文本表示 | 支持超过 100 种语言，可用于跨语言图文检索的文本侧 |
| 多功能性 Multi-Functionality | 支持多种检索范式 | 文本检索场景下可使用密集检索、多向量检索等 |
| 多粒度性 Multi-Granularity | 覆盖不同长度文本 | 文本侧可从短句处理到长达 8192 个 token 的长文档 |
| 技术架构 | 图像与文本联合建模 | 视觉编码器提取图像 patch token → 映射为与文本同维度的“图像 token” → 与文本 token 一起送入 BGE 的 Transformer 编码器 → 得到统一向量表示 |
| 基础底座 | BGE-M3 | 继承文本嵌入能力，再引入图像能力 |

## 六、Visualized_BGE 编码能力比较

| 编码类型 | 说明 |
|---|---|
| 纯文本编码 | 保持原始 BGE 模型的强大文本嵌入能力 |
| 纯图像编码 | 使用基于 EVA-CLIP 的视觉编码器处理图像 |
| 图文联合编码 | 将图像和文本特征融合到统一的向量空间 |
| 主要应用 | 混合模态检索、多模态知识检索、组合图像检索、多模态查询的知识检索等 |
| 相似度计算 | 使用矩阵乘法计算余弦相似度；嵌入向量被标准化到单位长度 |

## 八、选择建议

| 需求 | 建议 |
|---|---|
| 纯文本 RAG | 优先选择文本嵌入模型，如 BGE 系列 |
| 需要图文跨模态检索 | 选择多模态嵌入模型，如 CLIP、bge-visualized-m3 |
| 需要零样本视觉分类 | CLIP 类模型较合适 |
| 需要多语言、多粒度、多功能文本检索 | bge-visualized-m3 继承 BGE-M3，较有优势 |
| 需要细粒度图文理解与生成 | 可关注 BLIP 系列 |
| 需要大规模噪声数据训练思路 | 可参考 ALIGN |
| 需要混合模态知识检索 | Visualized_BGE / bge-visualized-m3 适用 |

## 九、结论

多模态嵌入的核心目标是打破文本、图像等模态之间的“墙”，在共享向量空间中对齐不同模态的语义。CLIP 通过双编码器和对比学习奠定了重要范式，并具备零样本能力。bge-visualized-m3 则在 BGE-M3 文本底座上引入图像能力，继承多语言、多功能、多粒度特性，适合更统一、更全面的多模态检索。示例结果表明，图文联合编码之间的相似度最高，说明统一向量空间能够有效融合图文语义。实际选型仍需结合任务类型、语言、模态需求、模型大小与部署成本综合判断。
