# 向量嵌入基础、技术演进与选型比较

> 依据《第三章 索引构建 第一节 向量嵌入》整理，重点比较 Embedding 基础、技术发展、训练任务、增强策略与选型维度。

## 一、Embedding 基础概念比较

| 概念 | 说明 |
|---|---|
| 数据对象 | 真实世界中的复杂高维数据，如文本、图像、音频、视频 |
| Embedding 模型 | 深度学习模型，负责将数据对象转换为向量 |
| 输出向量 | 固定长度的一维数组，维度通常在几百到几千之间 |
| 核心意义 | 向量不是随机数值，而是对数据语义的数学编码 |
| 核心原则 | 语义相似的对象，向量距离更近；语义不相关的对象，向量距离更远 |

## 二、相似度度量方式比较

| 度量方式 | 计算逻辑 | 特点 |
|---|---|---|
| 余弦相似度 | 计算两个向量夹角的余弦值 | 最常用；值越接近 1，方向越一致，语义越相似 |
| 点积 | 计算两个向量的乘积和 | 向量归一化后，点积等价于余弦相似度 |
| 欧氏距离 | 计算两个向量在空间中的直线距离 | 距离越小，语义越相似 |

## 三、Embedding 在 RAG 中的作用

| 环节 | 作用 |
|---|---|
| 离线索引构建 | 将知识库文档切分后，用 Embedding 模型把每个文档块转换为向量，存入向量数据库 |
| 在线查询检索 | 用同一个 Embedding 模型将用户问题转换为向量 |
| 相似度计算 | 在向量数据库中计算“问题向量”与“文档块向量”的相似度 |
| 召回上下文 | 选取 Top-K 个文档块，与原始问题一起送给 LLM 生成答案 |
| 质量影响 | Embedding 质量直接决定检索召回内容的准确性与相关性；劣质模型会污染上下文，导致答案质量低下 |

## 四、静态词嵌入 vs 动态上下文嵌入

| 维度 | 静态词嵌入 | 动态上下文嵌入 |
|---|---|---|
| 代表模型 | Word2Vec、GloVe | BERT 等基于 Transformer 的模型 |
| 主要原理 | 为每个单词生成固定、与上下文无关的向量 | 通过自注意力机制，动态考虑句子中所有其他词的影响 |
| 语义能力 | 可验证向量运算，如“国王 - 男人 + 女人 ≈ 王后” | 同一个词在不同语境中生成不同向量 |
| 核心局限/突破 | 无法处理一词多义 | 有效解决一词多义难题 |
| 例子 | “苹果公司发布了新手机”和“我吃了一个苹果”中，“苹果”向量相同 | “苹果”在不同句子中向量不同 |

## 五、RAG 对嵌入技术的新要求

| 新要求 | 说明 |
|---|---|
| 领域自适应能力 | 通用模型在法律、医疗等专业领域往往表现不佳，需要微调或指令适配 |
| 多粒度与多模态支持 | 需处理短句、长文档、代码、图像和表格等不同长度与类型的数据 |
| 检索效率与混合检索 | 向量维度和模型大小影响存储与速度；支持密集检索与稀疏检索结合的模型更有利，如 BGE-M3 |

## 六、训练任务比较：MLM vs NSP

| 训练任务 | 过程 | 目标 | 后续发展 |
|---|---|---|---|
| 掩码语言模型 MLM | 随机遮盖输入句子中 15% 的 Token，让模型预测原始 Token | 学习词元与上下文之间的关系，掌握深层语境语义 | 仍是核心预训练任务 |
| 下一句预测 NSP | 构造句子 A 和 B，50% 为真实下一句，50% 为随机句，让模型判断 | 学习句子间逻辑关系、连贯性和主题相关性 | 后续研究发现可能过于简单甚至损害性能，RoBERTa、SBERT 等移除 NSP |

## 七、效果增强策略比较

| 策略 | 核心思想 | 方法 | 关键点 |
|---|---|---|---|
| 度量学习 | 直接以“相似度”为优化目标 | 收集相关文本对，如（问题，答案）、（新闻标题，正文） | 优化向量空间中的相对距离；拉近正例对，推远负例对；优化排序关系而非绝对相似度值 |
| 对比学习 | 在向量空间中将相似样本拉近，不相似样本推远 | 构建三元组（Anchor, Positive, Negative） | 让 distance(Anchor, Positive) 尽可能小，distance(Anchor, Negative) 尽可能大 |

## 八、MTEB 排行榜四维度比较

| 维度 | 含义 | 选型启示 |
|---|---|---|
| 横轴：模型参数量 | 模型大小 | 参数量越大，潜在能力越强，但计算资源要求越高 |
| 纵轴：平均任务得分 | 综合性能 | 分数越高，通用语义理解能力越强 |
| 气泡大小：嵌入维度 | 输出向量维度 | 维度越高，可编码更丰富语义，但存储和计算成本更高 |
| 气泡颜色：最大处理长度 | 能处理的 Token 上限 | 颜色越深，长文本适应性越好；也是分块策略的重要依据 |

## 九、关键评估维度比较

| 维度 | 关注点 |
|---|---|
| 任务 | RAG 应用应重点关注 Retrieval 检索任务排名 |
| 语言 | 是否支持业务数据语言；中文 RAG 应选明确支持中文或多语言的模型 |
| 模型大小 | 性能与硬件要求、推理速度之间的权衡 |
| 维度 | 语义丰富度与存储、计算资源之间的权衡 |
| 最大 Token 数 | 决定可处理文本长度上限，块大小不应超过此限制 |
| 得分与机构 | 结合得分排名和发布机构声誉初步筛选 |
| 成本 | API 调用成本，或自部署的显存、内存与运维成本 |

## 十、选型流程比较

| 步骤 | 做法 |
|---|---|
| 确定基线 | 根据任务、语言、大小、维度、最大 Token、成本等选择几个初始基准模型 |
| 构建私有评测集 | 根据真实业务数据，创建典型用户问题和标准答案或最相关文档块 |
| 迭代优化 | 在私有评测集上评估召回准确率和相关性；不理想则换模型或调整分块等环节 |
| 最终选择 | 通过多轮对比测试，选出特定场景下表现最佳的模型 |

## 十一、结论

Embedding 是 RAG 语义检索的基础，其质量直接决定检索召回与最终生成质量。技术路线已从静态词嵌入发展到动态上下文嵌入，RAG 又进一步提出领域自适应、多粒度多模态、混合检索等新要求。训练上，MLM 是核心，NSP 后来被部分模型移除；效果增强主要依靠度量学习和对比学习。选型时，MTEB 排行榜可作为起点，但不能只看榜单得分，必须结合任务、语言、模型大小、维度、最大 Token、成本，并在私有评测集上迭代测试。最终目标是找到在特定业务场景下检索准确、成本可控、部署可行的嵌入模型。
