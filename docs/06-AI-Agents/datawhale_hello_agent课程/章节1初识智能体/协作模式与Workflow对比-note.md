# 协作模式与 Workflow/Agent 对比

> 智能体既可作"开发者工具"增强人类，也可作"自主协作者"独立达成目标；Workflow 让 AI 按部就班执行指令，Agent 给 AI 自由度自主达成目标。

## 两种协作模式的边界（1.4.1 / 1.4.2）

| 维度 | 作为开发者工具 | 作为自主协作者 |
|------|--------------|--------------|
| 角色 | 增强而非取代开发者 | 像项目成员，独立规划/推理/执行/反思 |
| 人机关系 | 人主导，AI 辅助 | "命令-执行" → "目标-委托" |
| 自主性 | 低（补全、建议、即时问答） | 高（接手高层级目标直到交付） |
| 典型产物 | 代码补全、重构、调试建议 | 完整代码库、研究报告等复杂成果 |

**工具型代表（1.4.1）：**

| 工具 | 出品 | 形态与特点 |
|------|------|-----------|
| GitHub Copilot | GitHub+OpenAI | 深度集成 VS Code，整行/整函数补全；Copilot Chat 支持编辑器内对话式编程 |
| Claude Code | Anthropic | 终端自然语言指令，理解完整代码库，执行编辑/测试/调试；headless 模式用于 CI、pre-commit、构建脚本 |
| Trae | 新兴工具 | 轻量设计、快速响应，适合频繁迭代与快速原型 |
| Cursor | — | AI 原生代码编辑器，AI 交互为核心，理解整个代码库上下文做问答/重构/调试 |

**协作者型代表（1.4.2）：** 从早期 BabyAGI、AutoGPT，到更成熟的 CrewAI、AutoGen、MetaGPT、LangGraph，架构范式归纳为三个主流方向：

```
① 单智能体自主循环   AgentGPT："思考-规划-执行-反思"闭环，自我提示迭代
② 多智能体协作       CAMEL(角色扮演对话) | MetaGPT/CrewAI(组织化工作流 SOP)
                     AutoGen/AgentScope(灵活对话网络)
③ 高级控制流架构     LangGraph：建模为状态图，支持循环/分支/回溯/人工介入
```

## Workflow vs Agent 的差异（1.4.3）

一句话：**Workflow 让 AI 按部就班执行指令，Agent 赋予 AI 自由度自主达成目标。**

> 图 1.6 Workflow 和 Agent 的差异（原文图片转 ASCII）：

```
Workflow（编排/流程图式）                Agent（自主决策）
┌──────────────────────────┐       ┌──────────────────────────┐
│ 预先定义、结构化的任务序列   │       │ 自主、目标导向的系统        │
│ 条件/顺序精确写死          │       │ LLM 当"大脑"动态推理       │
│ 输入─►步骤A─┬─校验─►步骤B  │       │ 输入─►规划─►选工具─►行动    │
│            └─分支─►步骤C   │       │        └─观察反馈迭代─┘    │
│ 每一步精确、静态、可预测     │       │ 无写死 if-else 规则        │
└──────────────────────────┘       └──────────────────────────┘
```

对比表：

| 维度 | Workflow | Agent |
|------|----------|-------|
| 核心逻辑 | 预先定义、结构化编排，静态流程图 | 自主、目标导向，动态决策 |
| 决策方式 | 条件/顺序写死 | LLM 推理 + 工具调用 |
| 可预测性 | 高（精确可复现） | 中（结果可能不同） |
| 适应变化 | 弱（新情况需改流程） | 强（据实时信息动态调整） |
| 成本/复杂度 | 低、稳定 | 高、需模型与工具管理 |
| 典型例子 | 费用报销审批：金额<500 部门经理 → >500 加财务总监 → 打款 | 旅行助手：天气→景点动态推荐 |

Agent 处理新指令的三个自主步骤（旅行助手为例）：

1. **规划与工具调用**：拆解为 ①查天气 ②基于天气推荐景点，自主选择调用"天气查询 API"并传参"北京"。
2. **推理与决策**：拿到"晴朗，微风"后 LLM 推理"晴天适合户外"，在知识库/搜索引擎中筛选故宫、颐和园、天坛等户外景点。
3. **生成结果**：综合信息给出完整、人性化的回答。

> 关键证据：过程中没有 `if 天气=晴天 then 推荐颐和园` 的写死规则；若换成"雨天"，Agent 会自主推理改推国家博物馆、首都博物馆等室内场所——**基于实时信息的动态推理决策是 Agent 的核心价值**。

## 何时选 Workflow，何时选 Agent

```
任务规则清晰、稳定、可枚举   ──► Workflow（审批流、合规流、固定 SOP）
任务模糊、多变、需实时推理    ──► Agent（开放问答、动态规划、多工具探索）
混合场景（规则为主+少量模糊点）──► Workflow 主骨架 + 关键节点嵌 Agent
```

> 趋势注记（1.4.1）：无论 Copilot 还是 Cursor，共同指向"AI 正深度融入软件开发全生命周期、重塑软件工程效率边界与开发范式"。

## 易错点

> **以为"越自主越高级"**：可预测性、成本、合规是硬约束。报销/退款等强规则场景用 Agent 反而引入不可控与幻觉风险。

> **把带 LLM 的流程一律叫 Agent**：只要步骤顺序和判定条件完全写死、无自主规划，本质仍是 Workflow（哪怕某一步调用了 LLM）。

> **忽略 Agent 的成本与失败模式**：自主决策可能重复调用、陷入循环、产生幻觉，生产使用需最大步数、人工确认、结果校验等护栏。

## 练习

- Q1：两种协作模式的根本区别？  
  A1：人机关系不同——工具型"命令-执行"增强人类；协作者型"目标-委托"，智能体独立规划执行交付。
- Q2：Workflow 与 Agent 的一句话区别？  
  A2：Workflow 让 AI 按部就班执行预设指令，Agent 给 AI 自由度自主达成目标。
- Q3：报销审批、根据天气推荐景点分别更适合哪种？  
  A3：报销审批规则清晰可枚举 → Workflow；天气推荐需据实时天气动态推理 → Agent。
- Q4：CAMEL / MetaGPT / LangGraph 各归属哪类协作范式？  
  A4：CAMEL 角色扮演对话，MetaGPT/CrewAI 组织化工作流（SOP），LangGraph 高级控制流（状态图）。

| 场景 | 选型 |
|------|------|
