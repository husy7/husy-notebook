# 智能体构成与运行原理

> 用 PEAS 模型形式化描述任务环境，用"感知→思考→行动→观察"的 Agent Loop 驱动智能体与环境持续交互。

## 任务环境如何形式化定义（1.2.1）

用 **PEAS 模型** 精确规约任务环境，四个字母对应：

| 字母 | 含义 | 智能旅行助手示例 |
|------|------|-----------------|
| P Performance | 性能度量 | 用户满意度、行程合理性、响应速度 |
| E Environment | 环境 | 网络 API、预订系统、天气/景点数据 |
| A Actuators | 执行器 | 调用天气 API、预订工具、输出文本 |
| S Sensors | 传感器 | 用户输入、API 返回值、工具反馈 |

LLM 智能体所处的数字环境有四个特性，直接影响设计：

| 特性 | 含义 | 对智能体的要求 |
|------|------|---------------|
| 部分可观察 | 只能通过 API 看到部分数据（看不到全部座位信息） | 记忆（记住已查航线）+ 探索（尝试不同日期） |
| 随机性 | 相邻两次调用结果可能不同（票价/余票波动） | 处理不确定性、监控变化、及时决策 |
| 多智能体 | 环境中存在其他行动者（其他用户/脚本/航司调价系统） | 快速响应与策略选择 |
| 序贯 + 动态 | 当前动作影响未来；环境在决策时也在变 | 循环必须快速、灵活地适应变化 |

> 表 1.2"智能旅行助手的 PEAS 描述"即按上述四元组逐项填写，是分析任何任务环境的标准模板。

## 运行机制：Agent Loop（1.2.2）

智能体不是一次性完成任务，而是靠 **智能体循环（Agent Loop）** 与环境持续交互。四个阶段：

```
        ① 感知 Perception ──观察 Observation──┐
              │                                │
              ▼                                │
        ② 思考 Thought                         │
         ├─ 规划 Planning（基于观察+记忆分解子任务）│
         └─ 工具选择 Tool Selection（选工具+定参数）│
              │                                │
              ▼                                │
        ③ 行动 Action（执行器调用工具改变环境）   │
              │                                │
              ▼                                │
        环境状态变化 State Change               │
              │                                │
        新观察 Observation ─────────────────────┘  (回到①，闭环)
```

- **感知（Perception）**：循环起点，传感器接收输入信息，即"观察"（用户初始指令 或 上一步行动的环境反馈）。
- **思考（Thought）**：核心决策阶段，由 LLM 驱动，细分为两步——**规划**（更新理解、制定/调整计划、分解目标）→**工具选择**（从工具库选最合适的工具并确定参数）。
- **行动（Action）**：通过执行器执行，通常表现为调用一个选定工具，改变环境状态。
- 行动引发环境状态变化 → 产生新观察 → 下一轮被感知捕获，闭环从初始状态向目标状态演进。

## 感知与行动的交互协议（1.2.3）

工程上需 **交互协议（Interaction Protocol）** 规范信息交换。智能体输出被结构化为两部分：

- **Thought（思考）**：内部决策的"快照"，自然语言阐述如何分析情境、回顾观察、反思分解、规划下一步。
- **Action（行动）**：对环境施加的具体操作，通常以函数调用形式表示。

```
Thought: 用户想知道北京的天气。我需要调用天气查询工具。
Action: get_weather("北京")
```

外部的 **解析器（Parser）** 捕捉 Action 指令并调用 `get_weather` 函数。执行后环境返回原始数据（如 JSON），感知系统把它封装成简洁自然语言的 **Observation** 反馈给智能体，作为下一轮输入：

```
Observation: 北京当前天气为晴，气温25摄氏度，微风。
```

> 结论：`Thought-Action-Observation` 严谨循环，把 LLM 的语言推理能力与外部环境的真实信息、工具操作能力结合起来。

## 易错点

> **混淆"环境"与"工具"**：工具（执行器）作用于环境，环境是外部世界本身（含其他行动者）。PEAS 里 E 和 A 要分开填写，不能把"天气 API"既当环境又当执行器。

> **把 Observation 等同于工具原始输出**：原始 JSON 含 LLM 无需的冗余信息、格式不符自然语言习惯，必须封装成简洁自然语言再反馈，否则下一轮思考质量下降。

> **忽略"部分可观察"带来的记忆需求**：单凭当前 API 快照决策会重复查询、漏掉信息，需显式保存历史观察（记忆）+ 主动探索（尝试不同查询条件）。

## 练习

- Q1：PEAS 四个字母指什么？  
  A1：Performance 性能度量、Environment 环境、Actuators 执行器、Sensors 传感器。
- Q2：Agent Loop 的四个阶段及闭环如何形成？  
  A2：感知→思考（规划+工具选择）→行动→环境状态变化→新观察→回到感知，不断迭代推进任务。
- Q3：为什么要把工具返回的 JSON 封装成 Observation？  
  A3：原始数据含 LLM 不需要的冗余、格式不符自然语言习惯，封装为简洁自然语言后更利于下一轮推理。
- Q4：Thought 和 Action 分别是什么？  
  A4：Thought 是内部决策的自然语言快照；Action 是对环境的具体操作（通常为函数调用）。
