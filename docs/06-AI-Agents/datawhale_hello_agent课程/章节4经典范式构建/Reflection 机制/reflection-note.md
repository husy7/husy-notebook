## 各模块填写指南

### 必填模块（保证理解与记忆的最小闭环）

| 模块 | 填写要点 | 示例 |
|------|---------|------|
| **一句话总结** | 用一句话说明本质，可含类比或口诀 | “装饰器：闭包传参，不改原函，增强功能。” |
| **核心原理/流程** | 用代码/流程图/公式直击本质，避免长篇描述 | 见上方 ReAct 示例 |
| **易错点/坑** | 只记自己或他人真实踩过的坑，每条一个 ❌+✅ | 见 ReAct 易错点 |
| **提取练习** | 1~3 个问答，覆盖核心概念、区别、陷阱 | Q1/A1, Q2/A2 |
| **关联** | 用链接（Obsidian 双链）连接前置、横向、进阶知识 | 前置：[[闭包]]；横向：[[上下文管理器]] |

### 可选模块触发条件

| 模块 | 何时添加 | 注意事项 |
|------|---------|----------|
| **对比与选型** | 存在多种技术方案且需要选型时（如数据库、算法、框架） | 只列关键差异，不要写成百科 |
| **破坏性测试** | 代码/配置类知识，且需要验证边界行为时 | 一次只改一个变量，记录结果 |
| **执行意图** | 高频使用或容易忘记使用的场景（如调试技巧、设计模式） | 用 If-Then 格式，具体到代码特征 |
| **费曼解释** | 概念抽象、需要教学或面试时 | 禁止专业术语，用生活类比 |
| **深度源码/原理** | 需要深入理解底层实现时（如 JVM、Linux 内核） | 可补充关键源码片段或底层流程图 |
