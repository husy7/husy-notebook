# 数据生成质量评估笔记（AIME 题目生成）

## 1. 背景
- **AIME**：美国数学邀请赛，答案均为 0~999 的整数，题目涵盖代数、几何、数论、组合、概率等，需要多步推理但无高深理论。
- **参考数据集**：
  - 生成参考：`TianHongZXY/aime-1983-2025`（900+ 道真题，用于随机选取示例）
  - 评估参考：`math-ai/aime25`（AIME 2025 真题，用于对比）

## 2. 评估方法总览
采用三种互补方法：
- **LLM Judge**：自动化多维度绝对评分
- **Win Rate**：成对对比相对质量
- **人工验证**：专家最终把关

## 3. 评估方法一：LLM Judge

### 3.1 设计动机
- 自动化、快速、一致地评估大量生成题目
- 提供多维度评分和详细理由，帮助优化

### 3.2 评分维度（1~5 分）
1. **正确性**：数学逻辑是否正确，答案是否准确
2. **清晰度**：问题表述是否清晰，解答是否易懂
3. **难度匹配**：是否符合 AIME 中等偏难标准
4. **完整性**：解答步骤是否完整，包含必要推理

### 3.3 评估指标
- **平均分**：所有题目四维度得分的平均值
- **及格率**：平均分 ≥ 3.5 的题目比例
- **优秀率**：平均分 ≥ 4.5 的题目比例

### 3.4 实现
- 使用 `LLMJudgeTool`，底层调用 `LLMJudgeEvaluator`
- 评估提示词要求输出 JSON 格式，包含四个维度分数和评语
- 自动生成 Markdown 报告

### 3.5 输出示例
```
平均总分: 4.2/5.0
通过率: 85.0%
优秀率: 40.0%
各维度平均分：正确性 4.3，清晰度 4.1，难度匹配 4.0，完整性 4.4
```

## 4. 评估方法二：Win Rate

### 4.1 设计动机
- 相对评估：衡量生成题目与真题的质量差距
- 更符合人类比较习惯，能发现相对优劣势

### 4.2 评估流程
- 成对对比：随机选取一道生成题目和一道 AIME 2025 真题，交给 LLM 判断哪个更好（A/B/Tie）
- 统计胜率、败率、平局率

### 4.3 评估指标
- **Win Rate**：生成题目获胜的比例，理想值 ≈ 50%
- **Loss Rate**：真题获胜的比例
- **Tie Rate**：平局比例
- 三者之和 = 100%

### 4.4 实现
- 使用 `WinRateTool`，底层调用 `WinRateEvaluator`
- 对比提示词要求输出 `winner`（A/B/Tie）和 `reason`
- 自动生成报告

### 4.5 结果判读
- Win Rate ≈ 50% → 生成质量接近真题
- Win Rate 显著低于 50% → 生成质量较差
- Win Rate 显著高于 50% → 可能超越真题或评估偏差

## 5. 评估方法三：人工验证

### 5.1 设计动机
- 数学题目需严格逻辑验证，自动化评估可能遗漏主观因素（创新性、趣味性）
- 人工专家验证答案准确性、步骤完整性、推理严密性

### 5.2 验证流程
- 阅读题目、答案、解答
- 从 4 个维度评分（正确性、清晰度、难度匹配、完整性）
- 标注状态：
  - ✅ approved（通过）
  - ❌ rejected（拒绝）
  - 🔄 needs_revision（需修改）
- 添加评论（可选）

### 5.3 实现：Gradio 界面
- `HumanVerificationUI` 类，启动 Web 界面
- 显示题目、答案、解答，提供滑块评分和状态选择
- 结果保存为 JSON 文件（`<data_path>_verifications.json`）

### 5.4 使用方法
```bash
python data_generation/human_verification_ui.py data_generation/generated_data/aime_generated_XXXXXX.json
# 浏览器访问 http://127.0.0.1:7860
```

## 6. 完整评估流程整合

使用 `run_complete_evaluation.py` 一键运行：
1. **生成题目**：`AIMEGenerator` 从参考数据中随机选示例，批量生成 AIME 题目（支持延迟、LaTeX 处理）
2. **LLM Judge 评估**：对生成题目进行四维度评分
3. **Win Rate 评估**：与 AIME 2025 真题成对对比
4. **生成综合报告**：汇总所有结果，给出结论和建议

### 运行命令
```bash
python data_generation/run_complete_evaluation.py 30 3.0
# 参数：题目数量、API 延迟（秒）
```

## 7. 综合评估报告内容
- 基本信息（生成时间、题目数量、参考年份）
- 主题分布（代数、几何等占比）
- LLM Judge 结果（平均分、通过率、优秀率、维度评分）
- Win Rate 结果（胜率、败率、平局率）
- 综合结论（是否达到质量标准）
- 改进建议
- 下一步行动（人工验证等）

## 8. 实践建议
- **数据生成**：使用 2-3 秒延迟避免 API 限流；先小批量测试（10 个）再大批量生成；定期检查质量。
- **评估策略**：LLM Judge 做绝对质量评估，Win Rate 做相对对比，人工验证最终把关。
- **质量标准**：
  - LLM Judge 平均分 ≥ 4.0/5.0
  - Win Rate ≥ 45%（接近 50%）
  - 通过率 ≥ 80%
  - 人工验证通过率 ≥ 90%
- **迭代优化**：根据评估结果调整生成提示词，分析低分题目共性，参考高分题目优点。
