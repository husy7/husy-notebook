## 1. 从 LLM 训练到 Agentic RL

### 1.1 核心概念

Agentic RL 将 LLM 作为可学习策略，嵌入智能体的感知-决策-执行循环，通过强化学习优化多步任务表现。与传统基于偏好的强化微调（PBRFT）相比，Agentic RL 处理的是多步序贯决策问题，状态随行动演化，行动空间扩展为文本+工具调用，优化长期累积奖励。

### 1.2 LLM 训练全景

- **预训练**：海量文本自监督学习，学习语言规律和世界知识。
- **后训练**：包括 SFT（监督微调）、奖励建模、强化学习微调（如 PPO、GRPO）。

### 1.3 Agentic RL 六大核心能力

1. **推理**：多步逻辑推导
2. **工具使用**：调用外部工具
3. **记忆**：信息保持与重用
4. **规划**：行动序列规划
5. **自我改进**：反思与纠错
6. **感知**：多模态理解

### 1.4 MDP 对比

| 要素 | PBRFT | Agentic RL |
|------|-------|------------|
| 状态 | 仅初始提示 | 提示 + 历史观察 |
| 行动 | 文本生成 | 文本 + 工具调用 |
| 转移 | 无状态转移 | 环境动态变化 |
| 奖励 | 单步奖励 | 累积折扣奖励 |
| 目标 | 最大化单步期望 | 最大化累积回报 |

## 2. 数据集与奖励函数

### 2.1 GSM8K 数据集

- 小学数学应用题，7473 训练样本，1319 测试样本。
- 需要 2-8 步推理。
- 可转换为 SFT 格式（含完整解答）和 RL 格式（只含最终答案）。

### 2.2 奖励函数设计

| 类型 | 公式 | 特点 |
|------|------|------|
| 准确率 | r=1 如果答案正确，否则 0 | 简单，稀疏 |
| 长度惩罚 | r = accuracy - α·max(0, L-L_target) | 鼓励简洁 |
| 步骤奖励 | r = accuracy + β·steps | 鼓励推理步骤 |

组合奖励可平衡多个目标。

## 3. SFT 训练

### 3.1 为什么需要 SFT

预训练模型不懂任务格式，输出冗长无结构。SFT 教会模型输出格式、推理模式，为强化学习提供合理起点。

### 3.2 LoRA 原理

LoRA 通过低秩分解 ΔW = BA 来近似权重更新，只训练少量参数（A 和 B），大幅降低显存和计算量。

关键超参数：秩 r、缩放因子 α、目标模块。

### 3.3 训练实战

```python

    "action": "train",

    "num_epochs": 3,
    "batch_size": 8,
    "use_lora": True,
    "lora_rank": 16,
    "lora_alpha": 32,
})
```

## 4. GRPO 训练

### 4.1 从 PPO 到 GRPO

GRPO 省去 Value Model，使用组内相对奖励代替优势函数，简化训练流程，提高稳定性。

### 4.2 核心公式

J(θ) = E[ (πθ/πref) · (r - r̄_group) ] - β·D_KL(πθ || πref)

### 4.3 训练流程

1. 对每个问题生成多个答案（num_generations）
2. 计算每个答案的奖励
3. 计算组内平均奖励，得到相对奖励
4. 使用相对奖励更新策略，加入 KL 惩罚
5. 重复

### 4.4 关键参数

- num_generations：每组答案数（典型 4-8）
- kl_coef：KL 惩罚系数（典型 0.05-0.1）
- temperature：生成温度（0.7-1.0）
- learning_rate：通常比 SFT 小（1e-6 ~ 1e-5）

## 5. 模型评估与分析

### 5.1 评估指标

- **准确性**：准确率、Top-K 准确率、数值误差
- **效率**：平均长度、推理步骤数、推理时间
- **质量**：格式正确率、推理连贯性、可解释性

### 5.2 错误分析

常见错误类型：计算错误、推理错误、理解错误、格式错误。通过分析错误分布指导改进方向。

---

## 6. 完整训练流程

端到端流程：数据准备 → SFT 训练 → SFT 评估 → GRPO 训练 → GRPO 评估 → 模型部署。

支持分布式训练（DDP、DeepSpeed ZeRO）和超参数调优（网格搜索、随机搜索、贝叶斯优化）。

## 7. 习题及参考答案

### 7.1 为什么 Agentic RL 的状态包含历史观察，而 PBRFT 的状态只包含初始提示？

**参考答案**：  
Agentic RL 处理多步任务，智能体每一步的行动都依赖于之前的观察和结果（如工具返回、中间推理）。状态必须包含历史才能做出正确决策，这类似于部分可观测马尔可夫决策过程（POMDP）。而 PBRFT 是单轮对话，只需根据初始提示生成一个回答，没有中间交互，状态自然只有初始提示。这种差异使得 Agentic RL 能够建模复杂的依赖关系和长期规划，但训练难度也更大。

### 7.2 将“智能代码调试助手”映射到强化学习框架

**参考答案**：  
- **状态**：当前代码、已发现的 bug 信息、已查阅的文档、测试结果等历史观察。
- **行动**：读取代码、搜索文档、修改代码、运行测试、输出最终修复。
- **奖励**：每一步可给予小奖励（如成功调用工具 +0.1），最终测试通过给予大奖励（+1），修复失败给予 0 或负奖励。
- **状态转移**：执行修改代码后，代码内容改变；运行测试后，测试结果更新。

### 7.3 为什么监督学习难以优化长期目标？设计一个多步推理任务说明

**参考答案**：  
监督学习只提供最终答案的标签，对中间步骤没有直接监督信号。例如数学证明，若模型生成了错误的中间步骤但最终答案碰巧正确，监督学习仍会认为该样本正确，无法纠正中间推理。强化学习则通过最终奖励（证明是否正确）来调整生成策略，即使中间步骤没有标签，也能通过试错学习哪些步骤更可能导向正确结果。

### 7.4 LoRA 的核心思想是什么？为什么能用少量参数实现接近全参数微调的效果？何时选择 LoRA？

**参考答案**：  
LoRA 假设模型微调时的参数变化是低秩的，将 ΔW 分解为两个小矩阵的乘积 BA。由于预训练模型已经学到了丰富的特征，微调往往只需要在低秩子空间内调整即可适应新任务。LoRA 参数量仅为原模型的 r(d+k)/dk，当 r 很小时（如 8），参数量极小（约 0.16%）。适合资源受限、需要快速实验、防止过拟合的场景。当任务与预训练分布差异巨大或需要极致性能时，可考虑全参数微调。

### 7.5 GRPO 相比 PPO 的优势？应用到其他任务需要哪些调整？

**参考答案**：  
GRPO 省去 Value Model，简化训练流程，降低显存；使用组内相对奖励减少方差，提高稳定性。应用到其他任务（如代码生成、对话优化）时，需要设计合适的奖励函数（如代码可运行性、对话相关性）、调整 num_generations 和 temperature 以适应任务特点、可能需要对状态和行动空间进行适配（如代码执行环境）。

### 7.6 设计更精细的奖励函数：部分正确给分、推理过程评分、惩罚冗长

**参考答案**：  
可以组合多个奖励项：  
- 部分正确：计算预测答案与真实答案的数值误差，误差越小奖励越高（如误差 <0.01 得 1，<1 得 0.8，<5 得 0.5，否则 0）。  
- 推理过程评分：检测推理步骤数量、是否有“Step”标记、逻辑是否连贯（可用规则或小型分类器）。  
- 长度惩罚：若答案正确但超过目标长度，按超出比例扣分。  
最终奖励 = 0.6*准确率奖励 + 0.3*推理质量 + 0.1*简洁性奖励。

### 7.7 为三个任务设计奖励函数

**参考答案**：  
- **代码生成助手**：正确性（能否通过测试用例）为主，可读性（代码注释、命名规范）为辅，效率（运行时间）适当加分。  
- **客服对话智能体**：问题解决率（用户问题是否被解决）、用户满意度（基于用户反馈或情感分析）、响应时间（越短越好，但需平衡）。  
- **游戏 AI**：胜率为主，策略多样性（避免单一套路）、对抗鲁棒性（面对不同对手的稳定性）。

### 7.8 什么是奖励黑客？举例并设计防御机制

**参考答案**：  
奖励黑客指智能体通过非预期方式获得高奖励而并未真正完成任务。例如在对话任务中，模型学会输出冗长但无意义的模板来获得长度奖励（如果奖励函数包含长度项）。防御机制：多目标组合奖励，避免单一指标；使用对抗测试验证真实能力；设置奖励上限；定期人工审核；在奖励函数中引入惩罚项（如与参考模型的 KL 散度）防止偏离预期。

### 7.9 GSM8K 数据集特点？如何扩展到更复杂数学问题？

**参考答案**：  
GSM8K 是小学数学应用题，需要 2-8 步算术推理，答案明确。适合训练基础推理和格式遵从。扩展到高等数学或证明，需要构建包含符号推理、定理证明的数据集，可能需要引入形式化验证器（如 Lean、Coq）作为奖励信号，并设计支持长序列和工具调用（如计算机代数系统）的训练框架。

### 7.10 设计泛化能力评估方案

**参考答案**：  
- 使用与训练集分布不同的测试集（如不同题型、不同难度）。  
- 进行对抗测试：设计需要新颖推理模式的问题。  
- 分析模型在训练数据中未出现的数字、实体上的表现。  
- 正则化：权重衰减、dropout、早停；数据增强：改写问题、替换数字。  
- 评估指标：训练集与测试集准确率差距，差距过大说明过拟合。

### 7.11 设计在线学习方案

**参考答案**：  
智能体在实际使用中收集用户反馈（如点赞、点踩、修正），定期用新数据微调模型。技术挑战：数据质量控制（需过滤噪声）、灾难性遗忘（使用经验回放或弹性权重巩固）、安全性（防止恶意反馈毒化模型）。可采用异步更新、小批量在线梯度、结合离线预训练模型等方法。

### 7.12 设计工具学习训练方案

**参考答案**：  
定义工具集（搜索引擎、计算器、代码执行器），行动空间包含工具调用。奖励函数：任务完成给 +1，工具调用成功给 +0.1，无效调用给 -0.1，限制调用次数。使用 GRPO 训练，让模型在环境中尝试不同工具组合，学习何时用哪个工具。

### 7.13 设计分层强化学习方案（高层规划 + 低层工具调用）

**参考答案**：  
高层策略负责将任务分解为子目标序列，低层策略负责执行具体工具调用实现子目标。训练时，先训练低层策略掌握基本工具技能，再训练高层策略进行子目标选择。协调方式：高层给低层提供子目标，低层返回是否完成及结果；奖励在高层分配，低层根据子目标完成情况获得内部奖励。可使用分层强化学习算法（如 H-DQN、Option-Critic）。

### 7.14 设计课程学习方案（从简单任务到复杂任务）

**参考答案**：  
课程顺序：从只需 1-2 步推理、1-2 个工具的任务开始，逐步增加到多步、多工具、依赖关系的任务。评估是否进入下一阶段：在验证集上达到一定成功率（如 80%），且模型对工具的使用正确率高于阈值。课程设计需确保任务难度平滑递增，避免跳变。

## 8. 总结

Agentic RL 是让 LLM 从“对话助手”进化为“自主智能体”的关键技术。通过 SFT 建立基础，GRPO 优化多步决策，结合精心设计的奖励函数，可以训练出具备推理、工具使用、规划等能力的智能体。本章内容从理论到实践，覆盖了完整训练流程，为后续开发更复杂的智能体系统奠定了基础。
