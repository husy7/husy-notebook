# 第十一章 Agentic-RL 学习笔记

## 一、从 LLM 训练到 Agentic RL

### 1.1 核心概念
- **Agentic RL**：将 LLM 视为可学习策略，嵌入智能体的感知-决策-执行循环，通过强化学习优化多步任务表现。
- **与传统监督学习对比**：
  - 监督学习受限于数据质量，缺乏探索，难以优化长期目标。
  - 强化学习通过试错、延迟奖励，能发现更优推理路径，甚至超越人类标注。

### 1.2 LLM 训练全景
- **预训练**：海量文本自监督学习（因果语言建模），学习语言规律和世界知识。
- **后训练**：
  1. **SFT（监督微调）**：学习指令跟随和对话格式。
  2. **奖励建模（RM）**：学习人类偏好，为回答打分。
  3. **强化学习微调（RLHF/RLAIF）**：用 PPO 或类似算法优化策略，最大化奖励同时保持与参考模型接近。

### 1.3 PBRFT vs Agentic RL（MDP 对比）
| 要素 | PBRFT | Agentic RL |
|------|-------|------------|
| 状态 | 仅用户提示（单步） | 包含历史观察和上下文（多步） |
| 行动 | 仅文本生成 | 文本生成 + 工具调用 + 环境操作 |
| 奖励 | 单步质量评分 | 多步累积奖励（可含中间反馈） |
| 目标 | 最大化单步期望奖励 | 最大化累积折扣奖励 |

### 1.4 Agentic RL 的六大核心能力
- **推理**：多步逻辑推导，学习有效推理策略。
- **工具使用**：学会何时、如何调用外部工具。
- **记忆**：管理长期信息，主动记忆与遗忘。
- **规划**：动态制定行动序列，权衡短期与长期收益。
- **自我改进**：从错误中学习，自我反思优化。
- **感知**：理解多模态信息，如视觉推理。

## 二、数据集与奖励函数

### 2.1 GSM8K 数学推理数据集
- **特点**：小学数学应用题，答案明确，需 2~8 步推理，适合自动评估。
- **统计**：训练集 7,473 题，测试集 1,319 题。
- **格式**：
  - **原始**：包含问题、详细解答（含中间计算标记 `<<...>>` 和最终答案 `####`）。
  - **SFT 格式**：`prompt`（对话格式的用户问题）+ `completion`（完整解题步骤）。
  - **RL 格式**：`prompt` + `ground_truth`（仅最终答案，不提供解题过程）。

### 2.2 奖励函数设计
- **准确率奖励**：答案正确 +1，错误 0。
- **长度惩罚**：在正确基础上，对超出目标长度的部分乘以惩罚系数。
- **步骤奖励**：在正确基础上，根据推理步骤数量给予额外奖励（如每步 +0.1）。
- **组合奖励**：平衡正确性、简洁性和可解释性，公式如 `r = r_acc - α·max(0,l-l_target) + β·s`。

### 2.3 自定义数据集与奖励函数
- 使用 `format_math_dataset()` 将包含 `question` 和 `answer` 的原始数据转换为 SFT/RL 格式。
- 自定义奖励函数需遵循签名 `def custom_reward(completions, **kwargs) -> List[float]`，可通过 `register_reward_function` 注册。

## 三、SFT 训练

### 3.1 为什么需要 SFT
- 预训练模型输出自由文本，格式混乱，无法直接用于强化学习。
- SFT 教会模型：输出结构化格式（如 `Step 1: ... Final Answer: ...`）、基础推理模式，为 RL 提供合理起点。

### 3.2 LoRA：参数高效微调
- **原理**：冻结原模型权重，仅训练低秩矩阵 `ΔW = BA`，其中 `B∈R^{d×r}`，`A∈R^{r×k}`，`r << min(d,k)`。
- **优势**：显存占用大幅降低（参数量减少数百倍），训练更快，易于部署，防止过拟合。
- **关键超参数**：秩 `r`（典型值 8~64）、缩放因子 `alpha`（常设为 2r）、目标模块（注意力层等）。

### 3.3 SFT 训练实战
- **基础参数**：
  - `num_epochs`：3（常用）
  - `batch_size`：根据显存调整（4GB→1-2，8GB→4-8）
  - `learning_rate`：5e-5（LoRA 可稍大）
  - `use_lora=True`，`lora_rank=16`，`lora_alpha=32`
- **训练监控**：损失下降、梯度范数合理、学习率按 warmup 变化。

### 3.4 模型评估
- 使用 `evaluate` 操作，计算准确率、平均奖励等。
- 与预训练模型对比，验证 SFT 效果。

## 四、GRPO 训练

### 4.1 从 PPO 到 GRPO
- **PPO 问题**：需训练 Value Model，工程复杂，显存占用高，训练不稳定。
- **GRPO 改进**：
  - 去除 Value Model，使用组内相对奖励代替优势函数。
  - 仅需 Policy Model 和 Reference Model。
  - 添加 KL 散度惩罚，防止策略偏离过大。
- **目标函数**：`J = E[ (πθ/πref) * (r - r̄_group) ] - β·D_KL(πθ||πref)`

### 4.2 GRPO 训练实战
- **关键参数**：
  - `num_generations`：每个问题生成答案数（4~8）
  - `temperature`：0.7~1.0（保持探索）
  - `learning_rate`：1e-5（比 SFT 小）
  - `kl_coef`：0.05~0.1
  - `clip_range`：0.2
- **奖励配置**：可使用 `accuracy`、`length_penalty`、`step` 或组合。

### 4.3 GRPO 训练过程解析
1. **采样**：对每个问题生成多个候选答案。
2. **奖励计算**：根据奖励函数给每个答案打分。
3. **相对奖励**：减去组内平均奖励，减少方差。
4. **策略更新**：最大化相对奖励，同时保持与参考模型的 KL 距离。
- **监控指标**：平均奖励上升、KL 散度保持在 0.01~0.1、准确率提升。
- **常用工具**：Weights & Biases、TensorBoard。

## 五、模型评估与分析

### 5.1 评估指标体系
- **准确性**：准确率、Top-K 准确率、数值误差。
- **效率**：平均长度、推理步骤数、推理时间。
- **质量**：格式正确率、推理连贯性、可解释性。

### 5.2 评估实战
- 使用 `evaluate` 操作，可指定多个指标，对比不同阶段模型（预训练、SFT、GRPO）。

### 5.3 错误分析
- 分类：计算错误、推理错误、理解错误、格式错误。
- 分析不同难度（按推理步骤数）下的表现，定位薄弱环节。

### 5.4 改进方向
- 根据错误类型针对性优化：如计算错误 → 增强数值能力；推理错误 → 改进推理策略。
- 迭代流程：训练 → 评估 → 分析 → 改进 → 重新训练。

## 六、完整训练流程实战

### 6.1 端到端训练流程
1. 数据准备
2. SFT 训练
3. SFT 评估
4. GRPO 训练（从 SFT 模型开始）
5. GRPO 评估
6. 模型部署

### 6.2 超参数调优
- **网格搜索**：遍历参数组合，简单但计算量大。
- **随机搜索**：随机采样，更高效。
- **贝叶斯优化**：使用 Optuna 等库，样本效率高。

### 6.3 分布式训练
- **DDP**：单机多卡，每卡持有完整模型副本。
- **DeepSpeed ZeRO**：分片优化器状态、梯度、参数，支持更大模型。
  - ZeRO-2：优化器状态分片。
  - ZeRO-3：参数也分片，可卸载到 CPU。
- **多节点训练**：配置 `machine_rank` 和主节点 IP，使用 `accelerate launch`。

### 6.4 生产部署
- **模型导出**：合并 LoRA 权重到基础模型。
- **推理优化**：8-bit 量化、`device_map="auto"`。
- **API 服务**：使用 FastAPI 封装推理接口。

## 七、本章小结

- **Agentic RL 本质**：将 LLM 作为策略，在多步决策循环中优化长期回报。
- **核心能力**：推理、工具使用、记忆、规划、自我改进、感知。
- **训练流程**：SFT 奠定格式与基础能力，GRPO 通过试错提升策略。
- **技术栈**：HelloAgents 集成 TRL + Qwen3-0.6B，提供完整工具链。
