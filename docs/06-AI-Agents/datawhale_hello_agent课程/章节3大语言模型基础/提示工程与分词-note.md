# 提示工程与文本分词

> 提示工程决定"怎么问"，决定模型行为；分词决定"装什么进模型"，决定上下文窗口与成本。两者是与 LLM 交互的一体两面。

## 一、提示工程（3.2.1）

### 1.1 采样参数：在 Softmax 之上"改分布"

基础分布（Softmax）：$p_i=\dfrac{e^{z_i}}{\sum_{j=1}^{k}e^{z_j}}$。采样参数本质是重新调整/截断该分布，从而改变下一个 token。

- **Temperature（温度 $T$）**：把 softmax 改为 $p_i^{(T)}=\dfrac{e^{z_i/T}}{\sum_{j=1}^{k}e^{z_j/T}}$。
  - $T$ 变小 → 分布更陡，高概率项被放大 → 保守、重复；
  - $T$ 变大 → 分布更平，低概率项被提升 → 多样、可能不连贯。

| 区间 | 风格 | 适用 |
|------|------|------|
| 0 ~ 0.3 | 精准、确定 | 问答、计算、代码生成、法律/技术文书 |
| 0.3 ~ 0.7 | 平衡、自然 | 客服对话、邮件、文案、简单故事 |
| 0.7 ~ 2 | 创新、发散 | 诗歌、科幻、slogan、灵感启发 |

- **Top-k**：按概率排序取前 $k$ 个做候选集，再归一化 $\hat p_i=\dfrac{p_i}{\sum_{j\in\text{候选集}}p_j}$。$k=1$ 退化为贪心采样。
- **Top-p**：从高到低累加概率，直到 $\sum_{i\in S}p_{(i)}\ge p$，这些 token 组成"核集合"再归一化。相比 Top-k 的固定大小，能动态适应长尾分布，对分布不均匀场景更稳。

**协同优先级**：`温度调整 → Top-k → Top-p`（分层过滤）。通常 Top-k 与 Top-p 二选一即可；同时设置时实际候选集为两者交集。边界：`T=0` 时 Top-k/Top-p 失效（只取最可能 token）；`Top-k=1` 时 T/Top-p 失效（只剩一个 token）。

### 1.2 Zero / One / Few-shot：按示例数量分档

以情感分类为例：

- **Zero-shot（零样本）**：不给示例，直接下指令，靠预训练泛化能力：
  ```
  文本:Datawhale的AI Agent课程非常棒！
  情感:正面
  ```
- **One-shot**：给一个完整示例演示格式，再提新问题。
- **Few-shot**：给多个不同情况的示例，让模型把握任务边界与细节，通常性能更好。

### 1.3 指令调优：从"补全"到"听指令"

早期 GPT-3 是"文本补全"模型，需要 few-shot 教它做什么；**指令调优（Instruction Tuning）**用海量"指令-回答"数据微调，使模型直接听懂自然语言指令——ChatGPT/DeepSeek/Qwen 都是指令调优后的版本。作用是大幅简化交互方式，让直接、清晰的指令成为可能。

### 1.4 基础技巧：人设、示例、输出约束

- **角色扮演**：赋予角色来约束语气、知识范围与风格。
  ```
  你现在是一位资深的Python编程专家。请解释一下Python中的GIL是什么，让初学者也能听懂。
  ```
- **上下文示例（In-context Example）**：用输入输出对"教会"格式，尤其适合复杂格式/结构化输出。
  ```
  从产品评论中提取产品名称和情感，严格按JSON输出。
  评论:这款"星尘"笔记本电脑的屏幕显示效果惊人，但我不太喜欢它的键盘手感。
  输出:{"product_name": "星尘笔记本电脑", "sentiment": "混合"}
  ```
- **输出约束**：明确要求格式（JSON、Markdown 表格等），减少解析负担。

### 1.5 思维链（CoT）：让模型"一步一步想"

对逻辑推理/计算/多步任务，直接要答案易错。CoT 只需在提示中加一句引导语（"请逐步思考" / "Let's think step by step"），让模型显式展开推理步骤：

```
一个篮球队一个赛季80场赢60%，下一赛季打15场赢12场，两赛季总胜率？
请一步一步地思考并解答。
→ 第1赛季赢得 80*60%=48 场；总场 95、总胜 60；总胜率 60/95≈63.16%。
```

显式展示推理过程，既提升正确率，也让回答更可信、易检查纠正。

### 1.6 可复用套路提炼

```
① 定人设：角色扮演锁定风格与边界
② 立规矩：输出格式约束（如 JSON schema、字段）
③ 给样例：1~N 个典型输入输出对（复杂度越高越需要 few-shot）
④ 引思路：难任务加"Do this step by step"
⑤ 调采样：事实任务低温(T→0)，创意任务高温(T→0.7+)
```

## 二、文本分词（3.2.2）

**分词（Tokenization）**：把自然语言文本转成能被模型计算的数字序列；**分词器（Tokenizer）**定义切分规则，最小单元叫**词元（Token）**。

### 2.1 为何需要分词

| 策略 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| 按词（Word-based） | 空格/标点切词 | 直观 | 词表爆炸、**未登录词 OOV**（如 "DatawhaleAgent"）；"look/looks/looking" 语义关联丢失 |
| 按字符（Char-based） | 切成单字符 | 词表小、无 OOV | 单字符多无独立语义，学习拼接开销大 |
| 子词（Subword）✅ | 常见词整词、罕见词拆子词 | 词表可控 + 语义保留 + 能组新词 | 分词不可直接读、需正确实现 merge |

现代 LLM 普遍用**子词分词**：常见词 `agent` 保留整词，罕见词 `Tokenization` 拆成 `Token` + `ization`。

### 2.2 BPE：字节对编码（GPT 系采用）

核心是"贪心合并"三步：

```
① 初始化：词表 = 语料中所有基础字符
② 迭代合并：统计相邻 token 对频率，合并最高频那对并加入词表
③ 重复②直到词表达到预设阈值
```

> 迷你语料 `{"hug":1, "pug":1, "pun":1, "bun":1}`，代码模拟 `num_merges=4` 的实际合并序列：
> `('u','g')→ug` → `('ug','</w>')→ug</w>` → `('u','n')→un` → `('un','</w>')→un</w>`（`</w>` 表示词尾）。

训练结束后，未见词 `bug` 的分词：查 `bug` 不在 → 查 `bu` 不在 → `b`、`ug` 都在 → 切为 `['b','ug']`。实现要点：`get_stats` 统计 pair 频率、`merge_vocab` 用正则做整词替换、循环迭代。

**后续变体**：

- **WordPiece（BERT）**：合并标准非"最高频"，而是"最大化语料语言模型概率"（优先合并最能提升整体通顺度的 pair）。
- **SentencePiece（Llama 系）**：将空格也当普通字符（用 `_` 表示），分词/解码完全可逆，且**语言无关**（不依赖中文无空格分词）。

### 2.3 分词器对开发者的意义（踩坑）

- **上下文窗口按 Token 算**：8K/128K 窗口是 Token 数，不是字符/单词数。**同样一段话，中英文或不同分词器下 Token 数可能相差巨大**——精确管理输入长度是长时记忆智能体的基础。
- **API 成本按 Token 计费**：了解文本如何被切分，是预估/控制成本的关键。
- **模型表现异常常源于分词**：模型可能擅长 `2 + 2`，却在 `2+2`（无空格）上出错——后者可能被视为一个不常见 token；首字母大小写也可能切成完全不同 token 序列，影响理解。

## 三、易错点

> **把 Top-k 和 Top-p 等同**：Top-k 固定取前 k 个，Top-p 按累积概率动态取核集合；长尾/分布极不均匀时 Top-p 适应性更好。

> **重复造温度采样 vs Top-k 的轮子**：温度只改分布陡峭度、不改候选数量；Top-k 只截候选数量；Top-p 只按累积概率截取。

> **忽略协同优先级**：同时设置时是 `温度→Top-k→Top-p` 分层过滤，不是并列；Top-k/Top-p 一般二选一。

> **对指令调优模型仍写 few-shot 补全模板**：现代 Chat 模型可直接下指令，套"补全式"示例反而啰嗦、易引入格式噪声。

> **只看字符数不看 Token 数**：上下文窗口与计费都以 Token 为单位，中英文/复用分词器差异大，预算要按 Token 估。

> **手工构造 BPE 合并时漏了词尾符号**：`</w>`（或 SentencePiece 的 `_`）是分词可逆性的关键，丢弃后无法还原空格边界。

## 四、练习

- Q1：为什么不能只用"字符"或"单词"作为输入单元？  
  A1：按词有词表爆炸 + OOV + 语义关联丢失；按字符无语义、学习低效；子词分词兼得词表可控与语义表达。
- Q2：BPE 解决问题的核心手段？  
  A2：从基础字符出发，贪心迭代合并最高频相邻 token 对，常见词整词、罕见词拆子词，可组未见词。
- Q3：`T=0` 或 `Top-k=1` 会发生什么？  
  A3：都退化为确定性贪心采样（只取最可能 token），其他采样参数失效。
- Q4：CoT 与普通提示的区别？  
  A4：普通提示直接要答案；CoT 引导模型显式展开推理步骤，更难的任务上更准、更可审计。

## 六、对比与选型

| 提示策略 | 何时用 | 成本/Token | 稳定性 |
|----------|--------|-----------|--------|
| Zero-shot | 任务简单、指令清晰 | 低 | 中 |
| One-shot | 需给定输出格式 | 低（1 示例） | 中 |
| Few-shot | 任务边界/细节复杂 | 高（多示例） | 高 |
| CoT | 推理/计算/多步任务 | 高（推理过程更长） | 高（更准） |
| 角色+输出约束 | 风格与结构化输出要求强 | 低-中 | 高 |

**采样选型速查**：要"准"（事实/代码）→ 低温 0~0.3；要"稳"（对话/文案）→ 中温 0.3~0.7；要"活"（创意）→ 高温 0.7~2，必要时配合 Top-p 控长尾。
