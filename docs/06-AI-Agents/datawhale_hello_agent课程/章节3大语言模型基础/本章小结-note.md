# 第三章 大语言模型基础 · 小结

> 一条主线：先弄清 LLM"怎么长出来的"（架构演进 → Transformer/Decoder-Only），再学会"怎么用"（提示/分词/调用/选型），最后认清"能长多大、会犯什么错"（缩放法则与幻觉）——为下一章组装智能体备料。

## 一、全章知识地图

```
第三章 大语言模型基础
│
├─ 3.1 架构（从哪来）
│    N-gram → 词嵌入 → RNN/LSTM → Transformer → Decoder-Only
│    递进解决：稀疏/泛化 → 固定窗口 → 串行+长程遗忘 → 并行+全局注意力 → 生成范式
│
├─ 3.2 交互（怎么用）
│    ├─ 提示工程：采样参数(温度/Top-k/Top-p) + Zero/One/Few-shot + 角色/输出约束 + CoT
│    ├─ 文本分词：子词分词、BPE（WordPiece/SentencePiece）、Token 与成本/窗口
│    ├─ 调用开源模型：transformers 五步链路（加载→模板→编码→生成→解码）
│    └─ 模型选型：八维度 + 闭源/开源概览
│
└─ 3.3 法则与局限（能多大、会错哪）
     ├─ 缩放法则：幂律关系 → Chinchilla(参数×数据配比) → 能力涌现
     └─ 幻觉：类型/成因 → RAG / 多步验证 / 外部工具 缓解
```

**一句话速记**：

```
会算概率 → 会看上下文 → 会预测下一词（架构）
会下指令 → 会管 Token → 会选模型（交互）
越大越强但越大越贵 → 越强越能涌现、也越会一本正经地编（法则与局限）
```

**三个高频坑（速查）**：

- 窗口与计费都按 **Token** 算，不是字符/单词数，中英文差异巨大；
- 采样参数优先级是 **温度 → Top-k → Top-p**，`T=0`/`Top-k=1` 即退化为贪心；
- 幻觉的根治点在于**自回归无事实核查**，需 RAG/工具/多步验证在外围兜底。

## 二、核心术语速查表

| 术语 | 一句话释义 |
|------|-----------|
| 语言模型 | 计算词序列出现概率 $P(S)$ 的模型 |
| 马尔可夫假设 | 当前词只依赖前 $n-1$ 个词（N-gram 的核心近似） |
| 最大似然估计 | 概率用"词对计数 / 单词计数"来近似 |
| 数据稀疏 | 未出现的词序列概率为 0（N-gram 硬伤） |
| 泛化能力 | 模型把已学知识迁移到语义相似新词的能力 |
| 词嵌入 | 把词映射为高维连续向量，语义相近则向量相近 |
| 余弦相似度 | 用向量夹角余弦度量语义关系（`king-man+woman≈queen`） |
| 隐藏状态 | RNN 的"短期记忆"，随时间步向后传递 |
| 长期依赖问题 | RNN 反向传播连乘导致梯度消失/爆炸，难学长距离依赖 |
| 梯度消失 / 爆炸 | 深层反向传播连乘使梯度趋向 0 或极大 |
| 细胞状态 + 门控 | LSTM 的信息通路 + 遗忘/输入/输出三门 |
| 自注意力 | 计算序列任意两词相关度并加权融合的机制 |
| Q/K/V | 查询/键/值：打分（Q·K）、缩放、Softmax、加权求和（×V） |
| 多头注意力 | 把 Q/K/V 切 $h$ 份分别算注意力再拼接整合 |
| Softmax | 把分数转成和为 1 的概率权重 |
| FFN | 逐位置前馈网络，$d_{ff}=4\times d_{model}$ 先扩再缩 |
| 残差连接+LayerNorm | `x+Sublayer(x)` 缓解梯度消失；归一化稳定各层输入分布 |
| 位置编码 | 给词元向量加正弦/余弦位置向量，补"顺序"信息 |
| Encoder-Decoder | 编码器"理解"、解码器"生成"的端到端结构 |
| Decoder-Only | 抛弃编码器只留解码器，自回归"预测下一词"（GPT 系） |
| 自回归 | 把已生成词并入输入，逐词预测下一词 |
| 掩码自注意力 | 因果掩码挡住未来位置，保证只看前文 |
| Token | 分词后的最小单元；上下文窗口与计费均按它计算 |
| OOV | 未登录词：词表外的词，word-based 的致命伤 |
| 词表（Vocabulary） | 分词器能识别的最小单元的集合 |
| BPE | 迭代合并最高频相邻 token 对的子词分词算法 |
| WordPiece／SentencePiece | BERT／Llama 采用的分词变体（后者空格也当字符、语言无关） |
| 温度系数 T | 调分布陡峭度：T 小保守、T 大发散 |
| Top-k | 保留概率前 k 个 token 再归一化采样 |
| Top-p | 累积概率达 p 的最小 token 集（核集合）再采样 |
| 贪心采样 | 每步只取概率最高 token（`T=0` 或 `Top-k=1`） |
| Zero-shot | 不给示例直接下指令 |
| One-shot | 给一个示例演示格式 |
| Few-shot | 给多个示例让模型把握任务边界 |
| 角色扮演 | 赋角色以约束语气、知识范围与风格 |
| 输出约束 | 明确要求格式（JSON 等），减少解析负担 |
| 思维链 CoT | 引导"逐步思考"、显式展开推理的提示技巧 |
| 指令调优 | 用"指令-回答"数据微调，让模型听指令 |
| chat template | 把 roles 消息渲染成模型专属对话格式 |
| 上下文窗口 | 模型一次能处理的 Token 数上限 |
| 微调（Fine-tuning） | 在预训练模型上用领域数据继续训练 |
| RLHF | 人类反馈强化学习，用于对齐意图、从源头减幻觉 |
| MoE | 混合专家架构，只激活任务相关部分提升效率（Llama 4） |
| 部署方式 | API（闭源托管）vs 本地（开源自主可控） |
| 生态与工具链 | LangChain/LlamaIndex/Transformers、社区活跃度 |
| 缩放法则 | Loss 与参数量/数据量/计算量的幂律关系 |
| 幂律关系 | 对数-对数坐标下近线性的尺度规律 |
| Chinchilla 定律 | 给定算力下参数与数据需最优配比（更小模型+更多数据） |
| 能力涌现 | 规模达阈值后突然出现 CoT/指令遵循/多步推理等能力 |
| 幻觉 | 生成与事实/输入/上下文矛盾或编造的内容 |
| 幻觉三类型 | 事实性 / 忠实性 / 内在幻觉 |
| 知识时效性不足 | 模型知识止于训练数据收集时点 |
| 数据偏见 | 训练数据偏见被模型吸收并反映（随机鹦鹉警示） |
| RAG | 生成前检索外部知识注入上下文，缓解幻觉 |

## 三、习题精选（含答案）

- Q1：用迷你语料（`datawhale agent learns` / `datawhale agent works`）计算 Bigram 下 `agent works` 的概率？
  A1：$P(agent)=2/6\approx0.333$，$P(works|agent)=Count(agent\,works)/Count(agent)=1/2=0.5$，连乘 $\approx0.167$。
- Q2：马尔可夫假设含义 + N-gram 根本局限？
  A2：假设当前词只与前 $n-1$ 个词有关，把长历史条件概率近似为短上下文。局限：数据稀疏（未登录序列概率为 0）与泛化差（无法理解 `agent≈robot` 之类语义相似）。
- Q3：RNN/LSTM 与 Transformer 分别如何克服 N-gram 局限，各自优势？
  A3：两者都用词嵌入解决"泛化差"；RNN 以隐藏状态突破"固定窗口"，但串行、有长期依赖问题；LSTM 用门控缓解长程遗忘；Transformer 用全局自注意力+位置编码完全并行，同时解决长程依赖与并行效率。
- Q4：自注意力核心思想 + 为何可并行 + 位置编码作用？
  A4：核心是让每个词"动态兼顾"句中所有词、按 Q·K 相关性分配注意力权重并加权 V。并行：不再有 $t$ 依赖 $t-1$ 的循环，全序列两两关系一次算完。位置编码：给注意力（本身不感知顺序）补上绝对/相对位置信息。
- Q5：为什么不能直接用字符/单词作输入，BPE 解决什么？
  A5：单词→词表爆炸、OOV、语义关联缺失；字符→无独立语义、学习低效。BPE（子词）：常见词整词保留、罕见词拆子词，兼顾词表大小与语义，并能组合未见词。
- Q6：幻觉的成因与一类缓解法的原理/适用场景？
  A6：成因=训练数据含错、自回归只预测下一词无事实核查、复杂推理逻辑出错。以 RAG 为例：生成前检索外部知识注入上下文再作答，适用于知识密集、需要时效与溯源的问答。
- Q7（论文辅助阅读智能体）：选什么基座 + 如何处理超长论文 + 如何保证忠于原文？
  A7：选型看重**大上下文窗口**、强推理/信息抽取、中英能力与低幻觉——如长窗闭源 API 或开源长上下文模型，再权衡成本与隐私。超长论文：即使 128K 窗口也可能不足，宜**分块 + RAG 检索相关段落**（渐进式披露），按需拉取而非全量塞入。忠于原文：用 **RAG 引用原文片段、约束输出"必须标注出处"、多步推理自查/外部验证**，减少编造。
- Q8：从性能/成本/可控性/隐私比较闭源与开源？
  A8：闭源通常性能前沿、按 token 计费、托管部署省事但数据需外发、受服务条款限制；开源可本地部署保隐私、完全可控可微调，但硬件（GPU/内存）与运维成本高、上手门槛高。

## 四、与第四章（经典范式）的衔接

> 本章拆开了 LLM 这个"会预测下一个词的引擎"。第四章的 ReAct、Plan-and-Execute 等经典范式，本质是**在该引擎之上装配控制回路**：用提示词设定角色与规划、把工具/观察写回上下文、按任务与成本选基座、用 RAG 与验证机制对冲幻觉。掌握"引擎的能力与边界"，才知道范式要补什么、怎么调。
