# RAG 检索增强生成系统

> 在生成回答前，先从外部知识库检索相关信息注入上下文，克服 LLM 知识时效性差和专业领域不足的局限。  
> **核心公式**：`检索 → 增强 → 生成`，但2026年的RAG已从“流水线”演变为“智能体系统”。

## 核心原理与流程演进

### RAG 四阶段演进（2020-2026）

| 阶段           | 时期          | 检索方式                      | 生成方式                    | 代表技术                  |
| -------------- | ------------- | ----------------------------- | --------------------------- | ------------------------- |
| 朴素 RAG       | 2020-2021     | TF-IDF/BM25 关键词            | 文档直接拼接                | 早期LangChain             |
| 高级 RAG       | 2022-2023     | 稠密嵌入语义检索              | 查询重写、分块、重排序      | MQE、HyDE                 |
| 模块化 RAG     | 2023-2025     | 混合检索（向量+关键词）、路由 | 思维链、自我反思            | 自适应检索、GraphRAG      |
| **智能体 RAG** | **2025-2026** | **多策略自适应调度**          | **Agent自主规划、工具调用** | **Agentic RAG、自主迭代** |

> 当前主流已进入“模块化+智能体”混合阶段，**自适应检索**是核心调度大脑。

## HelloAgents RAG 架构（五层七步）—— 基础骨架

```
用户层:   RAGTool 统一接口（add_text/add_document/search/ask/stats）
  ↓
应用层:   智能问答 / 搜索 / 知识库管理
  ↓
处理层:   MarkItDown 转换 -> Markdown 智能分块 -> 向量化（+关键词索引）
  ↓
存储层:   Qdrant 向量数据库（命名空间隔离）+ 倒排索引（BM25）
  ↓
基础层:   嵌入模型（DashScope/Local/TFIDF 三级降级）+ 重排序模型（如Cohere）
```

## 核心模块详解（含2026新增）

### 1. 多模态文档载入（MarkItDown）—— 不变

微软开源工具，支持 PDF/Word/Excel/图片/音频 → Markdown。

### 2. 分块策略升级：从“标题结构”到“语义+上下文感知”

| 策略                                           | 适用场景                   | 优点                                   | 缺点         |
| ---------------------------------------------- | -------------------------- | -------------------------------------- | ------------ |
| 固定大小分块                                   | 纯文本/日志                | 简单快速                               | 语义割裂     |
| 标题层次分块（原笔记）                         | 结构化文档（手册、规范）   | 保留结构                               | 无标题时失效 |
| **语义边界分块**（新增）                       | 小说、法律条文、无明确标题 | 按句子/段落完整切分                    | 计算稍重     |
| **上下文检索（Contextual Retrieval）**（新增） | 所有文档                   | 为每个块注入文档级上下文（标题、摘要） | 存储成本略增 |

**推荐组合**：
- 优先使用 **标题层次分块**，并附加文档标题作为块上下文。
- 若无标题，退化为 **语义边界分块**（按句子边界切分，滑动窗口重叠）。
- 索引时，为每个块附加所属文档的 **文档摘要** 和 **章节路径**，避免碎片化。

```python
# 语义边界分块示例（补充原笔记Q1）
def semantic_chunk(text, max_tokens=1000, overlap_sentences=2):
    sentences = split_sentences(text)  # 按。？！切分
    chunks = []
    buffer = []
    for sent in sentences:
        if estimate_tokens(buffer + [sent]) > max_tokens:
            chunks.append(join(buffer))
            # 保留 overlap_sentences 个句子作为重叠
            buffer = buffer[-overlap_sentences:] + [sent]
        else:
            buffer.append(sent)
    if buffer:
        chunks.append(join(buffer))
    return chunks
```

### 3. 嵌入模型与索引（新增混合检索）

- **向量索引**：依然采用嵌入模型（DashScope/Local/TFIDF），用于语义相似度。
- **关键词索引**：同时构建 **BM25** 倒排索引，用于精确匹配（专有名词、缩写）。
- **混合检索**：将向量得分和关键词得分加权合并（如 `0.7*向量 + 0.3*BM25`），显著提升召回率。

> **易错点**：混合检索时，必须归一化两种分数（如 Min-Max 或 Rank 融合），否则量纲不同导致偏置。

### 4. 高级检索策略：MQE + HyDE + 重排序（Reranking）

原笔记已包含 MQE 和 HyDE，现补充 **重排序** 步骤：

- **重排序**：在初步检索（如 top_k=20）后，使用一个轻量级交叉编码器（如 Cohere Rerank、BAAI/bge-reranker）对候选块进行精细打分，筛选出最相关的 top_k（如5个）。这能过滤掉语义相似但实际不相关的噪声，提升最终答案质量。

```python
def search_with_rerank(query, initial_k=20, final_k=5):
    candidates = hybrid_search(query, top_k=initial_k)  # 向量+BM25
    reranked = rerank_model.rerank(query, candidates)   # 交叉编码器打分
    return reranked[:final_k]
```

> **易错点**：重排序模型通常比嵌入模型更慢，只适合对粗召回结果进行精排，不可替代一级检索。

### 5. 自适应检索（Adaptive RAG）—— 2026核心调度策略

**核心思想**：根据问题类型动态选择检索策略，避免“一刀切”。

```python
def adaptive_retrieve(query):
    intent = classify_intent(query)  # 轻量级分类器
    if intent == "simple_fact":
        return direct_search(query, top_k=3)          # 基础向量检索
    elif intent == "ambiguous":
        return mqe_search(query)                      # 多查询扩展
    elif intent == "professional":
        return hyde_search(query)                    # 假设文档检索
    elif intent == "multi_hop":
        return graph_rag_query(query)                # 图检索（见下）
    elif intent == "latest_news":
        return web_search(query)                     # 联网搜索
    else:
        return full_pipeline(query)                  # 组合策略
```

**为什么重要**：
- **降本**：对简单问候直接回答，避免昂贵的LLM调用和检索。
- **提质**：复杂问题启用递归检索或多跳推理，准确率提升30%+。
- **成为2026年RAG系统的事实标准**。

### 6. Graph RAG（图检索增强）—— 应对多跳复杂推理

当问题涉及实体间关系（如“A公司的CEO曾在哪所大学读书？”），向量检索难以关联跨文档片段。GraphRAG构建知识图谱（实体-关系-属性），通过图遍历实现多跳推理。

- **适用场景**：金融分析、医疗诊断、法律案件关联等。
- **实现方式**：可借助微软GraphRAG、LightRAG等成熟库，或自行构建Neo4j + 关系抽取流水线。
- **与向量检索互补**：GraphRAG适合“关系型”查询，向量检索适合“内容型”查询，两者可结合。

> **选型提示**：GraphRAG构建成本较高，只在有明确复杂关系需求时引入，不宜作为默认配置。

### 7. Agentic RAG（代理化RAG）—— 自主智能体驱动

2025年后，RAG不再是静态流水线，而是由LLM Agent自主规划任务。Agent可以：
- 决定使用哪些检索工具（向量库、搜索引擎、图谱、API）。
- 迭代追问、改写查询、反思结果。
- 在多个步骤间协调，甚至调用计算器、代码解释器等。

**典型流程**：
```
用户问题 → Agent分析 → 规划检索步骤 → 执行检索 → 评估答案是否充分 →
  若不充分，调整策略再检索 → 生成最终答案
```

**实现框架**：ReAct、LangGraph、AutoGen 等。可参照 [[ReAct 智能体范式]]。

## 易错点

> **分块过大/过小**：块太大 -> 语义模糊，检索不精确；块太小 -> 上下文断裂。  
> `chunk_size=1000, overlap=200` 是起点，需根据文档类型调整。**语义分块优先于固定大小**。

> **混合检索分数归一化失败**：向量相似度（0~1）和BM25分数（可能>10）直接加权会导致偏置。  
> 采用 **Rank融合** 或 **Min-Max归一化**，或使用 `mmr` 算法。

> **重排序模型与嵌入模型不一致**：重排序需要独立交叉编码器，与向量检索无关。但索引和查询的**嵌入模型必须一致**（原笔记已强调）。

> **自适应路由分类器不准确**：若分类错误，会选错策略。  
> 用强LLM做分类（成本略高但准确），或采用多分类器集成，并设置兜底策略（全管道）。

> **GraphRAG 过度设计**：对简单问题构建图谱，开销巨大。  
> 仅在问题中出现 **多个实体及关系词**（如“哪家公司的收购案影响了其股价？”）时启用。

> **Agentic RAG 的无限循环**：Agent可能迭代过多。  
> 设置最大迭代次数（如3轮），并引入终止条件（如置信度阈值）。

| 方案                      | 核心思想         | 检索质量           | 实现复杂度 | 最佳场景           | 成本等级 |
| ------------------------- | ---------------- | ------------------ | ---------- | ------------------ | -------- |
| 基础向量检索              | 单查询向量相似度 | 中                 | 低         | 简单明确查询       | ★        |
| MQE 增强                  | 多查询扩展+合并  | 高（召回+30-50%）  | 中         | 模糊/多义查询      | ★★       |
| HyDE 增强                 | 假设文档检索     | 高（精度提升）     | 中         | 专业领域查询       | ★★       |
| MQE+HyDE                  | 双策略组合       | 最高               | 高         | 高质量要求         | ★★★      |
| **混合检索（向量+BM25）** | 多路召回融合     | 高（互补）         | 中         | 所有场景（标配）   | ★★       |
| **重排序（Reranking）**   | 精细打分         | 极高               | 中         | 作为后处理（标配） | ★★       |
| **自适应检索**            | 智能路由         | 综合最优           | 高         | 生产系统（核心）   | ★★~★★★   |
| **Graph RAG**             | 知识图谱多跳推理 | 关系型查询极佳     | 极高       | 复杂关系推理       | ★★★★     |

**选型速查**：
1. **最低可用配置**：混合检索（向量+BM25）+ 重排序。
2. **标准生产配置**：在上述基础上增加 **自适应检索** 作为路由器。
3. **高级配置**：若遇到大量关系型问题，集成 **GraphRAG**；若任务需多步骤推理，升级为 **AgenticRAG**。

## 执行意图

- If 用户问题涉及文档/手册中的客观知识，then 用 RAGTool 检索外部知识库，而非依赖 LLM 内置知识。
- If 查询模糊/多义/专业术语差异大，then 启用 MQE 和 HyDE，并配合重排序。
- If 查询涉及多个实体和关系，then 优先使用 GraphRAG 进行图遍历。
- If 任务复杂（如“帮我对比A和B的优缺点，并给出建议”），then 交给 AgenticRAG 自主规划多步检索。
- If 索引和查询嵌入模型不一致 / 切换嵌入方案，then 必须重新索引全部文档，否则向量空间不匹配。

## 费曼解释

> **RAG** 就像开卷考试：LLM是考生，RAG是课本。  
> **混合检索** = 同时用目录（关键词）和内容大意（语义）找信息。  
> **重排序** = 找到20页后，快速浏览标题，选出最关键的5页细读。  
> **自适应检索** = 监考老师先看题，简单题直接口答，难题才让翻书。  
> **GraphRAG** = 画一张人物关系图，遇到“A的老板的朋友是谁”直接看图。  
> **AgenticRAG** = 考生自己决定先翻书、上网查还是画图，还会检查答案对不对。

## 最新趋势小结（2026.08）

- **检索范式**：从“单一向量” → “混合检索+重排序”已成为基线。
- **调度范式**：从“固定流水线” → **自适应路由**，因问施策。
- **复杂推理**：从“多跳检索” → **GraphRAG** 显式建模关系。
- **系统范式**：从“被动工具” → **AgenticRAG**，自主决策与反思。
- **关键能力**：可观测性（追踪检索步骤）和可评估性（RAGAS等评测框架）日益重要。
