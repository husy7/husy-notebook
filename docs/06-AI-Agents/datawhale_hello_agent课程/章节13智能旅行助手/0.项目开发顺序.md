
### 🥇 第一阶段：地基搭建
**核心目标：把“通用语言”和“环境”定死，让项目能跑起来。**

1. **放置数据模型（`backend/app/models/`）**
   - **做什么**：把你手里那份 `数据模型定义.txt` 里的代码，拆分成 `backend/app/models/` 目录下的 Python 文件（比如 `trip.py`, `poi.py`）在本次案例是schemas.py。
   - **为什么最先做**：这是整个项目的“契约”。只有定好了 `TripRequest` 和 `TripPlan`，后端的其他代码才知道怎么传数据，前端才知道要接什么。
2. **配置环境（`backend/app/config.py` + `requirements.txt`）**
   - **做什么**：在 `config.py` 里写好端口号、高德地图 API Key（先写假值占位）。然后运行 `pip install -r requirements.txt` 装好依赖。
3. **前端类型定义（`frontend/src/types/`）**
   - **做什么**：把后端的 Pydantic 模型，翻译成前端的 TypeScript 类型定义（比如 `TripPlan.ts`）。
   - **为什么**：让前端写代码时，编辑器也能有智能提示，跟前端后端一一对应。

---

### 🥈 第二阶段：后端“四肢”开发
**核心目标：写好“工具人”（服务层），确保能查到数据。**

4. **开发服务层（`backend/app/services/`）**
   - **做什么**：写具体的功能函数。比如 `map_service.py`（调用高德地图查坐标/POI）、`weather_service.py`（查天气）。
   - **新手铁律（极其重要）**：**先写“假数据（Mock）”返回，不要急着调真实API！**
     - 比如 `get_attractions(city)` 先不要连高德，直接 `return [{"name": "测试故宫", "location": {...}}]`。
     - **原因**：外部网络可能断、API可能收费。先把内部的“水管”打通，确保你的代码逻辑（Service）没写错，再最后去换成真实接口。

---

### 🥉 第三阶段：后端“大脑”开发
**核心目标：把零件组装成旅行计划（智能体 + 接口）。**

5. **开发智能体（`backend/app/agents/`）**
   - **做什么**：写核心编排逻辑 `trip_planner_agent.py`。它负责把上面的服务（Service）串起来：
     - 调用 Service 查景点 → 塞进 `Attraction` 模型
     - 调用 Service 查酒店 → 塞进 `Hotel` 模型
     - 组合成完整的 `DayPlan` → 最后生成一个 `TripPlan` 对象返回。
6. **开发 API 路由（`backend/app/api/`）**
   - **做什么**：写路由接口 `trip_routes.py`。定义一个 `POST /api/trip/plan`。
   - 在里面接收前端传来的 `TripRequest`，传给 `Agent` 去执行，最后把结果包装成 `TripPlanResponse` 返回给前端。
   - **验证**：这时候你打开 **Postman** 或 **Swagger**（FastAPI自带），手动发个 JSON 请求进去，如果能返回一份完整的假数据计划，说明**后端全部通了！**

---

### 🖥️ 第四阶段：前端“骨架”搭建
**核心目标：让前端页面能跳转，能发请求。**

7. **前端路由配置（`frontend/src/router/`）**
   - **做什么**：设置好首页（输入框）、结果页（展示行程）。
8. **前端 API 服务（`frontend/src/services/`）**
   - **做什么**：写一个 `api.js`，里面封装好 `axios` 请求。定义一个 `planTrip(data)` 函数，专门向后端刚刚写好的 `/api/trip/plan` 接口发请求。

---

### 🎨 第五阶段：前端“装修”与联调
**核心目标：肉眼看到炫酷界面，并把假数据换成真数据。**

9. **开发页面视图（`frontend/src/views/`）**
   - **做什么**：
     - `HomeView.vue`（或 .jsx）：做个漂亮的输入框，绑上 `city`、`date` 等字段，点击按钮时调用刚才的 `api.js`。
     - `ResultView.vue`：把后端返回的 `TripPlan` 数据，用卡片形式展示景点、地图、天气。
   - **首次联调**：让前端请求后端，把后端返回的**假数据**渲染在页面上。如果页面能显示出“第一天：测试故宫”，说明**前后端联调成功**。

---

### 🔌 第六阶段：接入“真电源”
**核心目标：把之前糊弄过去的“假数据”，换成真实的外部API。**

10. **替换真实 API 调用**
    - 回到 `backend/app/services/`，把之前写死的假数据删掉，换成正儿八经的 `requests.get(高德地图API)`。
    - 利用 Pydantic 模型的 `.parse_obj()` 方法，把高德返回的乱码 JSON 转成咱们标准的 `Attraction` 对象。
11. **异常处理与兜底**
    - 如果高德地图今天挂了，你的程序不能崩溃。在 Service 层加 `try...except`，如果查不到真实数据，**自动降级**返回之前准备好的“假数据”（这就是新手进阶为初级工程师的标志）。

---

### 💡 给新手的“十字箴言”（刻在脑门上）

> **“由底向上，先假后真；后端不通，前端不动。”**

- **千万不要做的事**：今天写两行后端 `models`，明天跑去写两行前端 `views` 画按钮，后天又回来调高德 API。**频繁切换上下文是新手效率低下的头号杀手！**
- **严格执行标准**：按照我的顺序，**在完成第 6 步（后端API返回假数据）之前，绝对不动前端的 `views` 页面。** 后端是根，根稳了，树冠（前端）随便长。
