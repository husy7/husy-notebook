# 📘 后端 API 实现笔记（新手开发指南）

> **一句话概括**：API 层是“快递收发室”——负责收件（校验请求）、转发（调用 Agent）、发件（封装响应），所有脏活累活都丢给 Agent 和 Service 去干。

---

## 1. 核心定位：为什么要有 API 层？
- **对内**：把 `Agent`（大脑）和 `Service`（工具箱）封装起来，防止外部直接触达核心逻辑。
- **对外**：把 Python 对象翻译成 JSON，让前端（网页/App）能通过 HTTP 协议调用。

**黄金法则**：API 层**只做 3 件事**——收件、转发、发件。绝对不在 API 层写复杂的业务逻辑（比如“怎么算预算”、“怎么排景点顺序”）。

## 3. 三个关键文件的职责分工

| 文件 | 角色 | 核心任务 |
| :--- | :--- | :--- |
| **`api/main.py`** | 总开关 | 1. 创建 `FastAPI()` 实例 <br> 2. 配置 CORS（放行前端域名） <br> 3. 用 `include_router` 挂载路由 |
| **`routes/trip.py`** | 核心收发室 | 1. 定义 `POST /plan` 接口 <br> 2. 接收 `TripRequest`（自动校验） <br> 3. 调用 `MultiAgentTripPlanner.plan_trip()` <br> 4. 用 `try...except` 兜底异常 <br> 5. 返回 `TripPlanResponse` |
| **`run.py`** | 点火器 | 1. 读取 `settings.host` / `settings.port` <br> 2. 执行 `uvicorn.run()` 启动服务 |

## 4. 数据流动链条（从请求到响应）
这是一条**完整的单向链路**，务必烂熟于心：

> **HTTP 请求 (JSON)**  
> → `main.py`（CORS 放行 + 路由分发）  
> → `trip.py`（接收并校验为 `TripRequest` 对象）  
> → `MultiAgentTripPlanner.plan_trip()`（返回 `TripPlan` 对象）  
> → `trip.py`（封装成 `TripPlanResponse`）  
> → **HTTP 响应 (JSON)**

**关键认知**：只要中间某个环节抛出异常，API 层必须负责“拦截”并转换成统一的错误 JSON 返回，绝不能让 Python 红色的堆栈信息直接暴露给前端。

## 5. 设计思想（新手必看）

### ① 单例模式延续
- `MultiAgentTripPlanner` 初始化很重（加载 MCP 工具、连接外部服务）。
- **做法**：在 `routes/trip.py` 文件加载时（模块级），就调用 `get_trip_planner_agent()` 拿到全局唯一的实例。
- **效果**：整个服务生命周期内只初始化一次，所有请求复用。节省资源，提高响应速度。

### ② 数据闭环（Pydantic 的价值）
- **输入校验**：`TripRequest` 会自动校验。如果前端没传 `city` 或传了 `travel_days=-1`，请求还没进 Agent 就被 FastAPI 拦截并返回 422 错误。
- **输出序列化**：`TripPlanResponse` 会自动把 Python 对象转成 JSON。前端完全不需要关心内部字段名，照着 Swagger 文档取数据就行。
- **精髓**：内部逻辑（Service/Agent）随便怎么重构，只要不改变 `Schemas` 的字段结构，前端代码完全不需要改。

### ③ 异常处理的“体面原则”
- **错误写法**：直接 `return agent.plan_trip(request)`。一旦 Agent 内部报错（比如高德 Key 失效），服务直接崩溃，前端收到 500 错误且无任何有效信息。
- **正确写法**：用 `try...except` 包裹 Agent 调用。
  - 成功：返回 `{"success": True, "data": {...}}`
  - 失败：返回 `{"success": False, "message": "具体原因"}`（状态码可以保持 200，也可以返回 500，但响应体格式必须统一）。
- **精髓**：让前端可以通过读取 `response.success` 来判断成败，而不是靠解析 HTTP 状态码或报错文本。

### ④ CORS（跨域资源共享）
- **为什么需要**：你的前端跑在 `http://localhost:5173`（Vue/React），后端跑在 `http://localhost:8000`。浏览器出于安全考虑，禁止不同端口间的请求。
- **配置位置**：`main.py` 中通过 `CORSMiddleware` 设置 `allow_origins`（允许的域名列表）。
- **要点**：不要图省事写 `["*"]`（允许所有），至少在开发阶段要明确列出前端域名，养成好习惯。

## 6. 测试策略（三步走）

| 阶段 | 操作 | 目标 |
| :--- | :--- | :--- |
| **① 冒烟测试** | 终端 `python run.py`，浏览器打开 `http://127.0.0.1:8000/docs` | 确认 Swagger 界面能正常加载，路由列表可见 |
| **② 契约测试** | 在 Swagger 中点击 `POST /plan`，传入合法 JSON（如北京 3 日游），点击 Execute | 确认返回 200 状态码，`success: True`，且 JSON 结构完整（含 `days`、`budget`） |
| **③ 容错测试** | 故意传入非法数据（如 `travel_days=35` 或删掉 `city` 字段） | 确认返回 `422`（校验失败）或 `success: False`（内部异常），且**没有**红色 Python 堆栈信息 |

**新手注意**：**Swagger（/docs）是你最强大的测试工具**。在 Swagger 上跑不通的接口，前端绝对跑不通。务必先在这里把正向和反向流程全部走通，再考虑联调前端。

## 7. 常见踩坑点（避坑指南）

1. **相对导入报错**：`from ..agents import ...` 在直接运行 `python run.py` 时通常没问题（因为根目录在 `backend/`），但如果移动了文件位置或直接运行 `api/main.py` 会报错。**统一在项目根目录通过 `run.py` 启动即可规避此问题。**
2. **CORS 不生效**：前端报跨域错误时，检查 `settings.get_cors_origins()` 是否包含了前端的实际地址（比如 `http://localhost:5173`）。
3. **Agent 未正确降级**：如果 Agent 初始化失败（比如 LLM Key 为空），`get_trip_planner_agent()` 会直接抛异常，导致整个服务启动不了。**确保你的 `llm_service.py` 中的异常处理和 Mock 降级逻辑已经完善**（参考 `LLM服务模块` 笔记）。
4. **修改代码不生效**：检查 `run.py` 中的 `reload=True` 是否开启，以及终端是否有保存文件的提示。如果还是不生效，按 `Ctrl+C` 停止服务，重新 `python run.py`。
